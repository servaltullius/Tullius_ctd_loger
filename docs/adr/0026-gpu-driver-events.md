# ADR-0026: 프리징 캡처에 그래픽 드라이버 기록 붙이기

## Status
Accepted (2026-11-06)

## Context
- GPU가 오류를 내거나 드라이버가 재시작되면(TDR), 게임의 GPU 대기는 끝나지 않고 다시 기다리기를 반복합니다. 이때 게임은 어떤 게임 로그에도 남기지 않고 굳습니다. 지금까지 리포트는 이런 프리징을 다른 프리징과 가를 수 없었습니다.
- Windows 시스템 로그에는 그래픽 드라이버가 남긴 기록이 있습니다. NVIDIA `nvlddmkm`, AMD `amdkmdag`·`amdwddmg`, Intel `igfx`·`igfxn`, 그리고 Windows 자신의 TDR 기록(`Display` 4101, "디스플레이 드라이버가 응답을 멈추었다가 복구됨")입니다.
- 이 PC에도 `nvlddmkm` 153("Error occurred on GPUID: 100", 오류 수준) 기록이 2026-10-11, 10-17, 11-03에 있습니다. `nvlddmkm`은 메시지 표가 없어 설명은 이벤트 데이터 문자열에만 있습니다.
- 계기: 사용자가 소개한 hang-watch(MIT)의 판독기가 덤프 시각까지의 드라이버 이벤트를 따로 대조합니다. 생각만 가져오고 코드는 새로 씁니다.

## Decision
1. **Helper가 프리징·수동 캡처 때 읽어 덤프에 넣습니다.** 게임 프로세스 시작 시각부터 캡처 시각까지 위 드라이버들의 시스템 로그에서 오류·경고(수준 1~3)만 `EvtQuery`로 읽어(최신부터, 최근 32건, 1만 건까지만 셈, 1.5초 안에서만), 사용자 스트림 `kMinidumpUserStream_GpuDriverEvents`("GD") JSON으로 넣습니다. 각 기록은 드라이버·이벤트 ID·수준·시각·설명입니다. 설명은 드라이버가 메시지 표를 주면 그 문장, 아니면 데이터 문자열(장치 경로 `\Device\...` 제외)입니다.
   - 정보 기록은 읽지 않습니다(2026-11-06 검수). 정보 기록이 최근 32건을 채우면 그 앞의 오류가 밀려나 "오류 없음"으로 보였습니다.
   - 끝까지 읽지 못하면(읽기 실패·시간 초과, 1.5초나 1만 건 한도) JSON의 `complete`가 false이고, 리포트는 "찾은 것 없음(기록을 끝까지 읽지 못함)"처럼 적습니다. 읽다 멈춘 것을 "없음"으로 단정하지 않습니다.
   - 숫자 문자 참조(`&#13;`, `&#x41;`)도 풀고, 제어 문자는 공백으로 바꿉니다.
   - 크래시 덤프에는 넣지 않습니다. 크래시는 게임이 끝나기 전에 써야 하므로 이벤트 로그를 기다리지 않습니다.
   - 로그를 읽지 못하면 스트림이 없고, 읽었는데 기록이 없으면 빈 목록이 들어갑니다. 둘은 다릅니다("기록 없음"은 말할 수 있음).
2. **분석기는 근거로 알리고, 원인으로 단정하지 않습니다.**
   - 근거 항목: 오류·경고(수준 1~3)가 있으면 "게임 중 그래픽 드라이버 오류가 기록됨"(가능성 중간), 없으면 "게임 중 그래픽 드라이버 기록"(낮음)으로 "게임 시작 이후 없음"을 적습니다. 오류·경고만 드라이버와 이벤트 ID로 묶어 최근 것부터 셋, 마지막 오류·경고가 캡처 몇 분 전인지 씁니다(정보 기록의 시각을 쓰지 않음).
   - 리포트 줄 `그래픽 드라이버 기록:`과 요약 JSON `gpu_driver_events`.
   - 프리징이고 오류·경고가 있으면 `[GPU 드라이버]` 권장 줄: 드라이버를 깨끗이 다시 설치하고 GPU 오버클럭·언더볼트를 되돌린 뒤 프리징이 계속되는지 보라고, 같은 게임 중에 났다는 것만으로 원인은 아니라고 적습니다. 빠른 답과 다음 조치는 바꾸지 않습니다.

## Alternatives Considered
- **분석기가 분석할 때 로그를 읽기:** 덤프를 다른 PC에서 열거나 나중에 다시 분석하면 다른 답이 나옵니다. 캡처 때 덤프에 넣어야 덤프와 함께 다닙니다.
- **드라이버 오류가 있으면 빠른 답을 GPU로:** 같은 게임 중의 오류라도 프리징과 무관할 수 있습니다(이 PC의 153 기록은 게임과 상관없는 시각에도 있음). 시각이 겹친다는 것만으로는 원인이 아니라서 근거와 권장 줄로만 둡니다.
- **크래시에도 넣기:** GPU 오류로 장치가 사라져 튕기는 경우도 있지만, 크래시 덤프를 늦출 수 없습니다. 필요하면 크래시 뒤 사후 처리에서 따로 읽는 방법을 나중에 검토합니다.

## Consequences
### Positive
- 로그 없이 굳은 프리징에서 그래픽 드라이버 오류가 함께 있었는지, 없었는지를 리포트가 말합니다.
### Limitations
- 이 버전 전의 덤프와 크래시 덤프에는 없습니다. (크래시는 ADR-0029에서 덤프 옆 파일로 붙입니다.)
- 드라이버가 남기는 기록만 봅니다. 기록 없이 멈춘 GPU는 알 수 없습니다.
- 다른 PC로 옮긴 덤프에도 캡처한 PC의 기록이 들어 있습니다(개인 정보는 드라이버 메시지뿐).

## Verification
- Helper: 이 PC의 실제 `nvlddmkm` 153 XML, 이름 있는·빈 데이터와 이스케이프가 든 `Display` 4101 XML 해석, 쿼리의 드라이버와 시각 범위, JSON 필드, 이 PC의 시스템 로그 읽기와 시간 순서, 범위가 없을 때 읽지 않음(`gpu_driver_events_tests`).
- 분석기: 스트림 읽기(손상·다른 버전 무시), 드라이버·ID별 묶음과 문구, 기록 없음, 근거 항목, 리포트 줄, 요약 JSON, 프리징에만 권장 줄(`quick_answer_tests`), 권장 줄 분류(`recommendation_class_tests`).
- 실제 덤프 작성기로 쓴 수동 캡처에서 스트림이 다시 읽힘(`memory_snapshot_e2e_tests`).
- 게임 안 확인(미확인): 프리징·수동 캡처의 리포트에 `그래픽 드라이버 기록:` 줄이 나오는지.
