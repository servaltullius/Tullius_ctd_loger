# ADR-0020: 예전 분석기가 쓴 요약은 뷰어가 다시 분석

## Status
Accepted

## Context
- 뷰어는 덤프를 고르면 저장된 요약(`*_SkyrimDiagSummary.json`)이 같은 덤프의 것이면 다시 분석하지 않고 그대로 보여 줍니다.
- 새 버전이 요약에 필드를 더하면(v0.2.69의 빠른 답, v0.2.70의 "어떻게 튕겼나"와 크래시 명령어 설명) 예전에 분석해 둔 덤프에서는 그 내용이 보이지 않았습니다. v0.2.69에서 사용자가 실제로 빠른 답 카드가 없다고 알려 왔고(#170은 빠른 답이 없을 때만 다시 분석하도록 고쳤습니다), 릴리즈마다 "분석 버튼을 다시 누르세요"를 노트에 적어야 했습니다.
- 요약에는 스키마 버전(2)만 있고, 어느 분석기 버전이 썼는지는 없었습니다. 스키마 버전은 추가 필드로는 올리지 않습니다.

## Decision
- 분석기는 요약 최상위에 `analyzer_version`(제품 버전, 예: `"0.2.70"`, CMake의 `CMAKE_PROJECT_VERSION`)을 씁니다. 추가 필드라 스키마 v2 독자는 무시합니다.
- 뷰어(`AnalysisSummary.NeedsReanalysisFor`)는 저장된 요약을 다음일 때 쓰지 않고 다시 분석합니다.
  - 빠른 답이 없을 때(#170과 같음)
  - `analyzer_version`이 없거나 읽을 수 없을 때(v0.2.70-rc1 이전에 쓴 요약)
  - `analyzer_version`의 major.minor.patch가 뷰어의 버전(어셈블리 버전 = 제품 버전 + `.0`)보다 낮을 때(숫자로 비교)
- 더 새로운 분석기가 쓴 요약을 예전 뷰어로 열면 그대로 보여 줍니다.

## Consequences
- 새 버전을 설치한 뒤 예전 덤프를 처음 열 때 한 번 다시 분석합니다(보통 1초 안팎). 다시 쓴 요약에는 새 버전이 들어가 다음부터는 바로 열립니다.
- 같은 버전의 RC끼리는 버전 문자열이 같아(`0.2.70`) 다시 분석하지 않습니다. RC 사이에 필드가 늘면 그 RC 노트에 분석 버튼 안내가 여전히 필요합니다.
- 빠른 답이 없는 요약을 다시 분석하던 #170의 규칙은 이 규칙에 포함됩니다.

## Verification
- `skydiag_winui_state_fixture_tests`: 같은 버전·더 새 버전은 그대로, 더 낮은 버전·버전 없음·읽을 수 없는 버전·빠른 답 없음은 다시 분석, `0.2.9` < `0.2.10`(숫자 비교), 뷰어 버전이 없으면 빠른 답만으로 판단
- `skydiag_quick_answer_tests`: 요약 JSON의 `analyzer_version`
- `skydiag_winui_xaml_tests`: 기존 분석 결과를 불러올 때 이 판단을 씀
