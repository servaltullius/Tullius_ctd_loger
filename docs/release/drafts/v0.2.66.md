# v0.2.66 — 크래시 당시 MO2 프로필, SKSE 로그·누락 마스터, Crash Logger 로그·프리징 후보 오진단 수정

v0.2.66-rc1과 rc2를 묶은 정식 릴리즈입니다. v0.2.65 감사에서 미뤄 둔 오진단을 고치고, 외부 리뷰에서 나온 진단 정확도 문제를 코드와 실제 덤프로 확인해 고쳤습니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 한눈에 보기
- **크래시 당시의 MO2 프로필로 판단합니다(F05).** 덤프를 보관했다가 다른 프로필로 바꾼 뒤 분석하면, 지금 프로필의 모드를 그 크래시의 리소스 제공 모드나 충돌로 적었습니다. 이제 Helper가 크래시 순간의 MO2 프로필과 켜진 모드 목록(우선순위 순)을 덤프에 함께 담고, 분석기는 그것을 씁니다. 캡처가 없는 이전 덤프에서는 "분석 시점 기준"이라고 적고, 그 제공 모드를 후보 판단에 쓰지 않습니다(rc1, rc2).
- **이전 실행의 SKSE 로그를 이번 실행으로 읽지 않습니다(F17).** 게임 프로세스가 시작된 뒤에 쓰인 `skse64.log`만 이번 실행의 것으로 봅니다(rc1).
- **실제로 없는 기본·CC 마스터를 누락으로 알립니다(F12).** Helper가 게임이 보는 Data 폴더를 확인할 수 있을 때(MO2 없이 실행, 또는 MO2 가상 파일 시스템 안)만 이름 면제를 풉니다(rc1).
- **다른 크래시의 Crash Logger 로그로 후보를 올리지 않습니다.** 덤프와 Crash Logger 로그는 시각(최대 120초)으로 짝을 짓습니다. 이번 크래시가 로그를 남기지 못하면 직전 크래시의 로그가 붙어 그 모듈이 후보를 바꿀 수 있었습니다. 이제 로그의 예외 위치가 덤프와 다르면 그 로그의 단서를 낮게 평가합니다(rc2).
- **프리징에서 메인 스레드를 막은 플러그인을 후보로 올리고, 쉬고 있던 스레드를 지목하지 않습니다.** 결론 문장만 그 플러그인을 지목하고 행동 우선 후보와 뷰어 후보 카드는 비어 있던 것을 고쳤습니다. 모드 업데이트 뒤 예전 덤프를 다시 분석할 때 Hitch Hunter의 대기 루프를 "막힌 스레드"로 고르던 문제도 고쳤습니다(rc2).
- **장소(셀·월드스페이스)를 정의한 모드를 범인으로 안내하지 않습니다.** 후보에서는 이미 뺐지만 결론 문장·권장 조치·뷰어에는 남아 있었습니다(rc2).
- **1.7.104 알려진 크래시 지점 2곳.** Engine Fixes가 막는 FaceGen·ShadowSceneNode 널 포인터 지점을 1.7.104에서도 알아봅니다(rc1).

## 그 밖에 고친 것
- 알려진 크래시 지점 매칭에 Crash Logger 문맥(C++ 예외, 오브젝트 타입, 상위 모듈)을 넘기는 조건을 예외 위치 비교와 같게 맞췄습니다.
- 예외가 Crash Logger 안에서 났을 때 결론 문장이 "알려진 훅 프레임워크"라고 부르던 것을 "원래 크래시를 기록하다 난 2차 예외"로 설명합니다.
- 뷰어: `[메인 스레드]`·`[Modal 대화상자]`·`[동기화 정지]` 안내를 "지금 바로" 묶음에 넣고, 한국어 문구 두 곳을 고쳤습니다.
- 요약 JSON에 `mo2`(제공 모드 출처와 프로필), `skse_log.time_checked`, `implicit_masters_verified`, `crash_logger.pairing.location_mismatch`를 적습니다.

## 정정
- v0.2.61·v0.2.63 노트는 프리징 때 막힌 게임 스레드의 플러그인을 "후보로 올린다", "후보로 짚는다"고 했습니다. 실제로는 결론 문장, 다음 조치, 스택 후보에만 올랐고 행동 우선 후보 목록과 뷰어 후보 카드에는 빠져 있었습니다(rc2에서 수정).
- 같은 기능의 기록(ADR-0009)은 시험 프리징 3건이 모두 CrashTester.dll을 가리킨다고 했습니다. 이는 캡처 때와 같은 DLL로 분석할 때만 맞았고, 모드를 업데이트한 뒤 다시 분석하면 Hitch Hunter를 가리켰습니다(rc2에서 수정).
- rc1 노트는 분석 시점에 찾은 제공 모드를 "신뢰도를 낮음으로 제한한다"고 했습니다. 근거 항목에서는 그랬지만, 후보 점수와 요약 문구에는 그대로 쓰였습니다(rc2에서 수정).
- rc2 노트는 "분석기만 바뀌었다"고 했지만 뷰어(WinUI)도 바뀌었습니다. Helper와 플러그인 동작이 rc1과 같다는 점은 맞습니다.

## 실게임에서 확인한 것
- 1.6.1170(MO2, SKSE 2.2.6, 켜진 모드 4,362개)에서 rc2로 수동 캡처:
  - Helper 로그 `MO2 capture: captured (enabled mods=4362)`, `SKSE log: matched (…, written after the game started)`
  - 리포트 "providers: 크래시 당시의 MO2 프로필 기준 (프로필 이름)", `time_checked=1`, 요약 JSON `mo2.providers_source=crash_time`
  - `implicit_masters_verified=true`이고 누락 마스터 0개: CC 파일을 MO2 모드로 둔 구성에서도 Helper가 가상 파일 시스템 안에서 그 파일을 봤습니다.
- 보관 덤프 재분석으로만 확인: Crash Logger 위치 비교(실사고 CTD 12건 모두 같은 크래시로 판정, 다른 크래시의 로그를 붙인 재현에서 강등), 프리징 막힌 스레드(시험 프리징 5건), 실제 덤프 34개 전후 비교.
- 실게임 미확인: 새 Helper로 난 실제 CTD, 1.7.104 Engine Fixes 지점, 1.5.97에서의 새 Helper 동작.

## 주의사항
- Helper, 분석기, 뷰어가 바뀌었습니다. 플러그인 코드는 v0.2.65와 같지만 버전 정보가 바뀌므로 ZIP 전체를 교체해 주세요. MO2에서 새 모드로 설치했다면 이전 버전 모드는 꺼 주세요.
- MO2 프로필 캡처와 SKSE 로그 시각 확인은 이 버전으로 새로 찍는 덤프부터 들어갑니다. 이전 덤프는 "분석 시점 기준"으로 표시됩니다.
- 덤프 안의 플러그인 스캔이 켜진 모드 목록만큼 커집니다(켜진 모드 4,362개에서 약 166KB).
- 1.7.104 Engine Fixes는 Nexus에 아직 1.7.99용 베타로 표시돼 있어, 권장 조치는 `EngineFixes.log`의 설치 줄로 수정이 켜졌는지 확인하게 합니다.
- 프리징 버킷 키에 막힌 플러그인이 들어가므로, 예전 프리징 덤프를 다시 분석하면 버킷이 바뀔 수 있습니다.
- 비ASCII 리소스 경로(감사 F16)는 아직 고치지 않았습니다.
