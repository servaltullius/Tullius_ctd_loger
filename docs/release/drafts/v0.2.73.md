# v0.2.73 — 긴 출력 폴더(MO2) 지원, 엇나가던 조언 정리, 분석 견고성

출력 폴더 경로가 길 때(특히 MO2) 분석 결과나 덤프가 만들어지지 않던 문제를 고치고, 분석 결과와 어긋나던 조언을 정리한 릴리즈입니다. 전체 점검(뷰어·분석기·Helper·릴리즈 도구)과 그 검수에서 찾은 문제도 함께 고쳤습니다. SKSE 플러그인, Helper, 분석기, 뷰어가 모두 바뀌었으니 ZIP 전체를 설치해 주세요(SharedLayout protocol은 그대로 v4). MO2에서 새 모드로 설치했다면 이전 버전 모드는 꺼 주세요. 새 설정은 없습니다.

## 한눈에 보기
- **긴 출력 폴더 경로를 지원합니다.** 출력 폴더 경로가 길면 분석 결과를 쓰지 못했고(약 130자부터, MO2에서는 약 140자부터), 더 길면 덤프 저장과 분석기·뷰어 실행까지 실패했습니다(약 190자부터). Steam 기본 설치 경로도 한계에 가까웠습니다. 이제 긴 경로는 Windows의 긴 경로 형식으로 다루고, MO2 가상 파일 시스템이 긴 경로에서 막는 파일 확인은 파일 핸들로 우회합니다. 보통 길이의 경로는 예전과 똑같이 다룹니다.
- **분석 결과와 어긋나던 조언을 정리했습니다.**
  - 다른 크래시의 것일 수 있는 Crash Logger 로그의 오브젝트 참조로 모드를 지목하거나 "꺼 보세요"라고 하지 않습니다.
  - 해제된 코드로 이동한 크래시(게임 종료 중에 자주 나는 형태)에서, 그 코드를 호출한 모드를 원인으로 단정하지 않습니다.
  - 수동 캡처, 프리징, 게임 종료 중 오류에 맞지 않던 안내 문구를 고쳤습니다.
  - 뷰어의 공유 텍스트와 판단이 리포트와 어긋나던 곳을 맞췄습니다.
- **값 하나 때문에 분석이 통째로 실패하지 않습니다.** Helper의 사고 기록, 플러그인 스캔, 크래시 기록 같은 파일에 예상과 다른 값이 하나 있으면 분석 결과가 아예 나오지 않았습니다. 이제 그 값만 기본값으로 두고 나머지로 분석합니다. 읽지 못한 크래시 기록 파일을 새 기록 하나로 덮어써 이전 기록이 사라지던 문제도 고쳤습니다.
- **해제된 후킹 코드가 누구의 것이었는지 기록합니다**(ADR-0024). Helper가 게임 중 30초마다 실행 메모리의 후킹 점프 코드를 기록해 두고, 해제된 코드로 이동한 크래시에서 그 코드가 어느 플러그인의 후킹이었는지 리포트에 적습니다.
- **플러그인 로그도 이전 다섯 세션을 남깁니다**(`SkyrimDiag.previous.log`, `SkyrimDiag.previous.2.log` …). 시험 뒤 바로 게임을 다시 켜면 앞 세션의 로그가 사라지던 문제입니다.
- 뷰어는 v0.2.72가 분석해 둔 덤프를 열 때 한 번 다시 분석합니다.

## 정정
- v0.2.72 노트에서 "다른 크래시의 것일 수 있는 Crash Logger 로그는 이제 원인 후보를 만들지 않습니다"라고 했지만, 그런 로그의 오브젝트 참조는 여전히 빠른 답·요약·권장 조치에서 모드를 중간 신뢰도로 지목했습니다. 이번 릴리즈에서 고쳤습니다.
- README가 Crash Logger를 "현재 v1.24 형식"이라고 했지만 실제 로그는 v1.27입니다. "v1.27 로그까지 확인"으로 고쳤습니다.

## 엔진 변경
**플러그인**
- 이전 다섯 세션의 `SkyrimDiag.log`를 `SkyrimDiag.previous.log`부터 남깁니다. CommonLib의 기본 로그가 우리 로그 설정보다 먼저 `SkyrimDiag.log`를 비우며 열고 있어서, 처음 넣은 보관 코드가 게임 안에서는 동작하지 않았습니다(시험 빌드에서 발견). CommonLib 로그를 끄고 로그는 플러그인이 직접 엽니다.
- 로드 줄에 버전을 남깁니다(`SkyrimDiag: loaded (v0.2.73.0)`).

**Helper**
- 긴 출력 폴더:
  - 긴 경로는 확장 경로 형식(`\\?\`)으로 쓰고, 보통 길이의 경로는 그대로 둡니다.
  - MO2 가상 파일 시스템은 MAX_PATH를 넘는 경로에서 속성 조회·폴더 나열·삭제를 막습니다. 존재·크기·수정 시각 확인, 폴더 나열과 삭제를 파일 핸들로 처리합니다.
  - 덤프 용량 상한(`MaxTotalDumpGB`)이 긴 경로에서 모든 덤프를 0바이트로 세어 아무것도 지우지 않던 문제, 크래시 재신호 표시 파일을 찾지 못해 Helper가 다시 뜰 때마다 같은 멈춘 크래시를 다시 처리하던 문제를 고쳤습니다.
  - 아주 긴 경로에서는 분석기·뷰어의 작업 폴더를 짧은 상위 폴더로 잡아 실행합니다.
- 예상 못 한 예외로 멈추면 원인을 세션 로그에 남기고 종료합니다(플러그인이 새 Helper를 띄움). 지금까지는 로그 한 줄 없이 꺼졌습니다. 캡처 JSON은 잘못된 UTF-8을 치환해 씁니다.
- 크래시 버킷 통계를 200개로 제한하고(가장 오래 갱신되지 않은 것부터, 미래 시각은 시각 없음으로 취급), 손상된 통계·크래시 기록 사본은 가장 최근 것만 하루 동안 남깁니다.
- 후킹 점프 코드 기록(ADR-0024): 30초마다 실행 가능한 개인 메모리(1MB 이하 영역)를 훑어 점프 코드와 그 대상 모듈을 기록하고, 모든 덤프에 사용자 스트림(`HookPages`)으로 담습니다. 기록은 Helper 로그의 `Hook stub record:` 줄에 페이지 수와 스캔 시간으로 남습니다.

**분석기**
- 긴 출력 폴더에 분석 결과와 분석 캐시를 씁니다.
- 짝짓기가 모호한 Crash Logger 로그의 오브젝트 참조는 빠른 답·요약·권장 조치·크래시 기록 투표에 쓰지 않습니다.
- 수동 캡처·스냅샷은 다음 행동이 `[충돌]` 점검으로 가지 않습니다. "fault module 미확정"은 크래시에서만, 이유가 이미 밝혀진 점프 크래시에는 "더 자세히 다시 수집" 안내를 내지 않습니다.
- 해제된 코드로 이동한 크래시: 호출한 모드를 원인 후보로 두지 않고(낮은 신뢰도), 업데이트·비활성화 조언도 내지 않습니다. Helper 기록이 있으면 그 코드가 어느 플러그인의 후킹이었는지 근거·요약·빠른 답에 적습니다(그 주소에서 시작하는 점프 코드가 기록돼 있으면 중간, 같은 페이지의 다른 점프 코드로만 추정하면 낮음). 다만 그 플러그인이 너무 일찍 해제한 것인지 호출한 쪽이 해제된 뒤에도 부른 것인지는 기록만으로 알 수 없어, 어느 쪽 탓인지는 단정하지 않습니다.
- 선택 입력(플러그인 스캔, MO2 상태, Crash Logger 로그, 사고 기록, 크래시 기록)을 읽다 예외가 나면 그 단계만 건너뛰고 진단 줄을 남깁니다. 중간에 실패한 단계의 결과는 남기지 않습니다. 사이드카·크래시 기록·플러그인 스캔·WCT 요약의 값은 타입이 다르면 그 값만 기본값으로 둡니다.
- 크래시 기록 파일을 읽지 못하면: 손상된 파일은 `crash_history.json.corrupt.<시각>`으로 남기고 새로 시작하고, 잠긴 파일이나 모르는 버전의 파일은 건드리지 않습니다. 지금까지는 새 항목 하나로 덮어썼습니다.

**뷰어**
- 공유 텍스트가 요약의 플래그만 보고 프리징·스냅샷을 판단합니다. 이름에 Freeze가 들어간 모드의 크래시를 프리징으로 공유하던 문제입니다.
- "Tullius 콜스택" 표시가 분석기와 같은 기준을 씁니다. 모호한 Crash Logger 짝짓기를 읽어 그 로그로 모드를 지목하지 않습니다.
- CLI 없이 분석할 때(헤드리스 대체 경로) 표시 언어를 따릅니다. 한국어 사용자에게 영어 리포트가 나왔습니다.
- `SkyrimDiagHelper.ini`의 `OutputDir`을 Helper와 같은 규칙으로 읽습니다(작은따옴표, 같은 이름 섹션은 첫 번째만).
- 예상과 다른 타입의 요약 값을 읽다 멈추지 않습니다.

**릴리즈·문서**
- (내부) 릴리즈 게이트가 계약 목록을 읽지 못하거나 빈 목록이면 멈춥니다. zip 목록 검사가 `grep -q` 파이프 때문에 있는 항목을 없다고 보거나 중첩 경로를 놓치던 문제를 고쳤습니다. `--strict` 릴리즈 노트 확인은 제목과 HTML 주석만 있는 노트를 거부합니다. CI의 ctest에 테스트당 시간 제한을 두었습니다.
- (내부) 테스트가 실제로 도는 코드를 확인하도록 고쳤습니다. 쓰지 않던 헤더(`CrashHeuristics.h`)를 지우고, 테스트만 쓰던 함수를 실제 코드가 쓰게 했습니다.
- ADR-0024(해제된 후킹 코드의 주인 기록). README에 해석 안내를 더했습니다.

## 실게임에서 확인한 것
- 1.6.1170(MO2)에서, 출력 폴더 205자 시험 빌드(2026-10-31): 수동 캡처와 F4 프리징 모두 분석 결과(요약·리포트·블랙박스·WCT)와 337자 경로의 분석 캐시가 만들어졌고, 뷰어에서 프리징 결과를 열었습니다.
- 후킹 점프 코드 기록 시험 빌드(2026-10-31, 두 세션): Helper가 30초마다 기록했고 점프 코드가 있는 실행 페이지가 41개에서 71개로 늘었습니다. 한 번 스캔에 140\~280ms가 걸려, 모듈 목록을 Toolhelp 스냅샷 한 번으로 만들도록 고쳤습니다(다른 프로세스에서 잰 모듈 목록 시간 61\~342ms → 3\~8ms). Helper 로그의 이전 세션 보관은 동작했고, 플러그인 로그의 보관이 동작하지 않는 것을 찾아 고쳤습니다.
- 실게임 미확인:
  - 해제된 코드로 이동한 실제 크래시에서 주인 이름이 나오는지. 이 PC에서 10/26\~30에 나던 종료 중 크래시가 10/30 뒤로 나지 않아 확인하지 못했습니다(테스트와 시험 프로세스 안의 스캔으로 확인).
  - 고친 뒤의 플러그인 이전 로그 보관과 스캔 시간.
  - 값 하나가 잘못된 사이드카, 읽지 못하는 크래시 기록, Helper 최상위 예외 처리 경로(테스트로 확인).

## 주의사항
- 이미 분석해 둔 덤프는 뷰어에서 열 때 한 번 다시 분석하므로, 처음 열 때만 조금 오래 걸립니다.
- 게임 종료 중에 난 "해제된 코드로 이동" 크래시는 게임이 이미 닫히는 중에 난 것이라 플레이에는 영향이 없습니다. 리포트도 "따로 할 일 없음"으로 안내합니다.
