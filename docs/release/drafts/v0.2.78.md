# v0.2.78 — qqq·메뉴 종료가 오래 걸려도 프리징이나 CTD로 남기지 않음

v0.2.78-rc1을 정식으로 내는 릴리즈입니다. rc1 이후에는 배포되는 파일의 코드가 바뀌지 않았습니다(문서만, 아래 "rc1 이후 바뀐 것"). v0.2.77에서 올리면 Helper, 분석기, 뷰어가 바뀌고, 플러그인의 동작과 설정은 v0.2.77과 같습니다(SharedLayout protocol v4 그대로, 새 설정 없음). ZIP 전체를 설치해 주세요. MO2에서 새 모드로 설치했다면 이전 버전 모드는 꺼 주세요. v0.2.76에서 바로 올린다면 v0.2.77 노트의 변경도 함께 들어갑니다.

v0.2.77 이전 버전이 분석해 둔 덤프는 뷰어에서 열 때 한 번 다시 분석합니다. rc1로 분석해 둔 덤프는 버전 번호(0.2.78)가 같아서 자동으로 다시 분석하지 않지만, rc1과 분석 결과가 같으므로 다시 분석할 필요는 없습니다.

## 한눈에 보기
- **콘솔 `qqq`나 메뉴의 종료로 끈 게임이 꺼지는 데 오래 걸려도 "프리징"으로 남기지 않습니다.** 툴챈 제보에서 `qqq`로 끌 때마다 "로딩 화면에서 게임이 멈췄습니다(무한 로딩). 의심되는 모드: usvfs_x64.dll — 가능성 중간"이라는 프리징 캡처가 남았습니다. 게임이 꺼지는 데 실제로 2분 넘게 걸린 경우였습니다.
  - Helper가 게임의 종료 플래그(`qqq`, 메뉴의 종료, 강제 종료로 켜지는 `Main::quitGame`) 기록을 보면, 그 뒤의 프리징은 메뉴나 로딩 화면과 상관없이 "느린 종료" 후보로 보류합니다. 게임이 정상 종료(종료 코드 0)로 끝나면 그 덤프를 지우고, 뷰어도 띄우지 않습니다. 덤프를 남기려면 `KeepSlowShutdownHangDumps=1`입니다. 다른 종료 코드(작업 관리자로 끈 경우 등)로 끝나면 지금처럼 덤프를 남기고 분석합니다.
  - 이미 찍힌 그런 덤프를 이 버전으로 다시 분석하면 "느린 종료"로 나옵니다. 빠른 답: "게임 종료(메뉴의 종료나 콘솔 qqq)를 고른 뒤 게임이 꺼지는 데 오래 걸린 것입니다. 플레이 중 멈춘 프리징이 아닙니다." 의심 모드를 짚지 않고, 크래시 이력에도 넣지 않습니다. 블랙박스에 종료 플래그 기록이 남아 있어야 합니다.
- **종료 플래그가 켜진 뒤에 난 크래시는 몇 초가 지났든 "강제 종료 중 오류"입니다.** 지금까지는 종료 요청 뒤 10초 안의 크래시만 강제 종료 중 오류로 봤습니다. 그래서 오래 걸리는 종료 중에 난 크래시는 플레이 중 CTD로 분류되고, 크래시 이력에 남고, 뷰어가 자동으로 열렸습니다.
  - 종료 플래그가 켜지면 게임의 메인 루프가 끝나고 게임은 돌아오지 않으므로, 그 뒤의 크래시는 모두 종료 중에 난 것으로 봅니다.
  - Alt+F4 키 입력, 창의 X 버튼, 다른 프로그램의 닫기 요청은 지금처럼 10초 안의 크래시만 강제 종료로 봅니다. 게임이 그 요청을 무시하고 계속 돌았을 수 있기 때문입니다.

## rc1 이후 바뀐 것
- 배포되는 파일의 코드는 rc1과 같습니다.
- rc1 공개 패키지로 게임에서 확인한 결과를 더했습니다(아래 "실게임에서 확인한 것").

## 수정
**Helper**
- 블랙박스를 이어 읽다가 종료 플래그로 생긴 종료 요청(`game_quit`, `forced_quit`)을 처음 보면 그 세션 동안 기억합니다(`QuitRequestWatcher`). 로그에 `The game was asked to quit (quit from the game's menu); a freeze from here on is its shutdown, and a normal exit after one is a slow shutdown.` 줄을 남깁니다.
- 그 뒤에 확정된 프리징은 메뉴·로딩 플래그와 상관없이 느린 종료 후보입니다. 보류 로그 줄은 `the game was asked to quit before this freeze`라고 이유를 적습니다.
- 크래시가 종료 플래그 뒤면 시간과 상관없이 강제 종료 중 오류로 봅니다: 로그 `crash followed a close request (quit from the game's menu) 130.0 s earlier`, 뷰어를 열지도 종료 뒤로 미루지도 않고, 강제 종료 덤프 보관 수(`MaxForcedCloseCrashDumps`)를 따릅니다.
- 세이브 불러오기 감시와 종료 요청 감시가 같은 방식으로 블랙박스 링을 읽습니다(`BlackboxCursor`).

**분석기**
- 예외가 없는 프리징 덤프의 블랙박스에 종료 플래그 기록이 있으면 "느린 종료"로 분류합니다. 결론 문장 앞머리, 근거 첫 항목, `[느린 종료]` 권장(다음 조치)이 붙고, 프리징 분석과 후보는 그 아래에 그대로 남습니다(종료 중에 무엇이 돌고 있었는지). 해볼 일: "따로 할 일은 없습니다. 끌 때마다 몇 분씩 걸린다면, 게임이 닫히는 동안 무엇이 돌고 있었는지 이 리포트에 나오니 도움을 요청할 때 공유해 주세요."
- 강제 종료 중 오류 판정은 Helper와 같은 규칙을 씁니다: 종료 플래그 종류(`game_quit`, `forced_quit`)는 시간 제한 없이, 나머지는 10초 안. 판정 규칙은 공유 헤더 한 곳(`CloseRequestCoversCrash`)에 있습니다.

**뷰어**
- 느린 종료로 분석된 덤프는 분류 줄 "분류: 느린 종료 (플레이 중 프리징 아님)", 요약 카드 "느린 종료 — 플레이 중 프리징 아님", 공유 텍스트 머리말 "⚪ Skyrim 느린 종료 리포트"와 유형 줄 `SLOW_SHUTDOWN`으로 나옵니다.

**출력 형식**(추가 필드)
- 요약 JSON `analysis.is_slow_shutdown`(항상), `quit_before_freeze.kind`(느린 종료일 때). 리포트 `분류: 느린 종료 (플레이 중 프리징 아님; game_quit)`.
- 요약 JSON `forced_close.seconds_before_crash`는 종료 플래그 종류일 때 10을 넘을 수 있습니다. `forced_close.window_seconds`(10)는 시간 제한이 있는 종류(`alt_f4`, `window_close`, `close_message`)에만 씁니다. `game_quit`, `forced_quit`에는 쓰지 않습니다.

**CI·테스트·개발 도구(내부)**
- 종료 플래그 뒤 로딩 플래그가 켜진 프리징의 보류·삭제·유지, Helper 루프 종단 테스트, 블랙박스 커서 테스트, 느린 종료 빠른 답·요약·리포트·공유 텍스트·뷰어 분류 테스트.
- 종료 플래그 130초 뒤 크래시의 판정(공유 규칙의 정적 확인, 분석기, Helper 스냅샷과 크래시 이벤트 처리 종단 테스트).
- `scripts/compare_analyses.py`가 요약 JSON의 모든 깊이에서 키가 생기거나 사라진 것을 보고합니다. 전에는 최상위 키만 봐서, 중첩 키의 변화가 "같음"으로 나왔습니다.
- 문서: ADR-0035(느린 종료), ADR-0022 Addendum(종료 플래그 뒤 크래시), ADR-0035의 블랙박스 링 크기 정정(500개가 아니라 65536개).

## 실게임에서 확인한 것
같은 MO2 환경(게임 1.6.1170, Crash Logger 켬, Engine Fixes의 빠른 종료 켬)에서 v0.2.78-rc1 공개 패키지로 2026-11-18에 확인했습니다.
- 플러그인 로그에 `loaded (v0.2.78.0)`, 호환성 사전 점검 경고·오류 0건.
- 메뉴의 종료로 끈 두 세션(09:02, 10:01): Helper 로그에 `The game was asked to quit (quit from the game's menu); ...` 줄이 남았고, 프리징 캡처 없이 종료 코드 0으로 끝났습니다. Helper가 게임에서 종료 플래그를 읽는 것이 확인됐습니다.
- Alt+F4로 끈 세션(12:20): 플러그인 로그에 `close request seen: alt_f4`가 남았고, Alt+F4는 종료 플래그를 켜지 않으므로 Helper에는 종료 플래그 줄이 없습니다. 종료 코드 0.
- 그날 실행에서 새 덤프와 Crash Logger 크래시 로그는 없었습니다.
- 실게임 미확인:
  - 느린 종료 자체(종료 뒤 프리징이 보류되고, 정상 종료 뒤 지워지고, 뷰어가 뜨지 않는 것). 이 PC는 Engine Fixes의 빠른 종료라 게임이 1초 안에 꺼져 이 경우가 생기지 않습니다. Helper 루프 종단 테스트로만 확인했습니다.
  - 종료 플래그 뒤 10초가 지나 난 크래시. 종료하는 도중에 크래시가 나야 해서 만들지 못했고, 보관 덤프에도 그런 덤프가 없어 테스트로만 확인했습니다. 10초 안에 난 종료 플래그 강제 종료 덤프 6개는 다시 분석해도 분류가 그대로입니다.
  - SE 1.5.97과 1.7.x 게임.
  - 크래시와 프리징을 잡아 덤프를 쓰는 다른 흐름은 v0.2.77과 같으므로, v0.2.77 노트의 실게임 미확인 목록이 그대로 해당합니다.

## 주의사항
- 종료 플래그가 켜진 뒤 게임이 진짜로 교착돼 작업 관리자로 끈 경우도 분석기는 "느린 종료"라고 합니다. 종료 중의 교착과 느린 종료를 덤프만으로는 가르지 않습니다.
- 정상 종료로 끝난 느린 종료는 무엇이 느렸는지 덤프가 남지 않습니다. 원인을 찾으려면 `KeepSlowShutdownHangDumps=1`로 덤프를 남겨 주세요.
- 종료 플래그 기록이 블랙박스 링(65536개)에서 밀려난 덤프는 예전처럼 프리징이나 CTD로 나옵니다.
- 종료 플래그가 켜진 뒤 게임이 끝나지 않고 계속 도는 경우가 있다면, 그 세션의 이후 크래시가 모두 강제 종료 중 오류로 분류됩니다. 그런 경우는 확인하지 못했습니다.
- Engine Fixes의 빠른 종료(`bSafeExit`)를 쓰면 플러그인이 종료 플래그를 기록하기 전에 게임이 끝나는 경우가 있어, `The game was asked to quit` 줄이 남지 않는 세션도 있습니다. 그런 종료는 빨라서 느린 종료가 되지 않으므로 결과에는 영향이 없습니다.
