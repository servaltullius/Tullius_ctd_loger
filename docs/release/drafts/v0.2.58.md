# v0.2.58 — CTD 증거 유실 차단과 검증 체계 연결

## 핵심 변경
- 덤프 쓰기가 일시적으로 실패해도 사고를 잃지 않도록, 대상 프로세스가 살아 있는 동안 제한된 횟수만큼 그 자리에서 재시도합니다.
- 정상 종료(exit 0)로 분류되는 강한 결함은 빠른 필터와 지연된 프로세스 종료 어느 경로에서도 `SkyrimDiag_CleanExitEvidence_*.json`을 남깁니다. 덤프 identity를 먼저 고정한 뒤 삭제 결과를 확인해 `dump_preserved`와 `delete_failed`를 사실대로 원자 기록하며, JSON 쓰기가 실패하면 덤프를 자동 보존합니다.
- exit 0을 관측한 직후 마지막 crash-event poll은 이미 종료된 프로세스에 덤프 쓰기를 재시도하지 않고 metadata-only로 drain합니다.
- blackbox/resource ring의 각 엔트리를 seqlock으로 다시 검증해 동시 기록 중인 엔트리만 무효화하고 나머지 사고 스냅샷은 보존합니다.
- Helper JSON은 임시 파일 완성 후 교체하며, 손상된 crash-bucket stats JSON은 별도 corrupt 파일로 격리합니다. Adaptive load stats는 원자 저장을 사용합니다.
- ETW 종료는 제한 재시도 후 `wpr -cancel` 결과까지 확인하고, 정리가 확인되지 않으면 manifest에 `cleanup_unconfirmed`를 남깁니다.
- 같은 stem의 다른 덤프는 identity가 붙은 authoritative report/summary 쌍과 triage 저장소로 분리합니다. 기존 이름의 파일은 호환용 최신 별칭으로만 유지합니다.
- CLI와 WinUI의 동시 분석 및 triage 저장은 같은 per-stem 파일 잠금으로 직렬화하고, summary mirror 실패 시 authoritative triage state를 보상 복구합니다.
- 덤프 SHA-256·크기·FILETIME·file ID를 동일한 열린 handle에서 확인해 mmap 이후 경로 교체에도 identity가 섞이지 않습니다.
- 타입이 잘못된 clean-exit sidecar는 optional evidence로 안전하게 무시하며 CLI 밖으로 예외를 전파하지 않습니다.
- background worker가 loader lock 안에서 join되지 않도록 플러그인 모듈 pin과 명시적 shutdown 경계를 추가했습니다.
- CrashLogger가 우리보다 늦게 로드되는 로드오더에서도 중첩 예외 억제가 동작하도록, SKSE `kPostLoad` 시점부터 모듈 범위를 다시 조회하고 write-once 규약으로 공개합니다.
- 싱글 스텝, 스레드 이름 설정, `OutputDebugString` 예외를 강한 결함 분류에서 제외해 unsafe `CrashHookMode=2`에서도 정상 알림이 clean-exit 증거 JSON 대상이 되지 않게 했습니다. 기본 Mode 1의 치명적 예외 선택은 기존과 같습니다.

## 빌드 · 검증 체계
- `CMakeLists.txt`의 버전에서 SKSE metadata, 모든 native PE `VERSIONINFO`, WinUI assembly/file/product version과 application manifest를 생성합니다. 릴리즈 게이트는 ZIP의 실제 PE/SKSE metadata를 읽어 확인합니다.
- native/WinUI/package provenance가 HEAD, dirty 상태, source fingerprint, exact configuration과 모든 artifact hash를 연결합니다. 로컬 dirty 패키지는 진단용으로 허용하지만 공개 릴리즈는 clean provenance를 강제합니다.
- WinUI publish는 매번 새 단일 staging 경로에 출력하고 검증된 그 디렉터리만 `build-winui`로 교체해, 이전 publish 후보가 선택되는 경로를 없앴습니다. MSBuild `Platform=x64`를 명시하고 해당 `bin\x64\Release`·`obj\x64\Release` 트리를 먼저 지워 로컬 셸과 GitHub MSVC 환경이 같은 fresh XAML 경로를 사용합니다.
- Linux의 빠른 clang-tidy 부분 집합에 더해 Windows compile database가 production `.cpp` 전체와 생성된 plugin metadata 소스를 포함하는지 확인하고 모두 `WarningsAsErrors`로 검사합니다.
- 릴리즈 ZIP을 새 임시 폴더에 풀어 최상위 WinUI launcher가 유효 minidump를 실제 분석하고 identity-aware report/summary 쌍을 만드는지 hard gate에서 확인합니다.
- ZIP의 모든 PE를 검사해 x64 호환 native/managed/AnyCPU IL-only/ARM64X hybrid만 허용하고, suffix 태그의 GitHub prerelease 상태를 공개 readback으로 확인합니다.
- 크래시 로그 파서 퍼저를 CI에서 실제로 실행합니다. libFuzzer가 새 입력을 첫 번째 코퍼스 인자에 쓰므로 스크래치 디렉터리를 앞에 두어 검수된 시드가 오염되지 않게 했습니다.
- Windows 전용 런타임 테스트를 CI에서 실행합니다.
- `skydiag_quality_corpus_runner`가 raw signal 픽스처를 production `BuildCandidateConsensus()`로 처리해 임시 Summary를 만들고, `skydiag_quality_corpus_gate_tests`가 그 결과의 후보 순위·상태·신뢰도·점수·기권과 집계값을 검사합니다. 실사고 정확도 측정이 아니라 candidate-consensus 동작 회귀 감지입니다.
- `skydiag_ci_wiring_tests`가 위 검사들이 워크플로에서 사라지면 실패합니다.
- 버전 태그 릴리즈도 unit·ASan+UBSan·clang-tidy·parser fuzz를 직접 실행한 뒤 Windows 패키징으로 넘어갑니다.
- Windows source/XAML guard는 CRLF를 정규화하고 share-text fixture stdout은 UTF-8로 읽어, runner 로캘과 줄바꿈 때문에 테스트가 실패하지 않게 했습니다.

## 주의사항
- SharedLayout protocol v4에서 Plugin은 `kState_Frozen` clear→set CAS로 최초 사고 ownership을 claim하고, Helper만 reject/abandon한 세대를 ACK/reset합니다. Plugin과 Helper를 ZIP 전체로 함께 교체해야 합니다.
- protocol v4 동시성·호환성은 자동 테스트로 검증했지만, 실제 Skyrim 런타임의 연속 first-chance/CTD와 구버전 save·모드 조합은 아직 사람 플레이로 확인하지 않았습니다.
- 정상 종료 증거 격리는 기본적으로 JSON 메타데이터만 남깁니다. `PreserveFilteredCrashDumps=1`이면 덤프도 보존되며 JSON이 그 상태를 명시합니다.
- 검수된 실사고 코퍼스가 여전히 없으므로, 다른 크래시 로거 대비 적중률을 수치로 주장하지 않습니다.
- 플러그인, Helper, 분석기와 WinUI가 함께 바뀌므로 기존 파일 일부만 덮지 말고 zip 전체를 업데이트해 주세요.

- 검수된 실사고 코퍼스와 실제 Skyrim 플레이 런타임: 미검증
