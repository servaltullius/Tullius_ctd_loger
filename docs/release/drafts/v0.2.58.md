# v0.2.58 — CTD 증거 유실 차단과 검증 체계 연결

## 핵심 변경
- 덤프 쓰기가 일시적으로 실패해도 사고를 잃지 않도록, 대상 프로세스가 살아 있는 동안 제한된 횟수만큼 그 자리에서 재시도합니다.
- 정상 종료(exit 0)로 삭제되는 실제 결함에 대해 `SkyrimDiag_CleanExitEvidence_*.json` 메타데이터를 남깁니다. 덤프와 파생 리포트는 그대로 삭제되며 결함 메타데이터만 보존됩니다.
- CrashLogger가 우리보다 늦게 로드되는 로드오더에서도 중첩 예외 억제가 동작하도록, SKSE `kPostLoad` 시점부터 모듈 범위를 다시 조회하고 write-once 규약으로 공개합니다.
- 싱글 스텝, 스레드 이름 설정, `OutputDebugString` 예외를 강한 결함 분류에서 제외해 정상 동작이 CTD로 보고되지 않게 했습니다.

## 빌드 · 검증 체계
- `vcpkg.json`이 `CMakeLists.txt`보다 14개 릴리즈 뒤처져 있었습니다. 두 값을 맞추고, 앞으로 불일치하면 릴리즈가 실패합니다.
- 설정만 있고 실행되지 않던 clang-tidy를 Linux CI에 `WarningsAsErrors`로 연결했습니다. 검사 대상은 컴파일 데이터베이스에서 도출하므로 새 분석기 소스가 자동 포함되고, Windows 전용 소스가 게이트 밖이라는 사실은 CI 로그에 그대로 드러납니다.
- 크래시 로그 파서 퍼저를 CI에서 실제로 실행합니다. libFuzzer가 새 입력을 첫 번째 코퍼스 인자에 쓰므로 스크래치 디렉터리를 앞에 두어 검수된 시드가 오염되지 않게 했습니다.
- Windows 전용 런타임 테스트를 CI에서 실행합니다.
- `skydiag_quality_corpus_gate_tests`가 후보 순위의 조용한 변화를 매 푸시마다 검사합니다. 실사고 정확도 측정이 아니라 동작 회귀 감지입니다.
- `skydiag_ci_wiring_tests`가 위 검사들이 워크플로에서 사라지면 실패합니다.

## 주의사항
- **2차 결함 보존 기능은 이번 릴리즈에서 제외했습니다.** 최초의 강한 결함을 이후 결함으로부터 지키는 기능을 구현했다가 릴리즈 전에 되돌렸습니다. 보존은 설계상 `crash_seq`를 움직이지 않는데 `crash_seq`가 이 프로토콜의 유일한 세대 카운터라, 헬퍼 입장에서 억제 사실이 보이지 않습니다. 버전 없는 별도 상태 플래그를 더해도 두 프로세스가 하나의 사고를 원자적으로 볼 수 없어, 검사를 추가할 때마다 다른 인터리빙이 남았습니다. 안전한 구현에는 `SharedLayout` 버전 상향과 ADR-0004 호환성 검토가 필요하며 다음 릴리즈 과제입니다. v0.2.57 대비 동시성 위험은 추가되지 않았습니다.
- 정상 종료 증거 격리는 JSON 메타데이터만 남깁니다. 덤프가 필요하면 `PreserveFilteredCrashDumps=1`을 별도로 켜야 합니다.
- 검수된 실사고 코퍼스가 여전히 없으므로, 다른 크래시 로거 대비 적중률을 수치로 주장하지 않습니다.
- 플러그인, Helper, 분석기와 WinUI가 함께 바뀌므로 기존 파일 일부만 덮지 말고 zip 전체를 업데이트해 주세요.
