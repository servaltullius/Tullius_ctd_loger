# v0.2.69-rc3 — AI 길찾기 프리징 안내, 오류 창 제목으로 원인 모드 지목, 프리징 덤프의 오브젝트 단서

rc2 이후 원인 모드를 짚지 못하던 경우를 줄인 테스트용 프리릴리즈입니다. Helper와 분석기가 바뀌었습니다.

## 한눈에 보기
- **AI 길찾기 프리징을 알려진 문제로 알려 줍니다.** rc2 실게임 프리징 두 번(엔진 NaN 반복, 1.6.1170의 `SkyrimSE.exe+0xD17465`)은 [AI Pathing Freeze Fix](https://www.nexusmods.com/skyrimspecialedition/mods/190049)(Nexus 190049)를 설치한 뒤 다시 나지 않았습니다. 같은 프리징이면 빠른 답이 "알려진 AI 길찾기 프리징과 일치합니다(가능성 중간)"라고 알리고 그 모드 설치를 안내합니다.
- **오류 창 제목에서 원인 모드를 짚습니다.** 오류 창 때문에 멈췄는데 창을 띄운 플러그인을 스택에서 찾지 못하면, 창 제목(없으면 본문)에 적힌 모드 DLL 이름으로 의심 모드를 알려 줍니다. 2026-10-05 무한 로딩은 이제 "SmoothCam (SmoothCam.dll) — 가능성 높음"으로 나옵니다.
- **프리징 덤프에 멈춘 스레드가 다루던 게임 오브젝트를 담습니다.** 기본 프리징 덤프에는 게임 힙이 없어, 멈춘 계산이 어떤 액터나 오브젝트를 다뤘는지 읽을 수 없었습니다. 이제 관련 스레드가 가리키는 오브젝트 메모리를 조금 담아, 빠른 답에 "멈춘 계산이 다루던 대상: Character "이름" (FormID …, 플러그인)" 같은 단서를 보여 줍니다.

## 수정
**분석기**
- 알려진 해결 방법에 프리징용 조건(게임 버전, 프리징 판정, 루프 위치)을 추가하고 `AI_PATHING_FREEZE_1_6_1170`을 등록했습니다. 1.6.1170에서만 맞추고, 크래시와 프리징 시그니처는 서로 맞추지 않습니다. 이미 `TMS_AIPathingFreezeFix.dll`이 로드돼 있으면 "업데이트를 확인하거나 제작자에게 알리세요"로 안내합니다. 근거가 사용자 확인 한 건이라 가능성은 "중간"으로만 표시합니다.
- 오류 창 원인 모드: 제목을 먼저, 없으면 본문에서 로드된 모드 DLL 이름을 찾습니다(대소문자 무시, 전체 이름 일치, 한국어 조사가 붙어도 인식). 하나만 걸리면 MO2 모드 이름으로 지목하고, 제목이 DLL 이름 그대로이거나 본문에 게임 버전·Address Library 미지원 문구가 있으면 "높음", 아니면 "중간"입니다. 여러 개가 걸리거나 로드되지 않은 이름만 있으면 하나로 정하지 않고 이름만 알려 줍니다. 요약 JSON에 `dialog_named_*` 필드가 추가됐습니다.
- 프리징 오브젝트: 메인 스레드, 메인 스레드가 기다리는 스레드, 실행 중 스레드, 판정이 가리키는 스레드에서 오브젝트를 읽어 요약 JSON `freeze_analysis.thread_objects`·`verdict_thread_object`, 리포트 `thread_objects` 줄, 근거 항목(낮음), 빠른 답의 "확실하지 않은 이유"에 보여 줍니다. 단서일 뿐이라 판정·신뢰도·후보는 바뀌지 않고, 그 플러그인을 원인으로 지목하지 않습니다.

**Helper**
- 프리징·수동 캡처에서 메인 스레드, WCT 대기 사슬(잠금 주인), 실행 중 스레드(게임이 만든 스레드 우선, 최대 16개)의 레지스터와 스택이 가리키는 오브젝트 메모리를 덤프에 추가합니다. 덤프를 쓰려고 스레드를 이미 멈춘 동안 읽어 추가로 멈추는 시간은 없습니다. 커밋되고 읽을 수 있는 페이지만 읽고, guard·접근 불가 페이지는 건드리지 않습니다. 상한은 4MB(스레드당 1MB), 100ms이고, Helper 로그에 `Object memory:` 한 줄이 남습니다.
- 크래시 덤프를 다시 시도할 때(ERROR_PARTIAL_COPY) 추가 메모리 범위가 빠지던 문제를 고쳤습니다.

## 테스트 시 확인할 점
- `Ctrl+Shift+Backspace`로 수동 캡처를 한 번 해 주세요.
  - `SkyrimDiagHelper.log`에 `Object memory: threads=…` 줄이 있고 `(budget reached)`가 없는지
  - 덤프 크기가 이전(약 570~600MB)과 거의 같은지
  - 캡처 뒤에도 게임이 끊김이나 새 크래시 없이 계속 도는지
  - 리포트의 `thread_objects` 줄에 Character, Actor 같은 오브젝트와 플러그인 이름이 나오는지
- 프리징이 나면(일부러 낼 필요는 없습니다) 빠른 답에 멈춘 계산이 다루던 대상이 나오는지 봐 주세요.
