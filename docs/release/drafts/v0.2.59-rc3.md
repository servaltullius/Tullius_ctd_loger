# v0.2.59-rc3 — CrashLogger가 보고 중인 원래 예외 기록

rc2 실게임 테스트에서 나온 CTD로 찾은 문제를 고친 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- 모드의 assert(브레이크포인트)나 처리되지 않은 C++ 예외로 난 크래시를 CrashLogger가 기록하는 동안, CrashLogger 내부에서 난 2차 예외가 크래시로 기록되던 문제를 고쳤습니다. 이제 덤프와 리포트가 `CrashLogger.dll`이 아니라 원래 예외를 기준으로 만들어집니다.
- 콜스택에 코드가 아닌 주소(`.rdata`의 vtable 등)가 프레임으로 섞이지 않습니다.
- 크래시 후 플러그인 스캔이 항상 건너뛰어지던 문제를 고쳤습니다.

## WinUI / 사용성
- 예외 위치가 `CrashLogger.dll`/`CrashLoggerSSE.dll`이면, 일반 훅 프레임워크 안내 대신 "다른 크래시를 기록하다 난 2차 예외일 가능성이 크니 짝지어진 CrashLogger 로그의 원래 예외와 콜스택을 보라"고 안내합니다. 이전 버전으로 캡처한 덤프에도 적용됩니다.
- 예외 코드가 `0x80000003`(브레이크포인트)이면, 모드가 내부 검사(assert/abort)에 실패해 스스로 멈춘 경우가 많다는 설명과 함께 콜스택에서 시스템 DLL이 아닌 첫 모듈을 먼저 확인하라고 안내합니다.

## 엔진 변경
- 플러그인은 기록하지 않은 마지막 브레이크포인트·C++ 예외를 스레드와 함께 보관합니다. 아무것도 기록되지 않은 상태에서 같은 스레드의 CrashLogger 내부 예외가 오면, CrashLogger의 예외 대신 보관한 예외를 크래시로 기록합니다. CrashLogger가 직접 던진 C++ 예외는 보관하지 않습니다.
- stackwalk는 0번이 아닌 프레임 주소가 로컬 이미지의 실행 가능한 섹션 밖이면 그 프레임을 넣지 않고 멈춥니다.
- Helper는 덤프를 쓴 직후, 게임이 살아 있을 때 실행 파일 경로와 모듈 목록을 읽어 두고 그것으로 크래시 후 플러그인 스캔을 합니다.

## 테스트 시 확인할 점
- CTD가 나면 리포트의 `ExceptionCode`와 `Module+Offset`이 같은 시각의 CrashLogger 로그 맨 위 `Unhandled exception` 줄과 같은 예외를 가리키는지 확인해 주세요. `CrashLogger.dll`을 가리키면 덤프와 로그를 함께 보관해 주세요.
- CTD 리포트의 콜스택에 `.rdata` 같은 데이터 주소가 섞이지 않는지 확인해 주세요.
- 크래시 후 `SkyrimDiagHelper.log`에 `PluginScanner skipped` 대신 `Plugin scan sidecar written` 줄이 있고, 덤프 옆에 `*_PluginScan.json`이 생기는지 확인해 주세요.
- rc2에서 확인하던 항목(오류 대화상자 프리징의 `modal_dialog_wait` 분류, 여러 프레임 콜스택, Linux/Proton 텍스트 리포트)도 계속 확인해 주세요.

## 주의사항
- 플러그인(`SkyrimDiag.dll`)이 바뀌었습니다. 공유 메모리 프로토콜(SharedLayout v4)은 그대로지만 ZIP 전체를 교체해 주세요.
- 원래 예외를 되살리는 것은 CrashLogger가 설치되어 있고 같은 스레드에서 보고할 때만 동작합니다. CrashLogger 없이 처리되지 않은 브레이크포인트로 종료되는 경우는 바꾸지 않았습니다.
- 수정 근거는 rc2 실게임 테스트의 실사고 덤프 1건과 그 CrashLogger 로그입니다. 그 덤프는 이미 CrashLogger 내부 예외로 기록되어 있어, 원래 예외 기록은 같은 순서를 재현하는 런타임 테스트로만 확인했습니다.
- 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
