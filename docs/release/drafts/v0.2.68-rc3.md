# v0.2.68-rc3 — 수동 캡처 때 Crash Logger 스레드 덤프로 생기던 덤프 쓰기 제거

rc2 실게임 확인에서 찾은 문제 하나를 고친 테스트용 프리릴리즈입니다. Helper만 바뀌었습니다.

## 한눈에 보기
- **수동 캡처 때 Crash Logger 스레드 덤프 때문에 쓸모없는 크래시 덤프를 쓰지 않습니다(rc1부터 생김).** Crash Logger 1.25도 `Ctrl+Shift+F12`를 스레드 덤프 단축키로 쓰고, 덤프하는 각 스레드에서 탐침 코드를 실행합니다. rc1부터 처리되지 않은 C++ 예외·중단점을 스레드마다 보관하게 되면서, 1분 안에 잡힌 C++ 예외가 있던 스레드가 탐침되면 그 예외가 크래시로 기록됐습니다(rc1 수동 캡처 1번, rc2 2번). 그때마다 600MB 덤프를 썼다가 하트비트 확인 뒤 지웠고, 그동안 게임이 몇 초 멈출 수 있었습니다.

## 수정
- Helper: 수동 캡처를 시작한 뒤 1분 안에 C++ 예외(`0xE06D7363`)나 중단점(`0x80000003`)이 크래시로 기록되면, 덤프를 쓰기 전에 먼저 하트비트로 게임이 계속 도는지 확인합니다. 계속 돌거나 정상 종료하면 덤프를 쓰지 않고 기록을 다시 풉니다. 게임이 멈추거나 비정상 종료하면 지금처럼 덤프를 씁니다. 다른 예외 코드와 수동 캡처와 무관한 크래시는 그대로입니다.

## 테스트 시 확인할 점
- 게임을 1분 넘게 켜 둔 뒤 `Ctrl+Shift+F12`로 수동 캡처를 해 주세요. `SkyrimDiagHelper.log`에 "No dump written: ... thread dump" 줄이 있거나 크래시 이벤트 줄이 아예 없으면 됩니다. "deleting dump" 줄은 더 나오지 않아야 합니다.

## 주의사항
- Helper가 바뀌었습니다. ZIP 전체를 설치하고, MO2에서 새 모드로 설치했다면 rc2 모드는 꺼 주세요.
- 수동 캡처 직후 1분 안에 처리되지 않은 C++ 예외로 진짜 CTD가 나면, 하트비트를 확인하는 몇 초 사이에 프로세스가 끝나 덤프를 쓰지 못할 수 있습니다. 그 경우에도 Crash Logger 로그는 남습니다.
