# v0.2.66-rc1 — 크래시 당시 MO2 프로필, SKSE 로그 시각 확인, 1.7.104 크래시 지점

v0.2.65 감사에서 미뤄 둔 오진단 세 가지를 고치고, 1.7.104용 알려진 크래시 지점 두 곳을 추가한 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- 리소스 제공 모드와 충돌을 크래시 당시의 MO2 프로필 기준으로 적습니다. 덤프를 보관했다가 다른 프로필로 바꾼 뒤 분석해도 지금 프로필의 모드가 붙지 않습니다.
- 같은 부팅의 이전 실행이 남긴 `skse64.log`를 "이번 실행에서 로드하지 못한 DLL"로 보고하지 않습니다.
- 실제로 없는 기본·CC 마스터(예: 1.5.97의 `ccBGSSSE001-Fish.esm`)를 누락 마스터로 알립니다.
- 1.7.104에서도 Engine Fixes가 막는 FaceGen·ShadowSceneNode 널 포인터 지점을 알아봅니다.

## 엔진 변경
- Helper: 플러그인 스캔에 MO2 인스턴스, 모드·프로필·overwrite 폴더(MO2 `[Settings]`, `%BASE_DIR%`), 선택된 프로필, 켜진 모드 목록(우선순위 순)을 담습니다. 전역 인스턴스는 MO2의 `CurrentInstance`로 찾고, `plugins.txt`도 설정된 프로필 폴더에서 읽습니다(감사 F05).
- 분석기: 덤프에 MO2 캡처가 있으면 그것으로 제공 모드를 찾습니다. 없으면 디스크를 읽되 "분석 시점의 MO2 설치에서 찾은 후보"라고 적고 신뢰도를 낮음으로 제한합니다. 요약 JSON에 `mo2.providers_source`를 적습니다.
- Helper: 게임 프로세스 시작 시각보다 먼저 쓰인 `skse64.log`는 쓰지 않고, 시각을 확인했는지(`skse_log.time_checked`)를 남깁니다. 분석기는 확인된 경우에만 "이번 실행에서"라고 씁니다(감사 F17).
- Helper: 기본·CC 마스터를 게임이 보는 Data 폴더에서 확인했는지(`implicit_masters_verified`)를 남깁니다. 분석기는 확인된 스캔에서만 이름 면제를 풉니다(감사 F12).
- 분석기: `FACEGEN_MORPHDATA_NULLPTR_1_7_104`(`0x43756C`), `SHADOWSCENENODE_NULLPTR_1_7_104`(`0x150E416`) 시그니처를 추가했습니다.

## 테스트 시 확인할 점
- MO2로 게임을 켜고 수동 캡처(`Ctrl+Shift+F12`)를 한 번 해 주세요.
  - `SkyrimDiagHelper.log`에 `MO2 capture: captured (enabled mods=N)`와 `SKSE log: matched (…, written after the game started)`가 나오는지 확인해 주세요.
  - 리포트의 "최근 리소스" 아래에 "providers: 크래시 당시의 MO2 프로필 기준 (프로필 이름)"이 나오는지 확인해 주세요.
- 누락 마스터 안내가 새로 생겼다면, 그 마스터 파일이 정말 없는지 확인해 주세요. CC 파일을 MO2 모드로 두는 경우 특히 봐 주세요.
- 아직 실게임에서 확인하지 못한 항목: 위 세 가지 모두(새 Helper로 찍은 덤프 필요), 1.7.104 Engine Fixes 지점(실제 크래시 필요), 1.5.97에서의 새 Helper 동작.

## 주의사항
- Helper와 분석기가 바뀌었습니다. 플러그인 코드는 v0.2.65와 같지만 버전 정보가 바뀌므로 ZIP 전체를 교체해 주세요.
- MO2 프로필 캡처와 SKSE 로그 시각 확인은 이 버전으로 새로 찍는 덤프부터 들어갑니다. 이전 덤프는 "분석 시점 기준"으로 표시됩니다.
- 덤프 안의 플러그인 스캔이 켜진 모드 목록만큼 커집니다(켜진 모드 4,362개에서 약 166KB).
- 1.7.104 Engine Fixes는 Nexus에 아직 1.7.99용 베타로 표시돼 있어, 권장 조치는 `EngineFixes.log`의 설치 줄로 수정이 켜졌는지 확인하게 합니다.
- 비ASCII 리소스 경로(감사 F16)는 아직 고치지 않았습니다.
