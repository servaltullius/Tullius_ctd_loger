# v0.2.69-rc1 — 쉬운 말 빠른 답, 프리징 잠금 주인 추적과 Crash Logger 스레드 덤프 교착 판정

v0.2.68 이후 리포트를 읽기 쉽게 바꾸고 프리징 분석을 보강한 테스트용 프리릴리즈입니다. 분석기와 뷰어가 바뀌었고, 플러그인과 Helper는 v0.2.68과 같습니다.

## 한눈에 보기
- **리포트와 뷰어가 쉬운 말로 된 "빠른 답"으로 시작합니다.** 넥서스 사용자 피드백(리포트가 너무 어렵다, 원인 모드를 바로 알려 달라)을 반영했습니다. 무슨 일이 있었는지, 의심되는 모드(MO2 모드 이름, 없으면 파일 이름)와 그 가능성(높음/중간/낮음), 해볼 일 한 가지, 확실하지 않으면 그 이유를 3~4줄로 보여 주고, 자세한 분석은 그 아래에 그대로 둡니다. 판정·후보·신뢰도는 바뀌지 않았습니다.
- **잠금 때문에 멈춘 프리징에서 잠금을 쥔 스레드를 찾습니다.** 메인 스레드가 다른 스레드가 쥔 크리티컬 섹션이나 뮤텍스를 기다리다 멈추면, Windows 대기 체인(WCT)으로 그 스레드를 찾아 번호, 이름, 맨 위 모듈을 결론에 적습니다. 지금까지는 메인 스레드가 기다리던 위치(예: dxgi.dll)만 보고 "그래픽 드라이버 대기"라고 했고, 메인 스레드 스택의 모드를 후보로 올렸습니다.
- **Crash Logger 스레드 덤프 교착을 알아봅니다.** Crash Logger의 스레드 덤프는 스레드를 하나씩 멈춘 채 분석하는데, 잠금을 쥔 스레드를 멈춘 상태에서 자신도 그 잠금을 기다리면 게임 전체가 멈춥니다(v0.2.68-rc3 실게임에서 관찰). 이런 프리징은 이제 "Crash Logger 스레드 덤프 교착"으로 보고하고, 조치는 스레드 덤프 단축키를 쓰지 않거나 끄는 것 하나만 안내합니다.

## 수정
**빠른 답**
- 리포트 맨 위(제목 바로 아래)에 "빠른 답" 블록, 그 아래 "자세한 분석". Summary JSON에 `quick_answer` 항목 추가(스키마 v2 유지, 예전 리더는 무시).
- 뷰어: 빠른 답 카드를 요약 카드 위에 보여 주고, 요약 복사·공유 텍스트가 빠른 답으로 시작합니다. 빠른 답이 없는 예전 요약은 이전처럼 보입니다.
- 경우별 조치: 외부 프로그램(그 프로그램 업데이트·오버레이 끄기), 해결 방법이 알려진 문제(그 방법), Crash Logger 스레드 덤프 교착(단축키 쓰지 않기), 그래픽 드라이버 쪽 멈춤, 오류 창(창 내용 확인), 로딩 멈춤, 직접 찍은 스냅샷(따로 할 일 없음). Engine Fixes·FSMP처럼 많은 모드가 기대는 모드는 "업데이트, 끄는 것은 시험할 때만"으로 안내합니다. 원인 모드를 특정하지 못하면 그렇다고 적고 리포트 공유를 권합니다.
- README와 넥서스 소개 문구를 맞췄습니다.

**분석기: 프리징**
- 잠금 주인: WCT의 메인 스레드 → 잠금 → 주인 스레드 사슬을 끝 스레드까지 따라갑니다. WCT 두 번 모두 같은 스레드를 가리킬 때만 확인된 주인으로 봅니다. 다른 프로세스의 스레드나 덤프에 없는 스레드는 주인으로 보지 않습니다.
- 덤프의 스레드 이름 정보(ThreadNamesStream)를 읽어 주인 스레드 이름을 표시합니다. 필요한 이름 하나만 읽고, 제어 문자는 바꿔 기록합니다.
- 새 프리징 판정 `lock_owner_wait`(신뢰도 중간): 확인된 잠금 대기는 결론·다음 조치·권고가 주인 스레드부터 안내합니다. 메인 스레드 스택의 모드는 호출 경로로만 다루고 후보로 내세우지 않습니다. 주인이 그래픽 드라이버 안이면 GPU 쪽 점검을 권합니다. 확인되지 않은 주인은 "…쪽일 수 있습니다"로 적고 기존처럼 판정합니다.
- 새 프리징 판정 `crash_logger_thread_dump_deadlock`: 다음이 모두 맞을 때만 판정합니다.
  - Crash Logger 코드 안에 있는 스레드가 있음
  - 잠금 주인이 밖에서 멈춰진 상태로 보임(대기 객체 없이 막혀 있고, 시스템 호출 중이 아님. 시스템 호출 직후면 신뢰도 중간)
  - 함께 찾은 Crash Logger 스레드 덤프 로그가 중간에 끊겼고, 캡처 전에 쓰기가 멈췄음
  - 게임이 스레드 덤프가 시작된 뒤에 멈췄음(이미 멈춘 게임에서 단축키를 누른 경우는 해당하지 않음)
- 이 두 판정은 크래시 이력에서 자기 버킷으로 묶입니다. 교착은 판정 하나로, 잠금 대기는 주인 스레드(맨 위 모듈과 스레드 이름)로 묶어 일반 그래픽 드라이버 대기와 섞이지 않습니다. 이전 이력의 해당 프리징과는 합쳐지지 않습니다(버킷 버전은 그대로 3).
