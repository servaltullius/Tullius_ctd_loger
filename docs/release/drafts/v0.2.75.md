# v0.2.75 — 그래픽 드라이버 기록, AI 패키지와 레벨드 적의 원래 플러그인, 정상 불러온 세이브 안내

크래시와 프리징이 무엇을 다루던 중이었는지 더 알려 주는 릴리즈입니다. 게임 도중 만들어진 AI 패키지와 레벨드 리스트에서 생긴 적은 지금까지 플러그인 없이 나왔는데, 이제 원래 패키지와 원래 NPC를 따라가 어느 플러그인 것인지 보여 줍니다. 프리징 캡처에는 그래픽 드라이버 오류 기록이 붙고, 세이브를 불러오다 튕기면 다른 세이브가 정상적으로 열렸는지도 알려 줍니다. Helper, 분석기, 뷰어가 바뀌었으니 ZIP 전체를 설치해 주세요(플러그인 동작과 SharedLayout protocol v4는 그대로). MO2에서 새 모드로 설치했다면 이전 버전 모드는 꺼 주세요. 새 설정은 없습니다.

## 한눈에 보기
- **게임 도중 만들어진 AI 패키지가 어느 패키지에서 나왔는지 보여 줍니다.** 크래시나 프리징 때 레지스터·스택에 AI 패키지가 있으면, 그 패키지를 만든 원래 패키지(템플릿)와 데이터 항목까지 덤프에 담습니다. 리포트의 오브젝트 줄이 `TESPackage [0xFF0036C8] {type 18, made from [0x00037CC0] Skyrim.esm, data 3: Bool, Location, ?}`처럼 나오고, `?`는 오브젝트가 아닌(어긋난) 데이터 항목입니다.
  - 계기: 11/06 밤에 깨운 에이드리안 아베니치 옆에서 다른 NPC에게 말을 걸다 튕겼습니다. 게임이 처리하던 것은 그녀가 실행 중이던, 게임 도중 만들어진 패키지(`FF0036C8`)였는데, 그런 패키지는 플러그인이 없고 원래 패키지 정보는 덤프에 없어서 어느 모드의 패키지인지 알 수 없었습니다.
- **레벨드 리스트에서 생긴 적의 원래 NPC와 플러그인을 보여 줍니다.** 이런 적은 게임이 만든 임시 NPC(FFxxxxxx)를 베이스로 가져서 지금까지 `base TESNPC [0xFF…]`에서 끝났습니다. 이제 `leveled from TESNPC [0x0001D8F6] Skyrim.esm`처럼 원래 NPC와 그 플러그인이 나옵니다. 직접 배치된 액터는 이미 플러그인이 나오므로 따로 따라가지 않습니다.
- **프리징·수동 캡처에 그래픽 드라이버 오류 기록이 붙습니다**(ADR-0026). GPU가 오류를 내거나 드라이버가 재시작되면(TDR) 게임은 아무 로그 없이 굳을 수 있습니다. 게임 시작부터 캡처까지 Windows 시스템 로그의 그래픽 드라이버 오류·경고(NVIDIA, AMD, Intel, Windows TDR)를 덤프에 넣고, 리포트에 `그래픽 드라이버 기록:` 줄로 보여 줍니다. 없으면 "게임 시작 이후 없음"으로 적어 GPU 쪽을 배제하는 근거가 됩니다. 프리징인데 오류가 있으면 드라이버를 깨끗이 다시 설치하고 GPU 오버클럭·언더볼트를 되돌려 보라는 `[GPU 드라이버]` 줄이 붙습니다. 같은 게임 중에 났다는 것만으로 원인은 아니므로 빠른 답은 바꾸지 않습니다.
- **세이브를 불러오다 튕기면 정상적으로 열린 다른 세이브를 알려 줍니다**(ADR-0025 결정 5). Helper가 세이브 불러오기가 끝날 때마다 출력 폴더의 `loaded_saves.json`에 남기고(최근 64개), 불러오다 난 사고의 `[세이브]` 줄과 빠른 답의 "확실하지 않은 이유"에 "다른 세이브(Save79_…)는 11/06 15:09에 정상적으로 열렸습니다"를 적습니다. 그 파일이 없으면 같은 게임 세션에서 먼저 불러온 세이브를 덤프에서 찾습니다. 세이브 손상 의심의 조건은 그대로입니다.
- **SPID·KID·SkyPatcher·Base Object Swapper·Papyrus Extender를 "여러 모드가 기대는 프레임워크"로 봅니다.** 다른 모드의 INI나 스크립트를 받아 동작해서 여기서 튕겨도 원인은 다른 모드인 경우가 많고, 끄면 기대는 모드들이 함께 망가집니다. 11/01 SPID 크래시의 빠른 답이 "SPID를 끄거나 업데이트"에서 "최신 버전으로 업데이트, 끄는 것은 시험할 때만"으로 바뀝니다.
- **원격 플레이·스트리밍 앱의 가상 디스플레이가 켜져 있어도 GPU 이름이 나옵니다.** 화면 출력만 하는 어댑터가 GPU와 같은 수치를 이름 없이 보고해 `GPU: GPU`로 나오던 문제입니다. v0.2.74가 찍은 덤프도 다시 분석하면 실제 GPU 이름이 나옵니다.
- 뷰어는 v0.2.74가 분석해 둔 덤프를 열 때 한 번 다시 분석합니다.

## 엔진 변경
**Helper**
- 블랙박스에서 세이브 불러오기의 끝(`SaveLoadEnd` 성공)을 250ms마다 읽어 `loaded_saves.json`에 세이브 키·이름·시각을 남기고, Helper 로그에 `Save load finished: <이름>`을 씁니다. 다시 시작한 Helper가 같은 불러오기를 두 번 남기지 않습니다.
- 프리징·수동 캡처: 시스템 로그의 그래픽 드라이버 오류·경고(`nvlddmkm`, `amdkmdag`·`amdwddmg`, `igfx`·`igfxn`, `Display` 4101)를 최근 32건까지 새 덤프 스트림에 넣습니다. 읽기 한도는 1.5초이고(이 PC에서는 0.1초 안쪽), 끝까지 읽지 못하면 그렇다고 표시합니다. 크래시 덤프는 늦출 수 없어 넣지 않습니다.
- 크래시·프리징의 오브젝트 메모리가 AI 패키지의 원래 패키지와 데이터 항목(최대 32개), 레벨드 액터의 원래 NPC까지 따라갑니다.
- GPU 메모리 기록에서 화면 출력만 하는 어댑터를 뺍니다.

**분석기**
- 덤프 오브젝트: 요약 JSON `dump_objects[].package`(`type`, `template`, `data_count`, `data_types`)와 `base_object.leveled_from`, 리포트·근거의 오브젝트 줄과 프리징 단서 문구에 같은 내용을 넣습니다. 단서일 뿐이라 후보와 판정은 바꾸지 않습니다.
- 그래픽 드라이버 기록: 근거 항목, 리포트 줄, 요약 JSON `gpu_driver_events`, 프리징의 `[GPU 드라이버]` 권장 줄. 오류·경고만 세고 드라이버와 이벤트 ID로 묶어, 마지막 기록이 캡처 몇 분 전인지 적습니다.
- 다른 세이브 정상 불러오기: 근거 항목, `[세이브]` 줄, 빠른 답의 "확실하지 않은 이유", 리포트의 세이브 줄, 요약 JSON `save_load.other_save_loaded`. 캡처 뒤의 기록은 세지 않아 처음 분석한 결과가 나중에 바뀌지 않습니다.
- 예전 덤프에서 이름 없는 어댑터가 GPU와 같은 예산·사용량(2% 이내)이면 같은 어댑터로 보고 이름 있는 쪽을 씁니다.
- `hook_frameworks.json`에 위 다섯 프레임워크를 더했습니다.

**뷰어**
- `[GPU 드라이버]` 줄을 즉시 조치로 분류합니다.

**릴리즈·테스트(내부)**
- .NET 테스트 하니스를 한 번만 빌드하고 빌드 임시 파일을 남기지 않습니다(한 번 돌릴 때마다 TEMP에 수십 개씩 쌓이던 문제). WSL에서도 마찬가지입니다.
- WSL 병렬 테스트에서 패키징 테스트가 가끔 실패하던 원인(작업 중인 저장소의 출처 해시가 그 사이 바뀜)을 고쳐, 임시 저장소 사본에서 패키징합니다. 이 테스트가 70\~130초에서 0.5초로 줄었습니다.
- 실패한 런타임 테스트가 자기 폴더를 남기고 그 경로를 출력합니다.
- ADR-0026(그래픽 드라이버 기록), ADR-0025 결정 5(정상 불러온 세이브), ADR-0010 부록 둘(AI 패키지, 레벨드 액터).

## 주의사항
- 패키지의 원래 패키지, 레벨드 적의 원래 NPC, 그래픽 드라이버 기록은 v0.2.75 Helper가 찍은 덤프부터 나옵니다. 이전 덤프에는 그 메모리와 기록이 없어 패키지는 종류만 나옵니다.
- 모두 단서입니다. 원래 패키지나 NPC를 정의한 플러그인, 같은 게임 중의 드라이버 오류를 원인으로 단정하지 마세요.
- `loaded_saves.json`은 출력 폴더에 새로 생기는 파일이고 세이브 이름이 들어 있습니다. 덤프 폴더를 통째로 공유할 때 참고해 주세요.
- 드라이버 메시지는 Windows 표시 언어로 나옵니다.
