# v0.2.56 — CTD 근거 신뢰도 및 배포 검증 강화

## 핵심 변경
- 정상 종료가 확정된 뒤 headless 분석기가 summary를 다시 만드는 경합을 차단했습니다.
- 크래시 버킷을 심볼 문자열 대신 모듈명과 RVA 기반의 `CTD2` 형식으로 전환했습니다.
- Crash Logger 로그 페어링이 모호하면 해당 로그를 확정 근거처럼 사용하지 않고 신뢰도와 후보 가중치를 낮춥니다.

## CTD 판정 및 기록
- 동일 dump 파일을 다시 분석하면 crash history에 새 사고로 추가하지 않고 기존 항목을 갱신합니다.
- 현재 분석 중인 dump는 history 반복 근거에서 제외하므로 자기 자신이 반복 신호를 만들지 않습니다.
- `crash_bucket_version=2`와 Crash Logger 페어링 시간차·후보 수·모호성·신뢰도를 JSON summary와 텍스트 report에 기록합니다.
- 2초 이내에 유효한 경쟁 Crash Logger 로그가 있으면 CrashLogger 단서가 독립 stack suspect를 재정렬하거나 High confidence로 올리지 못합니다.

## 정상 종료 및 런타임 비용
- Helper가 기본 headless 분석 프로세스의 수명을 추적합니다. 게임이 `exit_code=0`으로 끝나면 분석기를 먼저 종료하고 dump의 파생 CTD 산출물을 정리합니다.
- first-chance 예외 rate limit을 모듈 경로 확인보다 먼저 적용하고 고정 버퍼를 사용해 VEH 경로의 동적 할당을 줄였습니다.
- heartbeat는 기존 주기를 유지하면서 비용이 큰 모듈/스레드 lifecycle 열거만 1초 주기로 분리했습니다.

## WinUI 및 배포
- v0.2.52+ 릴리즈는 .NET 8과 Windows App SDK를 포함하는 self-contained 배포이며 별도 Windows App Runtime 1.8 설치가 필요하지 않습니다.
- release gate가 Windows App Runtime bootstrap/runtime, WinUI XAML과 PRI 파일을 실제 ZIP과 현재 WinUI 빌드에서 모두 확인합니다.
- release gate가 핵심 PE의 x64 아키텍처, PDB 부재, 버전명과 현재 빌드 대비 SHA-256 일치를 검사합니다.
- CI와 태그 릴리스 모두 새로 만든 정확한 ZIP 경로로 hard gate를 실행한 뒤 업로드합니다.

## 주의사항
- 새 버킷은 `CTD2-` 접두사를 사용하므로 기존 `CTD-` history 그룹과 자동 병합되지 않습니다.
- 실제 CTD 원인 적중률은 검토 완료 실사고 코퍼스가 있어야 측정할 수 있습니다. 코퍼스가 없는 이번 검증에서는 정확도 단계를 `SKIPPED (not measured)`로 표시합니다.
- Windows App Runtime 설치 창이 계속 뜨면 기존 `SKSE\Plugins\SkyrimDiagWinUI` 폴더를 완전히 제거하고 최신 zip 전체를 다시 설치한 뒤 MO2 파일 제공자를 확인해 주세요.
