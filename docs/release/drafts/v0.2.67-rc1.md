# v0.2.67-rc1 — 처리된 예외 동결 해제, 종료 시 리포트 보존, Crash Logger 1.22 미만 원인 플러그인

외부 리뷰와 공개 크래시 사례에서 찾은 문제를 고친 테스트용 프리릴리즈입니다. Helper가 크래시를 다루는 방식이 바뀌어 실게임 확인이 필요합니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- **처리된 예외를 크래시로 잡아 둔 뒤 게임이 계속 돌면 풀어 줍니다.** 기본 설정(`CrashHookMode=1`)에서 플러그인은 치명적 예외를 처리되기 전에 기록하고, Helper는 약 11초 동안 하트비트를 보고 진짜 크래시인지 가립니다. 그 사이 메인 스레드가 바빴다면(긴 로딩 등) 처리된 예외가 크래시로 남았고, 그 세션 내내 블랙박스·리소스 기록이 멈추고 이후의 진짜 CTD도 기록되지 못했습니다. 이제 크래시로 잡은 뒤에도 게임이 60초 넘게 살아 있고 하트비트가 30초 연속 전진하면 처리된 예외로 보고 정리합니다(정상 종료 때와 같은 규칙).
- **게임이 꺼질 때 리포트 분석을 끊지 않습니다.** 크래시 뒤 게임이 종료되면 Helper가 진행 중인 백그라운드 분석을 강제로 끝냈습니다. 뷰어를 자동으로 열지 않는 설정(`AutoOpenViewerOnCrash=0`)에서는 그 분석이 리포트를 쓰는 유일한 경로라 리포트가 사라졌습니다. 이제 끝까지 쓰게 둡니다.
- **Crash Logger 1.22 미만 로그에서 원인 플러그인을 읽습니다.** 1.14·1.15 로그는 레지스터가 가리키던 오브젝트의 플러그인을 `REGISTERS:` 아래에만 적는데, 이 줄을 하나도 읽지 못하고 있었습니다. 원인이 공개된 실제 사례 2건(패치 ESP, 날씨 ESM)에서 정답 플러그인이 이제 잡힙니다. 1.22 이상은 같은 정보를 다른 절에서 이미 읽고 있어 바뀌지 않습니다.
- **상대 경로 `OutputDir`에서 자동 분석이 실패하던 문제를 고쳤습니다.**

## 엔진 변경
- Helper: 크래시로 확정한 뒤 5초마다 하트비트를 봅니다. 프로세스가 60초 넘게 살아 있고 5초 구간 6번 연속 하트비트가 전진하면, 진행 중인 분석·ETW·지연 뷰어를 멈추고 덤프를 정상 종료 때와 같은 규칙으로 정리합니다(기본은 삭제, `PreserveFilteredCrashDumps=1`이면 보존). 정상 종료 증거 기록에 `filter_context: late_recovery`를 남기고, 블랙박스·리소스 기록 동결을 풉니다. 일시정지·최소화로 하트비트가 멈춘 구간이 있으면 처음부터 다시 셉니다.
- 분석기: 보존된 늦은 복구 덤프는 "종료 코드 0" 대신 "예외 뒤에도 게임이 계속 실행됨"으로 설명합니다. 요약 JSON `clean_exit_evidence.filter_context`.
- Helper: 게임 종료 때 백그라운드 분석은 끝까지 두고, 종료 시점에 뷰어가 열려 같은 덤프를 분석할 때만 멈춥니다(기본 설정 동작은 그대로). 분석 시간 제한(`AutoRecaptureAnalysisTimeoutSec`)은 재캡처를 켠 경우에만 분석을 끊습니다.
- Helper: `OutputDir` 상대 경로를 Helper 폴더 기준 절대 경로로 바꿉니다. 이전에는 분석기가 `MyLogs\MyLogs\x.dmp`를 찾다가 실패했습니다.
- 분석기: Crash Logger `REGISTERS:`에서 레지스터 줄보다 한 단계 깊은 줄(오브젝트 자신의 `File:`, FormID, 이름)만 읽습니다. `ParentCell:` 아래처럼 더 깊은 줄은 다른 오브젝트라 읽지 않아, 장소 모드가 캐릭터의 플러그인으로 붙지 않습니다.
- 플러그인: 리소스 기록에서 같은 파일 중복 확인을 기록량 제한보다 먼저 합니다. 같은 파일을 반복해서 여는 것이 제한 계산에 들어가, 크래시 직전 새 파일이 최대 8개 중 7개까지 빠질 수 있었습니다.
- 뷰어: 블랙박스 이벤트 수를 최근 200줄이 아닌 전체로 표시하고, 덤프가 96개를 넘으면 최신 덤프가 목록에서 빠지던 문제를 고쳤습니다.
- Helper: 재캡처 기록(`Incident_CrashRecapture_*.json`)을 그 덤프와 함께 보관 정리합니다.
- 릴리즈: 초안도 CHANGELOG 항목도 없는 태그는 공개 단계에서 실패합니다(이전에는 "Release vX" 한 줄로 공개됨).

## 테스트 시 확인할 점
- 평소처럼 플레이하고 `Ctrl+Shift+F12`로 수동 캡처를 한 번 해 주세요. 플레이와 캡처가 이전과 같으면 됩니다.
- CTD가 나면(일부러 낼 필요는 없습니다) 리포트와 뷰어가 이전처럼 나오는지 봐 주세요.
- `SkyrimDiagHelper.log`에 "Game kept running …" 줄이 보이면, 그 앞뒤 줄과 함께 알려 주세요. 처리된 예외를 늦게 풀어 준 기록입니다.
- 뷰어를 자동으로 열지 않게 설정해 쓰신다면(`AutoOpenViewerOnCrash=0`), CTD 뒤에 리포트 파일이 생기는지 봐 주세요.

## 주의사항
- Helper와 플러그인이 바뀌었습니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요. MO2에서 새 모드로 설치했다면 이전 버전 모드는 꺼 주세요.
- 늦은 복구는 게임이 1분 넘게 정상으로 도는 동안에만 일어납니다. 진짜 CTD는 그 전에 프로세스가 끝나므로 영향을 받지 않습니다.
- 다음은 아직 고치지 않았습니다: 1차 예외를 걸러내는 약 11초 사이에 난 진짜 CTD가 기록되지 못하는 문제(프로토콜 설계 필요), 비ASCII 리소스 경로(감사 F16).
