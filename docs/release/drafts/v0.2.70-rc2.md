# v0.2.70-rc2 — 엔진 잠금 교착 감지, 예전 분석 결과 자동 재분석, 함정 접촉 크래시

rc1 이후 프리징 분석을 넓히고 rc1의 안내 누락을 고친 테스트용 프리릴리즈입니다. Helper와 분석기, 뷰어가 바뀌었습니다.

## 한눈에 보기
- **게임 스레드끼리 엔진 잠금에서 서로를 기다리며 멈춘 프리징을 알아봅니다.** 게임 엔진은 자기 잠금을 기다릴 때 OS 대기 대신 잠깐씩 잠들기 때문에, 지금까지는 Windows 대기 정보(WCT)에 이런 교착이 보이지 않았습니다. 이제 Helper가 프리징 캡처 때 잠든 게임 스레드가 가리키는 잠금 메모리를 덤프에 함께 담고, 분석기가 어느 스레드가 어느 잠금을 쥐고 기다리는지 읽어 "엔진 잠금 교착"(`engine_lock_deadlock`)으로 보고합니다. 특정 모드를 원인으로 지목하지 않습니다.
  - 1.5.97에서 알려진 교착 3종은 해결 모드를 안내합니다: 셀 로딩 잠금 순서 교착과 읽기/쓰기 잠금 자기 교착은 [Skyrim Cell load Freeze fix NG](https://www.nexusmods.com/skyrimspecialedition/mods/160704), 작업 스레드 스핀 잠금 교착은 [WorkerSpinLockFix](https://www.nexusmods.com/skyrimspecialedition/mods/180884)(`[phase4_defer] enabled=true`).
- **예전에 분석해 둔 덤프를 뷰어가 자동으로 다시 분석합니다.** 요약에 분석기 버전(`analyzer_version`)을 기록하고, 뷰어보다 오래된 분석기가 쓴 요약은 열 때 한 번 다시 분석합니다. 새 버전에서 생긴 항목("어떻게 튕겼나" 등)을 보려고 분석 버튼을 다시 누를 필요가 없어집니다.
- **1.6.1170의 함정 접촉 크래시(`SkyrimSE.exe+0x3FF101`)를 알아봅니다.** 액터가 닿아 있던 함정 오브젝트가 사라진 뒤 엔진이 그 함정을 계속 처리하다 튕기는 크래시입니다. Calamity 2(`CalamityAffixes.dll`)가 로드되어 있으면 2.2.6 이상으로 업데이트하라고 안내합니다.

## 수정
**Helper**
- 프리징·수동 캡처에서 `ntdll!NtDelayExecution`에서 잠든 게임 스레드의 비휘발 레지스터와 스택 위쪽이 가리키는 SkyrimSE.exe 쓰기 가능 데이터를 64바이트 단위로 덤프에 추가하고, 어느 섹션이 데이터인지 알 수 있게 실행 파일 헤더(4KB)도 함께 담습니다. 상한은 스레드당 32개, 전체 128개, 256KB, 20ms이고, 기존 오브젝트 메모리 예산 안에서 씁니다. Helper 로그에 `Lock memory:` 한 줄이 남습니다. 게임 쪽 `NtDelayExecution` 앞부분이 Helper의 것과 다르면 이 수집을 하지 않습니다.

**분석기**
- 엔진 잠금 교착: 잠금 함수 자기 프레임까지의 레지스터·스택 값 중 다른 스레드가 쥔 `BSSpinLock`이나 쓰기로 잡힌 `BSReadWriteLock`을 가리키는 것만 대기로 보고, 대기끼리 고리를 이룰 때만 교착으로 판정합니다(신뢰도 중간). 메인 스레드를 알 수 없는 덤프에서도 게임 스레드를 봅니다. Summary JSON `freeze_analysis.game_lock_waits`, `freeze_analysis.engine_lock_deadlock`, 리포트, 근거, 빠른 답, 버킷(`HANG1-` + 잠금 위치)에 씁니다.
- 1.5.97 교착 3종: 게임 버전, 스레드별 스택 위치, 잠금 위치와 쥔 스레드가 모두 맞을 때만 일치합니다. 잠금 메모리가 덤프에 없으면 일치하지 않습니다.
- 함정 접촉 크래시 서명 `TRAP_CONTACT_REMOVED_1_6_1170`(크래시 메커니즘, 신뢰도 중간).
- Summary JSON에 `analyzer_version` 추가.
- 리포트의 리소스 로드 시각이 세션 16분쯤부터 `2.91565e+06`처럼 과학적 표기로 나오던 문제를 고쳤습니다.

**뷰어**
- 저장된 요약을 다시 쓸지 정하는 규칙을 바꿨습니다: 빠른 답이 없거나, 분석기 버전이 없거나 뷰어보다 낮으면 다시 분석합니다. 더 새 분석기가 쓴 요약은 그대로 보여 줍니다.

**개발**
- `scripts/compare_analyses.py`: 두 분석기 빌드를 같은 덤프로 돌려 사용자가 보는 내용의 차이만 보여 주는 도구.

## 정정
- rc1에서 크래시용 알려진 서명의 "수정 모드가 이미 로드되어 있으면 업데이트를 확인하라"는 안내가 실제로는 나오지 않았습니다(키보드 입력 크래시, 물 충돌 크래시). 크래시 쪽 서명 비교에 로드된 모듈 목록을 넘기지 않고 있었습니다. rc2에서 고쳤습니다.

## 테스트 시 확인할 점
- 평소처럼 플레이해 주세요. 프리징이 나면(일부러 낼 필요는 없습니다) Helper 로그의 `Lock memory:` 줄과, 리포트가 엔진 잠금 교착인지 다른 판정인지 봐 주세요.
- rc1이나 그 이전에 분석해 둔 덤프를 뷰어에서 열면 한 번 다시 분석되고, 접근 위반 크래시라면 빠른 답에 "어떻게 튕겼나" 줄이 나와야 합니다.

## 주의사항
- Helper와 분석기, 뷰어가 바뀌었습니다. ZIP 전체를 설치해 주세요. MO2에서 새 모드로 설치했다면 rc1 모드는 꺼 주세요.
- 엔진 잠금 교착 판정은 실제 프리징에서는 아직 확인되지 않았고 합성 테스트로만 검증했습니다. 잠금 메모리 수집은 1.6.1170 수동 캡처에서 확인했습니다(`threads=4 pointers=4 ranges=3 bytes=4224 time_us=375`, 캡처 뒤 게임 정상).
- 알려진 교착 3종의 해결 모드 안내는 1.5.97에만 있습니다. 1.6.x에서 같은 형태의 교착이 나면 해결 모드 이름 없이 엔진 잠금 교착으로만 보고합니다.
- 게임이 정상일 때의 수동 캡처는 프리징 분석 대상이 아니라 교착 판정도 하지 않습니다.
