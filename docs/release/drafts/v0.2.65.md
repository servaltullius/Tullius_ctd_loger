# v0.2.65 — 틀린 진단 전수 점검(BEES, ENB/ReShade, MO2 우선순위, AE 리소스 기록)

리포트가 사용자 환경에 대해 틀린 말을 하던 곳을 전수 점검해 고친 릴리즈입니다. 계기는 "BEES를 설치했는데 미설치라고 나온다"는 Nexus 제보였습니다. Codex 감사와 직접 점검으로 같은 유형의 문제를 찾았고, 확인된 것을 고쳤습니다.

## 한눈에 보기
- **BEES 감지 수정** — BEES가 실제로 설치하는 `BackportedESLSupport.dll`을 찾지 않고 `bees.dll`만 찾아, 1.6.1130 미만에서 1.71 헤더 플러그인을 쓰면 BEES가 있어도 항상 "미설치"로 나왔습니다. 이제 두 이름을 모두 보고, "미설치" 대신 "로드되지 않음(설치하지 않았거나 SKSE가 로드하지 못함)"이라고 씁니다.
- **ENB/ReShade 오탐 수정** — 게임이 항상 로드하는 Windows의 `d3d11.dll`·`dxgi.dll`을 ENB와 ReShade로 착각해, 거의 모든 리포트가 "ENB, ReShade 감지됨"이라고 했습니다. 이제 Windows 폴더 밖(게임 폴더)에서 로드된 사본만 그래픽 인젝터로 봅니다. 같은 이름을 ENB, ReShade, DXVK가 모두 쓰므로 제품 이름 대신 DLL 이름을 적습니다. 게임 폴더의 인젝터 DLL은 이제 후보가 될 수 있습니다.
- **AE에서 리소스 기록이 처음으로 동작** — 1.6.x·1.7.x에서 리소스 기록 후킹이 엉뚱한 칸(다음 vtable의 RTTI 포인터)을 덮어쓰고 있었고, 리소스는 한 번도 기록되지 않았습니다. 게임 파일과 덤프로 구조를 확인해 고쳤고, 패치하기 전에 대상을 RTTI로 확인해 맞지 않으면 아무것도 건드리지 않습니다. 1.6.1170 실게임에서 처음으로 리소스 120개와 그 제공 모드가 기록됐습니다.
- **MO2 우선순위** — `modlist.txt`를 거꾸로 읽어, 모드끼리 충돌할 때 지는 모드를 이기는 모드로 봤습니다. Crash Logger 설정 파일(`CrashLogger.ini`)과 리소스 제공 모드에 영향이 있었습니다.
- **다른 사고의 Crash Logger 로그 차단** — 시간만 맞는 다른 사고의 로그로 "알려진 원인"을 붙일 수 있었습니다. 이제 예외 위치가 덤프와 같은 로그만 시그니처에 씁니다.

## 그 밖에 고친 것
- Crash Logger 콜스택이 스레드 시작(ntdll.dll)까지 이어질 때만 "스레드 시작 지점의 훅"으로 판정합니다.
- 후킹 설치 경쟁은 바뀐 게임 호출이 그 점프 코드를 불렀다는 것이 덤프로 확인될 때만 판정하고, "X로 가는 후킹"이라고 씁니다.
- `plugins.txt`에서 `*`가 없는 줄은 비활성으로 봅니다. 이전에는 `*`가 하나도 없으면 꺼진 플러그인까지 모두 활성으로 봤습니다.
- GOG·Epic 판의 `plugins.txt`와 Crash Logger 로그 폴더를 찾습니다.
- 과장된 안내를 고쳤습니다.
  - Engine Fixes 설정 이름: 7.x와 이전 버전 모두 적음
  - 물 반사 AddWater: "알려진 지점과 일치"로 낮춤
  - Address Library 오류 창: 플러그인 버전과 Address Library 파일 두 원인을 모두 안내
  - ESP 240개: 신뢰도 낮은 정리 안내로 낮춤
  - C++ 예외 가이드: `CrashHookMode=1` 권장, "GPU 드라이버 크래시", "RAM/VRAM 부족" 단정을 뺌
  - 프리징 가이드: "WCT 순환이 없으면 데드락이 아님" 문구를 뺌
  - D6DDDA: SSE Display Tweaks에 없는 "VRAM 제한" 대신 VRAM 관찰 안내
  - 뷰어: 근거 없이 띄우던 "Skyrim SE 감지됨"을 뺌
