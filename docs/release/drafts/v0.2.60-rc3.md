# v0.2.60-rc3 — AMX CPU에서 CTD 덤프 쓰기 실패 수정

rc2 실게임 결과와, CI에서 찾은 덤프 쓰기 문제의 수정을 담은 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- rc2의 SKSE 미로드 DLL 목록 묶기를 실게임에서 확인했습니다. `[SKSE]` 줄과 근거 항목에 `msdia140.dll, NpcGhostFix.dll: 버전 정보 없음(…)`이 한 번만 나왔습니다.
- AMX를 지원하는 Intel 서버 CPU(Xeon Sapphire/Emerald/Granite Rapids 등)와 Windows Server 2022의 dbghelp 조합에서 CTD 덤프 쓰기가 `0x800706F8`로 실패하던 문제를 고쳤습니다. CI에서만 간헐적으로 실패하던 덤프 테스트의 원인이었고, 같은 환경의 사용자 PC에서도 CTD 덤프를 놓칠 수 있었습니다. 일반 게이밍 PC(AMD, Intel 데스크톱 CPU)는 AMX가 없어 이전에도 해당하지 않았을 가능성이 큽니다.

## 엔진 변경
- Helper: dbghelp 10.0.20348은 예외 컨텍스트를 CPU 확장 상태 전체 크기(AMX에서 약 11.5KB)만큼 읽는데, Helper가 넘기던 것은 1,232바이트짜리 `CONTEXT`였습니다. 이제 `InitializeContext(CONTEXT_ALL | CONTEXT_XSTATE)`로 만든 확장 상태 크기 버퍼에 담아 넘깁니다. 레지스터 값은 그대로이고 리포트에는 변화가 없습니다.
- Helper: 덤프가 실패하면 로그에 오류를 16진수로도 적고, 로드된 dbghelp.dll의 버전과 경로를 남깁니다.
- CI: Windows 테스트 전에 러너의 CPU·OS·dbghelp 정보를 기록하고, dump-stress 워크플로를 16개 job과 덤프 쓰기 추적(`SKYDIAG_DUMP_IO_TRACE=1`, 테스트 전용)으로 바꿨습니다.

## 정정
- v0.2.59와 그 rc5·rc6 노트는 이 간헐적 실패를 `ERROR_PARTIAL_COPY`로 설명했지만 잘못 읽은 것이었습니다. 로그의 `2147944184`는 `0x800706F8`(ERROR_INVALID_USER_BUFFER)이고, 기록된 실패 5건이 모두 이 코드였습니다. rc5에 넣은 "읽을 수 없는 메모리를 건너뛰는 재시도"는 이 실패에서 한 번도 동작하지 않았습니다.

## 테스트 시 확인할 점
- 평소처럼 플레이하다가 수동 캡처(`Ctrl+Shift+F12`)를 한 번 해서 덤프와 리포트가 정상으로 만들어지는지 확인해 주세요. CTD가 나면 `SkyrimDiag_Crash_*` 덤프가 남는지도 봐 주세요.
- 아직 실게임에서 확인하지 못한 항목: 모드의 assert로 난 CTD에서 `ExceptionCode`가 `0x80000003`이고 `Module+Offset`이 `CrashLogger.dll`이 아닌지, 덤프가 실패했을 때 실패 위치가 Helper 로그에 남는지, Address Library 오류 창 안내(보관 덤프 재분석으로만 확인).

## 주의사항
- Helper가 바뀌었습니다. ZIP 전체를 교체해 주세요.
- 이 사용자 환경(AMD Ryzen, Windows 11)은 AMX가 없어 이번 수정의 효과를 직접 볼 수는 없습니다. 수정은 CI의 AMX 호스트에서 검증했습니다.
- 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
