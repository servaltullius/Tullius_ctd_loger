# v0.2.54 — CTD 원인 과단정 방지 및 캡처 정합성 보강

## 핵심 변경
- 플러그인과 Helper 사이의 크래시 컨텍스트를 원자적으로 커밋해, 예외 정보가 기록되는 도중의 불완전한 상태로 덤프가 만들어질 가능성을 줄였습니다.
- 알려진 크래시 서명은 기본적으로 "발생 메커니즘"을 설명하고, 실제 근본 원인 후보는 stack, Crash Logger, plugin/resource/history 등 별도 증거 합의 결과로 판단합니다.
- Crash Logger에 등장한 원시 DLL 프레임은 보존하되, 시스템 DLL·게임 실행 파일·훅 프레임워크가 사용자의 조치 대상 모드처럼 승격되지 않도록 했습니다.
- 예외 스레드 우선, 낮은 품질 stack 강등, 후보 키 충돌 방지, Crash Logger 로그 페어링 보강으로 기존의 구조적 오탐 경로를 줄였습니다.

## WinUI / 사용성
- signature 일치는 `scope`, `mechanism`, `match_confidence`로 표시되고, 근본 원인 후보 판단과 구분됩니다.
- Crash Logger의 `direct fault`, `first actionable probable`, `probable streak` 원문은 유지하면서 각 필드의 eligibility를 별도로 표시·판정합니다.
- 원시 프레임이 관측됐지만 행동 후보로 승격되지 않은 경우 이를 유력 원인처럼 표현하지 않습니다.
- 공유 문구의 "유력 원인" 표현을 "유력 후보"로 조정해 덤프 기반 추론의 한계를 더 명확히 했습니다.

## 엔진 변경
- 공유 메모리 프로토콜을 v3으로 올리고 `crash_seq` seqlock을 추가했습니다. Helper는 동일한 committed sequence에서 얻은 안정 스냅샷만 blackbox와 exception stream에 사용합니다.
- 복구 가능한 first-chance 예외는 자신이 기록한 시퀀스만 해제할 수 있으며, 더 최신의 치명적 크래시를 덮거나 thaw하지 못합니다.
- Helper는 프로세스 종료 전에 대기 중인 crash event를 우선 처리하고, 내부 덤프가 없는 비정상 종료에는 WER 확인 단서를 남깁니다.
- `D6DDDA_VRAM` 서명을 SkyrimSE 1.5.97.0의 정확한 `SkyrimSE.exe+0xD6DDDA` 접근 위반 메커니즘인 `D6DDDA_1597_AV`로 좁혔습니다. VRAM 압박과 손상 에셋은 확정 원인이 아니라 대조 실험 가설로 취급합니다.
- CTD stackwalk와 fallback stack scan 모두 예외 스레드를 우선하며, capture-quality와 Low/Unknown stack 신호는 단독으로 후보를 Medium 이상으로 승격시키지 않습니다.
- 후보 canonical key가 구분자와 Unicode를 보존하고, crash history schema v2가 모호한 구형 후보 키의 오승격을 차단합니다.
- Crash Logger 로그 검색은 artifact 종류를 확인하고, 120초 이내에서 실제 시간 차이를 최우선으로 비교합니다.

## 빌드 / 운영
- 실제 WinUI 후보 표시 순서와 같은 기준으로 top-1 accuracy, top-3 recall, High-confidence precision, abstention rate를 계산하는 품질 게이트를 보강했습니다.
- 중복 incident 또는 ground truth/분석 결과 충돌은 조용히 합치지 않고 설정된 품질 게이트를 실패시킵니다.
- RelWithDebInfo 테스트에서도 assertion을 유지하고, 상태 변경 호출을 assertion 바깥에서 실행하도록 정리했습니다.
- Crash Logger 로그 검색의 실제 Windows 파일·FILETIME·120초 경계를 검증하는 통합 테스트를 추가했습니다.
- 더 이상 사용하지 않는 Vibekit 스크립트, 에이전트 안내, 전용 CI와 smoke test를 제거했습니다.

## 주의사항
- `SkyrimDiag.dll`과 `SkyrimDiagHelper.exe`는 공유 메모리 protocol v3을 함께 사용합니다. 이전 릴리즈 파일과 일부만 섞지 말고 v0.2.54 zip 전체를 설치해 주세요.
- High-confidence signature는 크래시 패턴이 강하게 일치한다는 뜻이며, 특정 모드 또는 에셋이 근본 원인으로 확정됐다는 뜻은 아닙니다.
- 실제 CTD 원인 적중률을 수치로 확인하려면 검토 완료 실사고 summary의 `triage.ground_truth_mod` 라벨이 필요합니다. 합성 fixture만으로 정확도 백분율을 주장하지 않습니다.
