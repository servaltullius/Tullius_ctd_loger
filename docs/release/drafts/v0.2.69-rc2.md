# v0.2.69-rc2 — 엔진 NaN 반복 프리징 판정, 호출 경로의 플러그인을 원인으로 지목하지 않음

v0.2.68 실사용 프리징 두 번(2026-10-22)에서 찾은 오진을 고친 테스트용 프리릴리즈입니다. 분석기만 바뀌었습니다.

## 한눈에 보기
- **엔진이 계산하다 멈춘 프리징에서 엉뚱한 모드를 지목하지 않습니다.** 같은 화이트런 실내를 불러온 직후 두 번 멈췄는데, 리포트는 업스케일러(SkyrimUpscaler.dll)를 유력 원인으로 지목했습니다. 덤프를 보니 메인 스레드가 기다린 게임 스레드는 게임 엔진의 각도 계산 루프에서 값이 숫자가 아닌 값(NaN)이 되어 끝없이 반복하고 있었고, 업스케일러는 그 스레드 스택 깊은 곳의 호출 경로에 있었을 뿐이었습니다.
- **새 판정 "엔진 NaN 반복"(`engine_spin_nan`).** 이런 프리징은 이제 "게임 계산 값이 숫자가 아닌 값(NaN)이 되어, 엔진이 같은 계산을 끝없이 반복하다 멈췄습니다"라고 쉬운 말로 알려 주고, 특정 모드를 원인으로 지목하지 않습니다.

## 수정
**분석기: 프리징**
- 메인 스레드가 기다린 게임 스레드가 게임 엔진 코드를 실행 중이고, 플러그인은 그 아래 5프레임 이상 깊이에만 있으면, 그 플러그인을 원인 후보·이력·버킷에서 빼고 "호출 경로에 있었을 뿐"으로 표시합니다. 스택 위쪽에서 실제로 실행 중인 플러그인은 지금처럼 단서로 남습니다.
- 새 판정 `engine_spin_nan`(신뢰도 중간): 대상 스레드가 WCT 두 번 모두 실행 중(Running)이고, 그 스레드의 명령 위치가 게임 실행 파일의 부동소수점 비교와 되돌아가는 점프로 된 짧은 루프이며, 비교하던 값이 NaN이면 판정합니다. 이 루프는 NaN이면 빠져나올 수 없습니다.
  - 빠른 답과 결론은 특정 모드를 지목하지 않고, 최근 추가·업데이트한 전투·애니메이션·AI/길찾기·캐릭터 움직임 모드를 점검하라고 안내합니다. 스택의 플러그인은 호출 경로로만 적습니다.
  - 리포트와 요약 JSON에 `freeze_analysis.engine_spin`(스레드, 루프 위치, NaN이 든 레지스터)을 기록하고, 같은 루프에서 멈춘 프리징은 하나의 버킷으로 묶습니다.

- 이번 NaN 프리징의 원인 오브젝트는 기본 덤프(`DumpMode=1`)에 게임 힙이 담기지 않아 특정하지 못했습니다. 같은 프리징이 반복되면 `SkyrimDiagHelper.ini`에서 잠시 `DumpMode=2`(전체 메모리)로 바꿔 재현하면 그 오브젝트까지 읽을 수 있습니다(덤프가 수 GB로 커짐).
