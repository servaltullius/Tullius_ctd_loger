# v0.2.59-rc4 — Creation Club 누락 마스터 오판 수정

rc3 실게임 테스트에서 나온 CTD 리포트로 찾은 문제를 고친 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- MO2 + Anniversary Edition 환경에서 Creation Club 파일이 모두 "누락 마스터"로 잘못 판정되어, 리포트 맨 위 `[필수]` 안내와 다음 조치를 차지하던 문제를 고쳤습니다. rc3에서 크래시 후 플러그인 스캔이 다시 동작하면서 드러난 문제입니다.
- PDB가 없는 모드 DLL의 콜스택이 `SmoothCam.dll!SKSEPlugin_Load+0x7bd57`처럼 엉뚱한 함수 이름으로 표시되지 않고, `SmoothCam.dll+0x...`로 표시됩니다.

## WinUI / 사용성
- "ESL 슬롯 한계 근접"처럼 신뢰도 낮은 플러그인 규칙의 안내는 체크리스트 끝으로 옮겨, 크래시 안내보다 앞서 다음 조치가 되지 않습니다.
- 이전 버전으로 캡처한 덤프를 다시 분석해도 Creation Club 마스터를 누락으로 판정하지 않습니다.

## 엔진 변경
- Helper의 플러그인 스캔은 게임이 `plugins.txt` 항목 없이 읽는 기본 마스터(Skyrim.esm, Update.esm, DLC 3개)와 `Skyrim.ccc`의 Creation Club 파일 중 `Data`에 있는 것을 활성 플러그인으로 포함하고, 스캔 결과에 `implicit_plugins_included`를 남깁니다.
- 분석기는 이 표시가 없는 이전 스캔 결과에서 `plugins.txt`에 없는 Creation Club 마스터를 누락으로 판정하지 않습니다.
- 콜스택 표시에서, 모듈 심볼이 export뿐이고 가장 가까운 export와의 거리가 `0x1000`을 넘으면 함수 이름 대신 `모듈+오프셋`을 씁니다.

## 테스트 시 확인할 점
- 사고 후 리포트에 `누락 마스터`나 `MISSING_MASTER`가 나오지 않는지 확인해 주세요. 실제로 마스터가 빠진 플러그인이 없다면 나오지 않아야 합니다.
- 덤프 옆 `*_PluginScan.json`에 `"implicit_plugins_included": true`가 있는지 확인해 주세요.
- 콜스택에 `SKSEPlugin_Load+0x...`처럼 먼 함수 이름이 붙지 않는지 확인해 주세요.
- rc3의 확인 항목도 계속 봐 주세요. 특히 모드의 assert로 난 CTD(CrashLogger 로그 맨 위가 `EXCEPTION_BREAKPOINT`)에서 리포트의 `ExceptionCode`가 `0x80000003`이고 `Module+Offset`이 `CrashLogger.dll`이 아닌지 확인해 주세요. 이 수정은 아직 실게임에서 확인되지 않았습니다.

## 주의사항
- 이번 변경은 Helper와 분석기입니다. 플러그인(`SkyrimDiag.dll`)은 rc3과 같지만 ZIP 전체를 교체해 주세요.
- 플러그인 스캔은 MO2 가상 파일 시스템 안에서 실행되는 Helper가 `Data`를 보는 방식에 기댑니다. 한 사용자 환경에서 Helper가 모드 폴더의 플러그인 헤더를 읽는 것을 확인했습니다.
- export 이름 판정의 거리 기준(`0x1000`)은 경험적 값이며, 실사고 덤프 재분석으로만 확인했습니다.
- 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
