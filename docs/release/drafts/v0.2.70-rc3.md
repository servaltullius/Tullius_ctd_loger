# v0.2.70-rc3 — Alt+F4 강제 종료 중 오류를 CTD와 구분

rc2 이후 Alt+F4로 게임을 끌 때 난 오류를 CTD와 구분하는 테스트용 프리릴리즈입니다. 플러그인과 Helper, 분석기, 뷰어가 바뀌었습니다.

## 한눈에 보기
- **Alt+F4로 게임을 강제 종료하다 난 오류를 CTD로 보고하지 않습니다.** 게임은 Alt+F4를 받으면 렌더러와 모드 DLL을 정리하며 닫히는데, 이때 일부 모드의 후킹 코드가 이미 사라진 뒤에 불려 오류가 나는 경우가 있습니다(2026-10-26 실사고). 지금까지는 이것이 CTD로 기록되고 뷰어가 자동으로 떴습니다. 이제 플러그인이 Alt+F4·창 닫기(X 버튼)·게임 메뉴의 종료를 기록하고, 그로부터 10초 안에 난 오류는 "강제 종료 중 오류"로 분류합니다.
  - 빠른 답: "Alt+F4로 게임을 강제 종료하는 과정에서 난 오류입니다. 플레이 중에 튕긴 CTD가 아닙니다. 세이브에는 보통 영향이 없습니다." / "따로 할 일은 없습니다."
  - 뷰어가 자동으로 뜨지 않습니다. 덤프와 리포트는 그대로 남고, 상세 분석도 그대로 볼 수 있습니다.
  - 크래시 기록(같은 크래시 횟수, 크래시 버킷)에 넣지 않습니다.
- **해제된 메모리로 점프해 튕긴 경우를 그렇게 말해 줍니다.** "어떻게 튕겼나"에서 실행하려던 주소에 메모리가 없으면 "해제된 메모리(예: 제거된 후킹 코드)로 이동했다", 실행할 수 없는 데이터 메모리였으면 "코드가 아닌 데이터 주소로 이동했다(망가진 함수 포인터)"고 씁니다.

## 수정
**플러그인**
- 닫기 요청 기록(`EnableCloseRequestLog=1`, 기본 켬): 스카이림은 키보드를 DirectInput으로 읽어 Alt+F4가 창 메시지로 오지 않으므로, 다음을 함께 봅니다.
  - 하트비트 스케줄러 스레드가 25ms마다 Alt와 F4 키 상태를 읽고, 게임 창이 앞에 있을 때 둘이 함께 눌리면 기록합니다.
  - 크래시 순간에 Alt+F4가 아직 눌려 있으면 기록합니다(Alt+F4를 처리하는 바로 그 프레임에서 난 오류). 이미 GUI 스레드인 스레드에서만 확인합니다.
  - 게임의 종료 플래그(`Main::quitGame`)가 켜지는 순간을 기록하고, 그때 상황으로 Alt+F4, 메뉴의 종료(종료 확인 창·메인 메뉴·콘솔 `qqq`), 그 밖의 강제 종료를 구분합니다.
  - 게임 창 스레드의 관찰 전용 훅(`WH_GETMESSAGE`, `WH_CALLWNDPROC`)으로 X 버튼과 다른 프로그램의 닫기 요청을 봅니다. 메시지를 바꾸지 않고 항상 다음 훅으로 넘기며, 창 프로시저를 서브클래싱하지 않습니다.
  - 처음 본 닫기 요청은 `SkyrimDiag.log`에 한 줄 남깁니다(예: `close request seen: alt_f4 (keys held, game foreground)`).
- 블랙박스 이벤트 `kCloseRequest`(90)를 추가했습니다. 기존 이벤트 해석은 그대로라 공유 메모리 버전은 올리지 않았습니다.

**Helper**
- 닫기 요청 10초 안의 크래시는 뷰어 자동 열기를 건너뛰고 로그에 남깁니다(`Skipped viewer auto-open: crash followed a close request (Alt+F4) …`). 덤프와 자동 분석은 그대로 하고, 크래시 버킷 통계는 갱신하지 않습니다.

**분석기**
- 덤프의 블랙박스로 같은 판정을 합니다. Summary JSON `analysis.is_forced_close`와 `forced_close`(종류, 닫기 요청에서 크래시까지 걸린 시간), 리포트 분류 줄(`분류: 강제 종료 (CTD 아님; …)`), 근거, `[강제 종료]` 다음 조치에 씁니다. 정상 종료처럼 크래시 이력에서 뺍니다.
- `fault_instruction.target_state`: `bad_jump` 대상 주소의 메모리 상태(`freed`, `reserved`, `not_executable`, `executable`)를 덤프의 메모리 정보에서 읽어 씁니다. 문장이 바뀌는 것은 `freed`와 `not_executable`입니다.

**뷰어**
- 분류와 공유 텍스트 머리글에 강제 종료로 표시합니다.

## 테스트 시 확인할 점
- 게임을 Alt+F4로 꺼 보세요. 오류가 나지 않으면 아무 일도 없어야 하고, 오류가 나면 뷰어가 뜨지 않아야 합니다. `SkyrimDiag.log`에 `close request seen: alt_f4` 줄이 남고, 남은 리포트의 분류 줄이 강제 종료여야 합니다.
- 게임 메뉴에서 "종료"로 끄거나 콘솔 `qqq`로 꺼도 됩니다. 이때 오류가 나면 리포트는 "게임 종료를 고른 뒤…"로 나와야 합니다.
- 플레이 중 진짜 CTD에는 지금처럼 뷰어가 떠야 합니다.

## 주의사항
- 플러그인과 Helper, 분석기, 뷰어가 바뀌었습니다. ZIP 전체를 설치해 주세요. MO2에서 새 모드로 설치했다면 rc2 모드는 꺼 주세요.
- 다른 창·오버레이 모드와 충돌이 의심되면 `SkyrimDiag.ini`의 `EnableCloseRequestLog=0`으로 끌 수 있습니다. 끄면 Alt+F4 뒤의 오류도 예전처럼 CTD로 보고합니다.
- 닫기 요청 뒤 10초 안에 난 오류는 모두 강제 종료 중 오류로 봅니다. 게임이 닫기 요청을 무시하고 계속 돌다가 10초 안에 진짜 CTD가 나면 그것도 강제 종료로 분류됩니다.
- 남는 한계: 콘솔이나 메인 메뉴, 종료 확인 창을 연 채로 누른 Alt+F4를 키 샘플이 놓치면 "게임 종료를 고른 뒤…"로 나옵니다.

## 검증
- Windows test suite: (패키징 후 기록)
- 실게임(1.6.1170, PrismaUI 테스트 빌드가 Alt+F4 때마다 해제된 후킹 코드를 불러 오류를 냄): 2026-10-27 09:00 Alt+F4 → `close request seen: alt_f4 (keys held, game foreground)`, Helper `Skipped viewer auto-open`, 뷰어 안 뜸, 빠른 답 강제 종료, `target_state=freed`. 그 전 시험 네 번에서 찾은 문제(창 훅이 Alt+F4를 못 봄, 종료 플래그만으로는 Alt+F4를 메뉴 종료로 잘못 부름, Alt+F4를 처리하는 프레임 안의 오류를 놓침)를 고친 뒤의 결과입니다.
- 미확인: 검수 반영(4529bc7: 크래시 순간 확인을 GUI 스레드로 한정, 게임 창 핸들 갱신, 메뉴 종료 판정 축소, 기록을 끄면 하트비트 25ms 깨우기 안 함) 뒤의 실게임 Alt+F4, 메뉴 종료·`qqq` 뒤의 오류, X 버튼.
