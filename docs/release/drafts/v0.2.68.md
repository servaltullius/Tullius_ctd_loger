# v0.2.68 — 수동 캡처 단축키 변경, 크래시 기록 누락·중복 수정, 한글 환경·경로 가리기, 분석 정확도

v0.2.68-rc1~rc5를 묶어 정식으로 내는 릴리즈입니다. rc5 이후에는 Helper 로그 보관 방식만 바뀌었습니다. 플러그인, Helper, 분석기, 뷰어가 모두 바뀌었으니 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요. MO2에서 새 모드로 설치했다면 이전 버전 모드는 꺼 주세요.

## 한눈에 보기
- **수동 캡처 기본 단축키가 `Ctrl+Shift+Backspace`로 바뀌었습니다.** 예전 `Ctrl+Shift+F12`는 Crash Logger 1.25의 스레드 덤프 단축키와 같아서, 누를 때마다 Crash Logger 스레드 덤프가 함께 실행됐습니다. 그 스레드 덤프는 드물게 게임을 멈추게 합니다(실게임에서 관찰한 교착). `SkyrimDiagHelper.ini`의 `ManualCaptureHotkey`로 바꿀 수 있고, Crash Logger 단축키와 겹치게 설정하면 사전점검이 경고합니다. 예전 키를 누르면 Helper 로그에 안내가 남습니다.
- **크래시를 놓치거나 두 번 기록하던 경로를 막았습니다.**
  - Crash Logger 없이도 처리되지 않은 C++ 예외·중단점·noexcept 위반으로 꺼진 게임을 기록합니다.
  - 크래시를 잡은 뒤 같은 CTD를 "프리징"으로 한 번 더 덤프하던 문제, Helper가 크래시를 처리하다 죽으면 그 세션의 이후 CTD가 전부 빠지던 문제를 고쳤습니다.
  - 여러 스레드의 처리되지 않은 C++ 예외를 스레드마다 따로 보관해, 다른 스레드의 잡힌 예외가 진짜 크래시를 가리지 않습니다.
- **그래픽 제조사 프로그램·오버레이 DLL과 ENB/ReShade DLL을 바르게 분류합니다.** NVIDIA 텔레메트리, Steam·Discord 오버레이 같은 외부 프로그램 DLL은 모드처럼 지목하지 않고, 게임 폴더의 ENB/ReShade `d3d11.dll`·`dxgi.dll`은 Windows 시스템 DLL이 아니라 모드로 봅니다.
- **한글 환경 지원:** 한글 메시·애니메이션 경로, 한글 MO2 프로필 이름, UTF-8 BOM·UTF-16·ANSI로 저장한 `SkyrimDiagHelper.ini`와 한글 `OutputDir`, ANSI로 저장한 `CrashLogger.ini` 경로를 바르게 읽습니다.
- **개인정보:** 경로 가리기가 켜진 리포트·Summary·WCT 사본·사전점검 파일에 사용자 이름이 든 절대 경로가 남지 않습니다.
- **분석:** 1.6.1170 프리징의 메인 스레드를 바르게 찾고, 프리징 결론이 데드락·로딩 정지 판정과 맞습니다. Crash Logger 스레드 덤프 로그의 모듈 목록이나 Crash Logger 자신을 용의자로 올리지 않고, 근거가 약한 후보를 과장하던 문구를 고쳤습니다. 모드가 많은 환경에서 분석이 크게 빨라졌습니다(켜진 모드 4,362개 기준 11~15초 → 1초).
- **Helper 로그를 최근 5개 세션까지 남깁니다.** 크래시 뒤 게임을 여러 번 다시 켜도 크래시 난 세션의 로그가 `SkyrimDiagHelper.previous.log`, `previous.2.log` …로 남고, 첫 줄에 세션 시작 시각이 적힙니다.

## 엔진 변경
**플러그인**
- 처리되지 않은 C++ 예외와 중단점을 Crash Logger 없이도 기록합니다(최상위 예외 필터, abort 처리기; 둘 다 이전 처리기로 넘김). 잡혀서 처리된 예외는 기록하지 않고, abort는 같은 스레드에서 0.5초 안에 던진 예외가 있을 때만 그 예외를 원인으로 봅니다.
- 처리되지 않은 C++ 예외·중단점을 스레드마다 따로 보관하고(8칸), Crash Logger가 보고하다 낸 부수 예외 때 원래 예외를 기록합니다.
- 메인 스레드에서 60초마다 하트비트 이벤트를 남기고 메인 스레드 번호를 담습니다(1.6.1170의 SKSE 작업은 작업 스레드에서 돌기 때문).
- 비ASCII 리소스 경로를 ANSI 코드 페이지에서 UTF-8로 바꿔 기록하고, 로그 폴더 이름을 ANSI로 나타낼 수 없으면 8.3 짧은 이름을 씁니다.
- 메뉴 감시는 항상 켜고 `LogMenus`는 블랙박스 기록 여부만 정합니다.
- 오래된 Visual C++ 런타임(msvcp140 14.40 미만)에서 시작할 때 크래시할 수 있던 문제를 고쳤습니다.

**Helper: 캡처**
- 수동 캡처 단축키 설정(`ManualCaptureHotkey`, 기본 `Ctrl+Shift+Backspace`), 키 상태 감시의 정확한 조합 일치, 사전점검 `CRASH_LOGGER_HOTKEY_COLLISION`, 누르고 있어도 한 번만 캡처.
- Crash Logger 스레드 덤프 단축키를 감시해, 그 탐침 예외에는 1분 동안 덤프를 쓰기 전에 하트비트를 먼저 확인합니다(메인 스레드 예외는 바로 덤프).
- 크래시가 잡힌 동안 프리징 판정을 보류하고, 프리징 확인 대기 중 게임이 끝나거나 크래시가 나면 종료 처리와 크래시 캡처를 이어 갑니다.
- 다시 실행된 Helper가 처리 중이던 크래시를 한 번 다시 처리합니다. 같은 크래시에서 또 죽으면 기록을 풀어 이후 크래시가 기록되게 합니다.
- 하트비트로 "처리됨" 판정한 예외의 덤프를 `SkyrimDiag_Released_*.dmp`로 잠시 보관하고, 곧바로 비정상 종료되면 크래시 덤프로 되돌립니다. 같은 위치에서 반복되는 처리된 치명 예외는 먼저 작은 덤프로 기록합니다.
- 이미 처리한 예외를 종료 때 다시 보고하지 않고, 멈춘 게임을 직접 끈 경우에는 WER 안내를 쓰지 않으며, 덤프 쓰기 실패 안내를 덮어쓰지 않습니다.
- Alt-Tab 뒤 오류 대화상자로 멈춘 프리징을 억제하지 않고, 느린 정상 종료에서는 프리징 뷰어를 열지 않습니다. PSS 스냅샷 권한, 재캡처 분석 시간 제한, 프리징 ETW 기록 구간을 고쳤습니다.
- 게임 시작 로딩을 로딩 통계에 넣지 않습니다.

**Helper: 설정·환경**
- `SkyrimDiagHelper.ini`를 직접 디코딩하고(UTF-8 BOM/UTF-16/ANSI), `OutputDir`를 쓸 수 없으면 대체 폴더(Helper 옆 `Tullius Ctd Logs`, `%LOCALAPPDATA%\SkyrimDiag\Tullius Ctd Logs`)에 저장합니다. 뷰어도 이 폴더를 찾습니다.
- 사전점검·Crash Logger 설정 읽기·경로 확인의 오류로 Helper가 종료되지 않습니다(rc4의 `CrashLogger.ini` ANSI 경로 종료 회귀 포함).
- 플러그인 헤더 전체를 읽어 누락 마스터를 찾고, MO2 인스턴스를 MO2와 같은 순서로 고르며, `.esl`을 라이트 슬롯으로 셉니다.
- Helper 로그: 최근 5개 세션 보관(`MaxHelperSessionLogs`), 첫 줄에 세션 시작 시각.

**분석기**
- 외부 프로그램 DLL 분류, 경로 기반 시스템 DLL 판정(ENB/ReShade/DXVK, Crash Logger 콜스택 포함).
- 메인 스레드는 세션 시작 기록과 하트비트에 담긴 번호로 찾고, 프리징 결론을 데드락·로딩 정지 판정과 맞춥니다. WCT 대기 시간을 대기 시작 tick으로 해석합니다.
- 크래시 스택 스캔을 예외 시점의 스택에서 시작하고, Crash Logger 스레드 덤프 로그의 모듈 목록을 용의자로 쓰지 않습니다.
- 후보 문구를 근거에 맞춥니다(단일 신호, 스택 스캔만 있는 후보, 반복 기록·리소스만 있는 경우). In-Page Error 안내의 Steam 무결성 검사 권고 삭제, Compact FormIDs 위험 명시, 누락 마스터·로딩 판정 정리, C++ 예외 설명을 기본 설정에 맞춤.
- 경로 가리기를 Summary의 MO2 폴더·심볼 경로·WCT 사본까지 넓히고, 인시던트 manifest를 실제 캡처와 매칭합니다.
- 덤프에 적힌 DLL·MO2·게임 폴더는 로컬 고정 디스크에 있을 때만 엽니다. 손상된 입력이 분석기를 끝내지 않습니다.
- MO2 제공 모드 조회를 폴더 단위로 기억해 분석을 빠르게 했습니다. 한글 MO2 프로필 이름과 비ASCII 리소스 경로(이전 덤프)를 읽습니다.

**뷰어**
- 검토 저장 대상 고정, 실패·취소 시 이전 결과 정리, 여러 창의 덤프 위치 목록 병합, 오프라인 네트워크 폴더에서 응답 없음 방지, 검토 저장 결과를 출력 폴더의 Summary에도 반영, "지금 분석" 연속 클릭 시 결과 엇갈림 수정.

**개발·릴리즈**
- 릴리즈 공개 확인이 zip 검증 실패를 무시하던 문제 수정, 출시 바이너리 PDB를 워크플로 아티팩트로 보관, 워크플로 권한 최소화·액션 커밋 고정, clang-tidy가 프로젝트 헤더까지 검사.

## 실게임에서 확인한 것
- 1.6.1170(MO2, SKSE 2.2.6, 켜진 모드 4,362개, Crash Logger 1.25)에서:
  - rc2: 하트비트 이벤트의 메인 스레드 번호가 세션 시작 스레드와 같음.
  - rc3: Crash Logger 스레드 덤프 탐침 예외에 덤프를 쓰지 않음("No dump written").
  - rc5: `Ctrl+Shift+Backspace` 수동 캡처, Crash Logger 스레드 덤프 미실행, 사전점검 충돌 `ok`, 모든 출력 파일에 사용자 이름 없음, 인시던트 정보 채워짐.
  - rc5: 실제 CTD(업스케일러 FSR3 DLL의 0으로 나누기)가 덤프·리포트 한 번씩만 생기고 프리징 덤프 없이 기록됨. Crash Logger 로그와 시간차 0ms로 짝지어짐. 정상 종료 세션에서 크래시 오탐 없음.
- 실게임 미확인:
  - 뷰어에서 분석 도중 다른 덤프로 바꾸거나 검토를 저장하는 동작(런타임·하네스 테스트로 확인).
  - Crash Logger가 있을 때 처리되지 않은 C++ 예외를 새 예외 필터로 기록하는 경로, Trainwreck과 함께 쓸 때(자식 프로세스 런타임 테스트로 확인).
  - Helper 로그 5개 세션 보관(런타임 테스트로 확인).

## 정정
- rc3 노트의 "\"deleting dump\" 줄은 더 나오지 않아야 합니다"는 틀렸습니다. rc3 필터는 덤프가 없는 경로에서도 이 문구를 남겼고(rc4에서 고침), "No dump written" 줄이 있으면 정상이었습니다.
- v0.2.59 노트는 Crash Logger와 단축키가 겹쳐도 "두 결과가 함께 생긴다"고만 했지만, Crash Logger 스레드 덤프는 드물게 게임을 멈추게 할 수 있어 무해하지 않았습니다.

## 주의사항
- **수동 캡처는 이제 `Ctrl+Shift+Backspace`입니다.** Crash Logger 스레드 덤프를 쓰지 않는다면 `CrashLogger.ini`에서 `Enable Thread Dump Hotkey = false`로 꺼 두세요. 스레드 덤프가 게임을 멈추게 하는 것은 Crash Logger의 동작이라 우리가 막을 수 없습니다.
- 처리된 예외로 판정된 덤프가 `SkyrimDiag_Released_*.dmp`로 잠시(최대 하루, 1개) 남을 수 있습니다. 크래시가 아니므로 뷰어 목록에는 나오지 않습니다.
- 이미 저장된 로딩 통계에 든 게임 시작 시간은 새 기록이 쌓이면서 밀려납니다. 바로 낮추려면 `SkyrimDiag_LoadStats.json`을 지워도 됩니다.
- 고치지 않은 것: 프리징에서 메인 스레드가 기다리는 잠금의 주인 스레드를 따라가는 분석과 Crash Logger 스레드 덤프 교착 판정은 다음 배치입니다.

## 검증
