# v0.2.59 — 원인 지목 보수화와 실게임 검증

v0.2.59-rc1부터 rc7까지의 변경을 묶은 정식 릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- **CTD 후보 신뢰도 보수화** — Crash Logger frame과 Tullius stack이 같은 사고의 실행 위치를 함께 가리켜도 독립 교차검증으로 세지 않습니다. 반복 이력, 인접 리소스, first-chance 문맥 같은 보강 신호만으로는 `High`가 되지 않습니다.
- **프리징 원인 귀속** — 메인 스레드(최신 Heartbeat 스레드)를 기준으로 판단하고, 여러 스레드가 같은 모듈에서 함께 멈춘 경우를 `synchronization_stall_likely`로 보고합니다. 리소스 제공자만으로는 후보가 되지 않습니다.
- **게임 플레이 중 프리징 판정 기준** — 메뉴가 한 번 열리면 "메뉴 중" 상태가 끝까지 꺼지지 않아, 게임 플레이 중에도 프리징을 메뉴 기준(`HangThresholdInMenuSec`, 기본 30초)으로 판정하던 첫 버전부터의 버그를 고쳤습니다. 이제 게임 플레이 중에는 `HangThresholdInGameSec`(기본 10초)가 적용됩니다.
- **플러그인 오류 대화상자 프리징(`modal_dialog_wait`)** — 메인 스레드가 플러그인이 띄운 MessageBox·DialogBox·TaskDialog에서 기다리면 그렇게 분류하고, 대화상자 제목·본문과 그 창을 연 모듈을 보여 줍니다. 스택에 우연히 남은 무관한 모듈은 원인으로 지목하지 않습니다.
- **실제 호출 체인 복원** — 정식 stackwalk가 처음부터 1프레임에서 멈추던 버그를 고쳤습니다. 덤프에 없는 unwind 정보는 같은 버전의 로컬 파일에서만 읽고, 코드가 아닌 주소는 프레임으로 넣지 않으며, PDB 없는 DLL은 `모듈+오프셋`으로 표시합니다.
- **Crash Logger와 함께 쓸 때** — 모드의 assert나 처리되지 않은 C++ 예외를 Crash Logger가 보고하는 동안 Crash Logger가 스스로 잡는 메모리 조사 예외가 크래시로 기록되던 문제를 고쳤습니다. 원래 예외를 기록하고, Crash Logger의 스레드 덤프(`Ctrl+Shift+F12`) 중에는 아무것도 기록하지 않습니다.
- **플러그인 스캔** — 크래시 후 스캔이 게임 종료 뒤에 실행되어 항상 건너뛰어지던 문제와, MO2 + Anniversary Edition에서 `Skyrim.ccc`의 Creation Club 파일이 모두 누락 마스터로 잘못 판정되던 문제를 고쳤습니다.

## WinUI / 사용성
- 리포트가 hang·수동 캡처까지 Windows 표시 언어를 따릅니다. 이전에는 CTD 리포트만 한국어, hang 리포트는 항상 영어였습니다.
- 게임 본체(EXE) 크래시는 플러그인 데이터, 버전 불일치, DLL 훅을 모두 가능성으로 안내하고, 다른 단서가 없으면 신뢰도 낮음으로 표시합니다.
- 예외 위치가 Crash Logger 안이면 2차 예외로 해석하도록 안내하고, 브레이크포인트(`0x80000003`) 예외는 모드의 assert/abort 가능성을 설명합니다.
- 신뢰도 낮은 플러그인 규칙(예: ESL 슬롯 한계 근접)은 체크리스트 끝으로 보내 다음 조치를 차지하지 않습니다.
- modal 대기로 판정되면 다음 조치가 "게임 창 뒤의 오류 창 확인"으로 바뀌고 캡처된 대화상자 본문이 표시됩니다.
- README와 Nexus 설명에 MO2에서 결과가 생기지 않을 때의 확인 방법, Linux(Wine/Proton) 지원 범위, Crash Logger와 겹치는 단축키를 적었습니다.

## 엔진 변경
- Helper: 게임 플레이 중에도 `Ctrl+Shift+F12`를 잡도록 20ms 키 상태 감시를 추가했습니다(`WM_HOTKEY`와 함께 동작, 한 번 누르면 캡처 한 번).
- Helper: 크래시 후 플러그인 스캔 입력을 덤프 직후 게임이 살아 있을 때 읽고, 게임이 스스로 읽는 기본 마스터와 `Skyrim.ccc` 파일을 스캔에 포함합니다(`implicit_plugins_included`).
- Helper: 기록된 크래시 없이 비정상 종료되면 WER 힌트가 "캡처 실패"가 아니라 종료 코드와 플러그인 오류 창 가능성을 안내합니다.
- Helper: 덤프가 실패하면 마지막 처리 단계와 읽지 못한 메모리 위치를 로그에 남기고, 읽지 못한 메모리 영역은 빼고 덤프를 계속 씁니다.
- Helper: Wine을 감지하면 뷰어 자동 열기를 끄고 모든 캡처에 `*_SkyrimDiagReport.txt`를 만듭니다(`AutoOpenViewerUnderWine=0` 기본).
- 플러그인: "메뉴 중" 상태를 게임을 멈추는 메뉴, 모달 창, 앱 메뉴, 아이템 메뉴가 실제로 열려 있을 때만 켭니다. 이전에는 HUD 표시 여부(`UI::IsShowingMenus()`)로 끄려 해서 플레이 중에 꺼지지 않았고, TrueHUD 같은 HUD형 메뉴도 상태를 켰습니다. 메뉴 이벤트와 100ms마다 도는 Heartbeat에서 다시 계산합니다.
- 플러그인: 기록하지 않은 브레이크포인트·C++ 예외를 보관했다가 Crash Logger가 같은 스레드에서 보고할 때 그것을 기록하고, Crash Logger 자신의 예외는 기록하지 않습니다.
- 분석기: crash bucket을 v3(`CTD3-`)로 올렸습니다. `--lang` 없이 실행하면 Windows 표시 언어를 씁니다.

## 실게임에서 확인한 것
- rc2~rc7을 한 사용자의 MO2 환경(게임 1.6.1170, 플러그인 약 4,250개)에서 실제로 플레이하며 확인했습니다.
- 확인됨: `modal_dialog_wait`(SmoothCam 오류 창, 신뢰도 High), 크래시 후 플러그인 스캔, Creation Club 누락 마스터 0개, Crash Logger 스레드 덤프 중 크래시 이벤트 없음, 실사고 덤프 재분석에서의 리포트 언어와 게임 본체 크래시 안내.
- 확인됨(rc6·rc7): 게임 플레이 중 `Ctrl+Shift+F12` 수동 캡처(키 상태 감시와 `WM_HOTKEY` 두 경로 모두, 키 한 번에 캡처 한 번), 프리징 판정 기준(메뉴를 닫은 플레이 중 `inMenu=0`·10초, 인벤토리 `inMenu=1`·30초), 세이브 불러오기·저장·종료 때 프리징 캡처 없음.
- 실게임 미확인: Crash Logger가 보고한 assert의 원래 예외 기록(같은 순서를 재현하는 런타임 테스트로만 확인), 덤프 실패 위치 진단(실패가 재현되지 않음).

## 정정
- rc5 노트의 "`ERROR_PARTIAL_COPY`로 실패하면 읽을 수 없는 메모리를 건너뛰고 다시 써서 CTD 덤프를 놓치지 않도록 했다"는 설명은 맞지 않았습니다. 이 재시도가 들어간 뒤에도 CI에서 같은 실패가 났습니다. 원인은 아직 모르며, 로컬 100회와 CI 러너 단독 400회 반복에서는 재현되지 않았고 전체 CI 실행 안에서만 간헐적으로 납니다.

## 주의사항
- 플러그인, Helper, 분석기, WinUI 런처가 모두 바뀌었습니다. ZIP 전체를 교체해 주세요. 공유 메모리 프로토콜(SharedLayout v4)은 v0.2.58과 같습니다.
- 게임 플레이 중 프리징 판정 기준이 실제로 30초에서 설정값(기본 10초)으로 바뀝니다. 10~30초 멈췄다가 풀리는 프리징이 이제 잡히며, 정상적인 긴 멈춤이 프리징으로 기록되면 `SkyrimDiagHelper.ini`의 `HangThresholdInGameSec`로 조정할 수 있습니다.
- 이전 버전 캡처의 `in_menu: true`와 Helper 로그의 `inMenu=1`은 위 버그 때문에 실제 메뉴 상태와 다를 수 있습니다.
- 새 `CTD3-` 버킷은 기존 `CTD2-` 이력과 자동으로 합쳐지지 않습니다.
- stackwalk는 덤프의 모듈과 같은 버전의 파일이 분석하는 PC에 있어야 그 모듈을 지나 내려갑니다. 다른 PC에서 분석한 덤프는 해당 모듈에서 멈출 수 있습니다.
- Crash Logger 1.25도 `Ctrl+Shift+F12`를 스레드 덤프 단축키로 써서, 둘 다 설치되어 있으면 한 번 누를 때 두 결과가 함께 생깁니다.
- Crash Logger가 SkyrimDiag가 기록하거나 보관하지 않는 드문 예외를 보고하면 SkyrimDiag 덤프가 남지 않습니다(Crash Logger 로그는 남음).
- Wine에서는 WCT 대기 체인과 modal 대화상자의 스택 근거를 쓸 수 없고, WinUI 뷰어는 동작하지 않습니다.
- 검수된 실사고 코퍼스가 없어 다른 크래시 로거 대비 적중률을 수치로 주장하지 않습니다.
