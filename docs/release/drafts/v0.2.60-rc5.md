# v0.2.60-rc5 — 프리징 리포트가 메인 스레드의 대기를 설명

멈춘 메인 스레드가 무엇을 기다리고 있었는지와 캡처 당시 게임 상태를 프리징 리포트에 담은 테스트용 프리릴리즈입니다. 정식 릴리즈 전에 rc1~rc4 전체를 다시 검수하고 찾은 문제도 고쳤습니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- 프리징 리포트가 메인 스레드의 상태를 말합니다: 게임 엔진 안의 대기, 플러그인이 부른 대기, 그래픽 드라이버 안의 대기, 코드 실행 중.
- 보관 중인 실사고 프리징 5건은 모두 GPU를 기다리던 중이었습니다. 4건은 엔진이 Direct3D 쿼리 결과를 `Sleep` 루프로 기다렸고, 1건은 NVIDIA 드라이버 안에서 기다렸습니다. 이전 리포트는 4건에서 CommunityShaders를, 1건에서 FSMP를 근거 없이 후보로 올렸습니다. 이제는 후보를 올리지 않고 GPU 쪽 점검(드라이버, 감지된 ENB·ReShade, 업스케일러, 비디오 메모리)을 다음 조치로 안내합니다.
- 캡처 당시 열려 있던 메뉴(예: 콘솔), 마지막 로딩 뒤 지난 시간, 직전의 긴 정지(PC 절전이나 최소화로 추정)를 함께 적습니다.
- WinUI 화면과 공유 텍스트의 "다음 조치"가 리포트의 `NextAction`과 같은 줄을 씁니다.

## 엔진 변경
- 분석기: 프리징 캡처에서 메인 스레드 스택 맨 위의 대기 API와 그것을 부른 모듈로 대기를 분류합니다(`engine_wait`, `plugin_wait`, `graphics_driver_wait`, `running`, `unknown`).
- 분석기: 엔진 대기를 부른 코드가 `GetData` 가상 호출, 결과 검사, `Sleep` 호출 모양이면 GPU 쿼리 대기(`gpu_query_poll`)로 봅니다. 코드는 덤프 메모리에서만 읽고, 주소가 아니라 코드 모양으로 판별해 게임 버전에 묶이지 않습니다.
- 분석기: 엔진·드라이버 대기에서는 메인 스레드 스택의 플러그인으로 후보를 만들지 않고 `Low`·호출 경로로 표시합니다. 데드락, 동기화 정지, 로더 stall 판정과 그 안내가 여전히 먼저입니다.
- 분석기: 블랙박스의 메뉴 열기/닫기, 마지막 로딩, 5분 이상의 정지로 캡처 당시 게임 상태를 만들고, 시간은 메인 스레드의 마지막 하트비트까지 잽니다.
- 분석기: 프리징 캡처의 메인 스레드 콜스택을 0번 프레임부터 16개 보여 줍니다. 크래시 콜스택과 crash bucket 키는 그대로입니다.
- 분석기: 요약 JSON `freeze_analysis.main_thread_wait`, `freeze_analysis.game_state`와 리포트 `main_thread_wait`, `game_state` 줄을 추가했습니다.
- 분석기: `[SKSE]` 안내를 "정상적으로 로드하지 못한 DLL"로 바꾸고, 필요한 DLL이 없는 경우와 버전 정보가 없는 보조 DLL에도 맞게 고쳤습니다.
- WinUI: 요약 JSON의 `next_action_index`를 따르고, 이 값이 없는 예전 요약만 기존 방식으로 고릅니다.
- Helper: CTD 덤프의 확장 상태 컨텍스트 복사를 보강했고, 보관 정리와 SKSE 로그 읽기가 예외로 멈추지 않게 했습니다.
- CI: 문서만 바꾼 PR은 Windows job을 건너뜁니다(main 푸시와 릴리즈는 항상 전체 실행).

## 테스트 시 확인할 점
- 게임을 켜고 수동 캡처(`Ctrl+Shift+F12`)를 한 번 해 주세요. 리포트가 평소처럼 나오고, "캡처 당시 게임 상태" 근거 항목에 마지막 로딩 뒤 지난 시간이 실제와 비슷하게 나오면 됩니다.
- 프리징이 나면 자동 캡처된 리포트의 결론과 `NextAction:`을 확인해 주세요. 메인 스레드가 무엇을 기다렸는지와 그에 맞는 안내가 나와야 합니다.
- WinUI에서 리포트를 열어 "다음 조치"가 리포트의 `NextAction:`과 같은지 봐 주세요.
- 아직 실게임에서 확인하지 못한 항목: 새 프리징 분석(보관 덤프 재분석으로만 확인), 모드의 assert로 난 CTD에서 `ExceptionCode`가 `0x80000003`인지, 덤프 실패 시 실패 위치 진단, Address Library 오류 창 안내(보관 덤프 재분석으로만 확인), AMX CPU에서의 CTD 덤프(CI에서만 확인).

## 주의사항
- Helper, 분석기, WinUI가 바뀌었습니다. ZIP 전체를 교체해 주세요.
- GPU를 기다렸다는 것까지만 알려 주고, GPU가 왜 끝내지 못했는지(어느 셰이더나 그리기 작업인지)는 덤프로 알 수 없습니다.
- 게임 EXE가 플러그인이 잡은 잠금에서 기다리는 경우도 "엔진 안의 대기"로 분류될 수 있습니다. 이때 스레드 그룹 합의가 없으면 그 플러그인은 후보에서 빠집니다.
- 한국어 리포트의 일부 후보 안내 문장에는 아직 영어 용어가 섞여 있습니다.
- 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
