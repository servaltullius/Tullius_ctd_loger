# v0.2.59-rc2 — modal 대화상자 프리징 분류와 실제 콜스택 복원

실제 Skyrim 환경에서 확인하기 위한 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- 플러그인이 띄운 오류 대화상자 때문에 게임이 멈추면 `modal_dialog_wait` 상태로 분류합니다. 스택에 우연히 남은 무관한 플러그인을 원인으로 지목하지 않고, 대화상자 제목·본문과 그 대화상자를 연 모듈을 보여 줍니다(#3).
- 정식 stackwalk가 처음부터 항상 1프레임에서 멈추던 버그를 고쳤습니다. CTD와 프리징 리포트에 실제 호출 체인이 나타나며, 프리징은 게임 메인 스레드(와 WCT cycle 스레드) 기준으로만 판단합니다.
- Linux(Wine/Proton)에서는 동작하지 않는 WinUI 뷰어를 기다리지 않고, 모든 캡처에 `*_SkyrimDiagReport.txt`를 남깁니다(#5).

## WinUI / 사용성
- modal 대기로 판정되면 WinUI의 다음 행동 안내가 "게임 창 뒤의 대화상자를 찾아 내용을 확인"으로 바뀌고, 권장 조치에 캡처된 대화상자 본문이 표시됩니다.
- Wine에서 `SkyrimDiagDumpToolWinUI.exe`를 실행하면 뷰어를 지원하지 않는 이유를 안내합니다. 덤프를 넘기면 함께 배포된 CLI로 리포트를 만든 뒤 열지 묻습니다.
- MO2에서 사고 후 결과가 생기지 않을 때의 확인 방법과 실제 폴더 배치 우회법(#4), Linux 지원 범위를 README와 Nexus 설명에 추가했습니다.

## 엔진 변경
- Helper가 hang 캡처 시 대상 프로세스의 보이는 대화상자(MessageBox, DialogBox, TaskDialog)를 WCT JSON의 `modal_dialogs`에 기록합니다. 대상에 메시지를 보내지 않아 멈춘 게임이 Helper를 막지 못합니다.
- stackwalk는 덤프에 없는 모듈 메모리와 unwind 정보를 로컬 파일에서 읽되, 파일의 `TimeDateStamp`와 `SizeOfImage`가 덤프와 같을 때만 사용합니다. unwind 정보가 없으면 스택 슬롯을 추측하지 않고 멈춥니다.
- 버킷 입력 프레임이 달라져 crash bucket을 v3(`CTD3-`)로 올렸습니다. "stackwalk 실패" 진단은 실제로 호출자 프레임을 얻지 못한 경우에만 남깁니다.
- 새 설정 `AutoOpenViewerUnderWine=0`(기본): Wine에서 뷰어 자동 열기를 끄는 동작을 원하면 끌 수 있습니다. Windows 동작은 바뀌지 않습니다.

## 빌드 / 운영
- 분석기 DLL과 CLI가 같은 `data` 폴더로 동시에 복사하다 빌드가 실패하던 경쟁 조건을 고쳤습니다.
- CI가 PR 브랜치를 한 번만 검증하고, 같은 PR에 새로 푸시하면 이전 실행을 취소합니다.
- MessageBox를 닫지 못해 멈추던 테스트와, 초기화 중인 프로세스를 덤프해 간헐 실패하던 테스트를 안정화했습니다.

## 테스트 시 확인할 점
- 플러그인 오류 대화상자가 뜬 채 게임이 멈추는 상황(예: 선행 모드나 Address Library가 빠진 SKSE 플러그인)에서 리포트가 `modal_dialog_wait`로 분류되고 대화상자 내용이 표시되는지 확인해 주세요.
- CTD 리포트의 콜스택이 여러 프레임으로 나오는지, `0x`로 시작하는 모듈 밖 주소가 섞이지 않는지 확인해 주세요.
- Linux/Proton 사용자는 사고 후 출력 폴더에 `*_SkyrimDiagReport.txt`가 생기는지, `SkyrimDiagHelper.log`에 `Wine/Proton detected` 줄이 있는지 확인해 주세요.
- 문제가 생기면 덤프, 리포트, `SkyrimDiagHelper.log`를 함께 보관해 주세요.

## 주의사항
- 새 `CTD3-` 버킷은 기존 `CTD2-` history 그룹과 자동으로 합쳐지지 않습니다.
- stackwalk는 덤프의 모듈과 같은 버전의 파일이 분석하는 PC에 있어야 그 모듈을 지나 내려갑니다. 삭제·업데이트된 모드나 다른 PC에서 분석한 덤프는 해당 모듈에서 멈추고, modal 판정도 창 근거만 남을 수 있습니다.
- 후킹 체인(D3D 초기화 훅 등)에 놓인 다른 DLL도 호출자로 보일 수 있습니다. 점수 정책은 바꾸지 않아 이런 DLL은 `Low` 보조 후보로만 남습니다.
- 이번 동작 변경은 한 사용자 PC의 실사고 덤프 7개로 회귀만 확인했으며 정확도 측정이 아닙니다. 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
- Wine에서는 WCT 대기 체인과 modal 대화상자의 스택 근거를 쓸 수 없습니다. Helper의 Wine 감지는 실제 Proton 게임 세션에서 확인하지 못했습니다.
- 플러그인과 공유 메모리 프로토콜(SharedLayout v4)은 rc1과 같지만, Helper·분석기·WinUI 런처가 함께 바뀌었으므로 ZIP 전체를 교체해 주세요.
