# v0.2.62 — Skyrim 1.7.104 지원과 게임 함수 이름

Skyrim 1.7.104(2026-08-27 Steam 업데이트)에서 SkyrimDiag.dll 오류 창이 뜨며 로드되지 않던 문제를 고쳤습니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- **Skyrim 1.7.104 지원** — v0.2.61은 1.7.104에서 오류 창이 뜨고 로드되지 않았습니다. 원인은 두 가지입니다.
  - SKSE 2.3.x가 요구하는 "Address Library v5 호환" 표시가 플러그인에 없었습니다.
  - 1.7.x용 Address Library 파일(형식 5)을 읽지 못했습니다.
  
  플러그인이 쓰는 CommonLibSSE-NG를 3.5.3에서 v12.1.0으로 올려 둘 다 해결했습니다. 1.7.104에서는 SKSE 2.3.1과 Address Library v13(All in One)이 필요합니다. 1.6.1170, 1.6.640, 1.5.97은 이전처럼 지원합니다.
- **콜스택의 게임 함수 이름** — 게임 EXE 프레임에 함수 이름을 붙입니다. 예: `SkyrimSE.exe+0x2ea36b (TESObjectREFR::GetDisplayFullName+0x2b)`. 근거 항목 "게임 함수 식별"은 예외가 난 함수를 정확히 적고, 원인은 대개 그 함수를 잘못된 데이터로 부른 모드라고 안내합니다.
  - 지원 버전: 1.7.104, 1.6.1170, 1.6.640, 1.5.97(각 730~734개).
  - 프레임이 속한 함수의 시작 주소가 정확히 맞을 때만 이름을 붙입니다. 이전에는 주소가 0x100 안쪽이면 가까운 이름을 붙였고, 1.6.1170·1.7.104 항목은 없었습니다.
- **분석 캐시 정리** — 덤프를 지운 뒤에도 남던 분석 사본(`.skydiag-analysis`)과 잠금 파일(`.skydiag-locks`)을 Helper가 하루 뒤 지웁니다. 남은 덤프의 사본과 검토 기록(`.skydiag-triage`)은 건드리지 않습니다.
- **라이선스: GPL-3.0-or-later** — CommonLibSSE-NG v12가 GPL-3.0이라 프로젝트 전체를 GPL-3.0-or-later로 정했습니다. ZIP에 `SKSE/Plugins/SkyrimDiag-LICENSE.txt`(고지와 라이선스 전문)를 넣었습니다.

## 엔진 변경
- 플러그인: CommonLibSSE-NG v12.1.0을 저장소의 submodule로 넣고 SE·AE용으로 소스에서 빌드합니다.
  - VR은 지원 대상이 아니어서 빌드에서 뺐습니다.
  - spdlog·fmt는 정적 라이브러리로 들어가서, `SkyrimDiag.dll` 말고 따로 필요한 DLL은 없습니다.
- 분석기: 게임 함수 이름표는 MIT 라이선스였던 CommonLibSSE-NG 리비전(`e342462`)에서 이름을 가져옵니다.
  - Address Library로 버전별 주소를 구한 뒤, 1.6.1170과 1.7.104의 실제 실행 파일에서 둘 다 함수 시작인 이름만 남깁니다(ADR-0014).
  - 프레임이 속한 함수의 시작은 덤프나 로컬 이미지의 `.pdata`로 찾습니다. 조각난 함수(chained 항목)도 원래 함수까지 따라갑니다.
- 개발
  - 외부 GitHub Action을 커밋으로 고정했고, vcpkg를 manifest baseline 커밋으로 받습니다.
  - CI job마다 시간 제한을 걸었습니다.
  - clang-tidy를 C++23에 맞췄습니다.

## 실게임에서 확인한 것
- **1.6.1170**: 한 사용자의 MO2 환경(SKSE 2.2.6, 플러그인 약 4,250개)에서 새 플러그인 DLL로 실행했습니다.
  - SKSE 로그 `loaded correctly`, Helper 연결, 하트비트
  - 수동 캡처: 덤프, 리포트, 메뉴·로딩 이벤트, `open_menus=Main Menu`, 메모리·GPU 줄
- **1.7.104**: 같은 PC의 Steam 설치(모드 없음, SKSE 2.3.1, Address Library v13)에서 실행했습니다.
  - 새 빌드 일체로 SKSE 로그 `loaded correctly`
  - 수동 캡처로 1.6.1170과 같은 항목을 확인했습니다.
  - 배포된 v0.2.61 DLL은 Address Library v5 표시가 없는 것(`versionIndependenceEx=0x1`, 새 빌드는 `0x3`)까지만 확인했습니다. 1.7.104에서 실제로 실행해 보지는 않았습니다.
- **게임 함수 이름(보관 덤프 재분석)**: 크래시 테스트의 게임 EXE 내부 CTD에서 `BSReadWriteLock::LockForRead+0xf`, `TESObjectREFR::GetDisplayFullName+0x2b`가 붙었고, Crash Logger의 `68233+0xF`, `19781+0x2B`와 일치합니다.
- **실게임 미확인**
  - 1.7.104에서의 실제 CTD·프리징 캡처(수동 캡처만 확인)와 모드가 많은 1.7.104 환경
  - 1.7.104 메인 메뉴 이후의 리소스 열기 기록
  - 1.5.97·1.6.640 실게임
  - 실사용 폴더에서 분석 캐시 정리 동작(테스트와 계산으로만 확인)

## 주의사항
- 1.7.104 사용자는 SKSE 2.3.1과 Address Library v13(All in One)으로 먼저 업데이트해야 합니다. v0.2.61 이하의 플러그인은 1.7.104에서 로드되지 않습니다.
- 공유 메모리 프로토콜(SharedLayout v4)은 같지만 플러그인, Helper, 분석기, 뷰어가 모두 바뀌었습니다. ZIP 전체를 교체해 주세요.
- 게임 함수 이름은 CommonLibSSE-NG가 아는 함수(모드가 자주 부르는 엔진 함수) 위주입니다. 실사고 CTD의 깊은 엔진 프레임은 대부분 이름 없이 주소로만 나옵니다. 보관 중인 실사고 CTD 1건에서는 게임 프레임 12개 중 0개에 이름이 붙었습니다.
- 게임 함수 이름은 후보, 버킷, 이력에 쓰지 않습니다. 게임 함수는 터진 위치일 뿐 원인이 아니기 때문입니다.
- 검수된 실사고 코퍼스가 없어 다른 크래시 로거 대비 적중률을 수치로 주장하지 않습니다.
