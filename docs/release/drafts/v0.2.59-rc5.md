# v0.2.59-rc5 — Crash Logger 스레드 덤프 단축키 오탐 수정

rc4 실게임 수동 캡처에서 찾은 문제를 고친 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- Crash Logger 1.25는 수동 캡처와 같은 `Ctrl+Shift+F12`로 스레드 덤프를 만듭니다. 그 과정에서 Crash Logger가 스스로 잡는 접근 위반을 SkyrimDiag가 크래시로 기록해, 키를 한 번 누를 때마다 전체 크래시 덤프를 여러 번 쓰고 지우는 동안 게임이 멈췄습니다. 이제 Crash Logger 자신의 예외는 크래시로 기록하지 않습니다.
- hang 리포트가 Windows 표시 언어를 따릅니다. 지금까지는 CTD 리포트는 한국어, hang 리포트는 항상 영어였습니다.
- 플러그인이 오류 창을 띄우고 게임을 끝낸 경우, WER 힌트 파일이 더 이상 "덤프 캡처 실패"라고 적지 않고 종료 코드와 함께 그런 가능성을 먼저 안내합니다.
- 덤프가 `ERROR_PARTIAL_COPY`(메모리 일부를 읽지 못함)로 실패하면, 읽을 수 없는 메모리를 건너뛰고 한 번 더 써서 CTD 덤프를 놓치지 않도록 했습니다.

## WinUI / 사용성
- README와 Nexus 설명의 수동 스냅샷 단축키 안내에, Crash Logger 1.25도 같은 키로 스레드 덤프를 만든다는 점을 적었습니다. 둘 다 설치되어 있으면 한 번 누를 때 Crash Logger의 `threaddump-*.log`도 함께 생깁니다.

## 엔진 변경
- 플러그인: Crash Logger 범위 안의 치명 코드 예외는, 같은 스레드에 최근 보관한 예외(assert 브레이크포인트·C++ 예외)가 있고 아직 기록된 것이 없을 때만 그 보관한 예외를 기록하는 데 쓰고, 그 밖에는 무시합니다.
- 분석기 CLI: `--lang`이 없으면 Windows 표시 언어(`GetUserDefaultUILanguage`)로 리포트 언어를 정합니다. 뷰어의 규칙과 같습니다.
- Helper: WER 힌트를 "크래시는 기록했지만 덤프 쓰기 실패"와 "기록된 크래시 없는 비정상 종료"로 나눠 씁니다.
- Helper: `MiniDumpWriteDump`가 `ERROR_PARTIAL_COPY`(HRESULT `0x8007012B`)로 실패하면 곧바로 `MiniDumpIgnoreInaccessibleMemory`를 더해 한 번 더 씁니다. 첫 시도의 덤프 형식은 그대로입니다.

## 테스트 시 확인할 점
- 게임 안에서 `Ctrl+Shift+F12`를 한 번 눌러 주세요. 출력 폴더에 `*_Manual_*` 캡처가 생기고, `SkyrimDiagHelper.log`에 `Crash event signaled` 줄이 생기지 않아야 합니다. Crash Logger를 쓰고 있다면 SKSE 로그 폴더의 `threaddump-*.log`도 함께 생깁니다.
- 수동 캡처와 hang 리포트(`*_SkyrimDiagReport.txt`)가 Windows 표시 언어(한국어 환경이면 한국어)로 나오는지 확인해 주세요.
- 수동 캡처 리포트에 `누락 마스터`나 `MISSING_MASTER`가 없고, 콜스택에 `SKSEPlugin_Load+0x...`처럼 먼 함수 이름이 붙지 않는지도 계속 봐 주세요.
- 모드의 assert로 난 CTD(Crash Logger 로그 맨 위가 `EXCEPTION_BREAKPOINT`)에서 리포트의 `ExceptionCode`가 `0x80000003`이고 `Module+Offset`이 `CrashLogger.dll`이 아닌지 확인해 주세요. 이 수정(rc3)은 아직 실게임에서 확인되지 않았습니다.

## 주의사항
- 플러그인(`SkyrimDiag.dll`), Helper, 분석기가 바뀌었습니다. ZIP 전체를 교체해 주세요.
- Crash Logger가 SkyrimDiag가 기록하거나 보관하지 않는 드문 예외(예: 처리되지 않은 `0xC0000008`)를 보고하면, 이전과 달리 SkyrimDiag 덤프가 남지 않습니다. 그 덤프는 원인 위치가 Crash Logger로 잘못 찍힌 것이었고, Crash Logger 로그는 그대로 남습니다.
- `ERROR_PARTIAL_COPY`의 원인은 아직 찾지 못했고 로컬에서 재현하지 못했습니다. 재시도는 플래그의 문서화된 동작에 기대며, 재시도로 남은 덤프는 읽지 못한 메모리 영역이 빠져 있을 수 있습니다.
- 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
