# v0.2.66-rc2 — 다른 크래시의 Crash Logger 로그 거르기, 분석 시점 MO2 제공 모드 제외

외부 리뷰에서 나온 진단 정확도 문제 두 가지를 고친 테스트용 프리릴리즈입니다. 분석기만 바뀌었고 Helper와 플러그인 동작은 rc1과 같습니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- 덤프와 Crash Logger 로그의 예외 위치가 다르면, 그 로그는 다른 크래시의 것일 수 있어 단서를 낮게 평가합니다. 로그를 남기지 못한 크래시(스택 오버플로 등)에 직전 크래시의 로그가 붙어 엉뚱한 모드가 후보로 올라가던 경우를 막습니다.
- 크래시 당시 MO2 프로필 정보가 없는 덤프에서는, 분석 시점 프로필에서 찾은 리소스 제공 모드를 후보 판단에 쓰지 않습니다(rc1 F05 보완).

## 엔진 변경
- 분석기: 로그의 예외 위치(`모듈+오프셋`)가 덤프의 예외 모듈·오프셋과 다르면 짝짓기를 모호함으로 처리합니다. 로그는 낮은 신뢰도로 보여 주고, 스택 후보 순서를 바꾸지 않으며, 후보 신호 가중치를 3 이하로 제한합니다. 덤프의 예외가 Crash Logger 안에서 난 2차 예외이거나 한쪽에 위치가 없으면 비교하지 않습니다. 요약 JSON에 `crash_logger.pairing.location_mismatch`를 적습니다.
- 분석기: `mo2.providers_source`가 `analysis_time`이면 리소스 제공 모드를 후보 신호에서 뺍니다. 리소스 근거 항목에는 rc1처럼 주의 문구와 함께 남습니다.

## 테스트 시 확인할 점
- rc1에서 부탁드린 확인(MO2 프로필 캡처, SKSE 로그 시각 확인, 리포트의 "providers: 크래시 당시의 MO2 프로필 기준")은 rc2로 해도 같습니다.
- Crash Logger를 쓰신다면, 실제 크래시 리포트의 "Crash Logger 쌍짓기" 줄이 `location_mismatch=0`인지 봐 주세요. 같은 크래시의 로그인데 1로 나오면 알려 주세요.

## 주의사항
- 분석기만 바뀌었습니다. 이미 찍어 둔 덤프도 다시 분석하면 새 판단이 적용됩니다.
- 짝짓기 판단은 Crash Logger 로그의 "Unhandled exception" 줄에 적힌 위치를 씁니다. 위치를 적지 않는 버전이나 형식에서는 지금처럼 시각만으로 짝을 짓습니다.
- 비ASCII 리소스 경로(감사 F16)는 아직 고치지 않았습니다.

## 검증
- Windows test suite: `93/93` 통과
- 실제 크래시 덤프 14개 재분석: Crash Logger 로그가 짝지어진 12개 모두 `location_mismatch=false`(Crash Logger 안에서 난 2차 예외 1건 포함)
- 재현: 스택 오버플로로 로그가 없던 덤프 옆에 40초 전 다른 크래시의 로그를 두고 분석 — rc1은 짝짓기 신뢰도 중간, 후보 점수 13 / rc2는 `location_mismatch=true`, 신뢰도 낮음, 후보 점수 8
- 분석 시점 제공 모드 제외: 수정 전 코드에서 실패하고 수정 후 통과하는 런타임 테스트 추가
- Windows production clang-tidy: 변경 파일 clean
