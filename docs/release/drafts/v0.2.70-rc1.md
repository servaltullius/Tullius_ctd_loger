# v0.2.70-rc1 — 수정 모드가 있는 알려진 크래시 5종, 크래시 명령어 쉬운 말 설명, 권고 분류 정리

v0.2.69 이후 알려진 크래시를 늘리고, 접근 위반 크래시에서 게임이 무엇을 하다 튕겼는지 설명하는 테스트용 프리릴리즈입니다. 분석기와 뷰어, Helper가 바뀌었습니다.

## 한눈에 보기
- **수정 모드가 있는 1.6.1170 크래시 5종을 알아봅니다.** 크래시 지점이 아래와 같으면 빠른 답이 "알려진 키보드 입력 크래시와 일치합니다"처럼 시작하고 그 수정 모드 설치를 안내합니다. 수정 모드가 이미 로드된 채로 같은 크래시가 났으면 새 버전 확인이나 제작자에게 알리기를 안내합니다(키보드, 물 충돌).
  - 키보드 입력 크래시(`SkyrimSE.exe+0xCDE0AE`): [Keyboard Offset Crash Fix SE-AE](https://www.nexusmods.com/skyrimspecialedition/mods/187246)
  - 물리 엔진(Havok) 계산 크래시 2곳과 정리 크래시 3곳: [Havok Solver Crash Fix - SKSE](https://www.nexusmods.com/skyrimspecialedition/mods/194392)
  - 물 충돌 크래시(`SkyrimSE.exe+0x51E220`, `+0x51E253`): [Water Collision Crash Fix NG](https://www.nexusmods.com/skyrimspecialedition/mods/190886)
- **접근 위반 크래시에서 게임이 무엇을 하다 튕겼는지 쉬운 말로 알려 줍니다.** 빠른 답에 "어떻게 튕겼나: 이미 사라졌거나 만들어진 적 없는 오브젝트를 쓰다가 튕겼습니다(null 포인터)." 같은 줄이 생기고, 자세한 분석에는 "SmoothCam.dll+0x15fcc의 명령어(cmp)가 [r8+r9*8]에서 8바이트를 읽으려 했는데 … 인덱스(r9)가 범위를 벗어났거나 포인터가 잘못됐을 가능성이 큽니다"처럼 적습니다. 덤프에 담긴 크래시 명령어를 읽고, 레지스터로 다시 계산한 주소가 예외 기록과 맞을 때만 레지스터를 짚습니다. 모르는 명령어면 아무것도 적지 않습니다.
- **v0.2.69 이전에 분석한 덤프도 뷰어에서 빠른 답이 나옵니다.** 빠른 답이 없는 예전 분석 결과는 자동으로 다시 분석합니다.

## 수정
**분석기**
- 알려진 크래시: `crash_signatures.json`에 1.6.1170 크래시 지점 8곳(5종)을 추가했습니다(20개 → 25개). 오프셋은 각 수정 모드 제작자가 공개한 1.6.1170 샘플이고, 명령어는 1.6.1170 덤프 안의 게임 코드와 대조해 모두 맞았습니다. 수정 모드가 그 지점의 엔진 결함을 직접 막으므로 알려진 원인(`root_cause`)으로 다룹니다. 다른 게임 버전과 오프셋에는 걸리지 않습니다.
- 크래시 명령어: 접근 위반이면 예외 위치의 명령어를 해석해 읽기/쓰기/실행, 크기, 주소식을 구하고, 레지스터 값으로 다시 계산한 주소가 예외 기록의 주소와 맞는지 확인합니다. 맞으면 "rax가 0이었습니다: 이미 사라졌거나 만들어지지 않은 객체(널 포인터)"처럼 원인을 적고, 맞지 않으면 읽기/쓰기와 주소만 적습니다. 근거 목록, 리포트 `예외 명령어:` 줄, Summary JSON `fault_instruction`에 들어가고, 쉬운 말 한 문장이 빠른 답의 "어떻게 튕겼나" 줄(`quick_answer.how_it_crashed`)로 나옵니다. 판정은 null 포인터, 해제됐거나 망가진 포인터, 잘못된 인덱스, 덮어써진 포인터(메모리 손상), 정렬 안 된 SSE 주소, 망가진 스택, 코드가 아닌 곳으로의 호출입니다. 원인 모드 지목, 신뢰도, 알려진 크래시 판정, 버킷은 바뀌지 않습니다. Crash Logger 안에서 난 크래시는 Crash Logger가 메모리를 조사하다 생긴 부작용으로 보고 설명을 붙이지 않습니다.
- 권고 분류: 권고마다 분류(`immediate`/`verify`/`recapture`)를 Summary JSON `recommendation_classes`에 함께 기록합니다. 기존 `recommendations` 배열은 그대로입니다.
- 경로 가리기: 경로 마스킹이 켜져 있으면(기본값) Crash Logger C++ 예외 메시지, 오류 창 내용, 이를 인용한 근거·권고 문장, WCT 사본 안의 절대 경로도 마지막 이름만 남기고 가립니다. 값이 사용자 프로필 폴더 자체면 `<redacted>\<user>`로 가립니다.
- 덤프의 WCT 값과 `crash_history.json` 값이 비정상적으로 길어도 분석기가 강제 종료되지 않습니다.

**뷰어**
- 권고를 "지금 바로 / 추가 확인 / 재수집 / 비교"로 묶을 때 표시 문구 대신 분석기가 적은 분류를 씁니다. 예전 요약은 이전처럼 문구로 묶습니다.
- "[프리징] … 다시 캡처" 권고가 영어 화면에서만 "추가 확인"으로 묶이던 문제를 고쳤습니다. 이제 한국어처럼 "재수집 / 비교"에 나옵니다.
- 빠른 답 카드와 요약 복사·공유 텍스트에 "어떻게 튕겼나" 줄을 보여 줍니다.
- 빠른 답 카드의 줄을 항목마다 따로 채웁니다. 지금까지는 "해볼 일"이 없는 답에서 다음 줄이 엉뚱한 칸에 들어갈 수 있었습니다.
- 빠른 답이 없는 예전 분석 결과를 불러오지 않고 덤프를 다시 분석합니다.

**Helper**
- 프리플라이트 경로가 사용자 프로필 폴더 자체면 `<redacted>\<user>`로 가립니다(분석기와 같은 규칙).

**CI**
- Linux 빌드의 패키지 설치가 미러 문제로 멈추면 다시 시도하고 시간 제한을 둡니다(v0.2.69 릴리즈 워크플로가 이 때문에 한 번 취소됐습니다).

## 주의사항
- 분석기와 뷰어, Helper가 바뀌었습니다. ZIP 전체를 설치해 주세요. MO2에서 새 모드로 설치했다면 v0.2.69 모드는 꺼 주세요.
- v0.2.69로 분석해 둔 덤프를 뷰어에서 열면 그때의 분석 결과를 그대로 보여 주므로 "어떻게 튕겼나" 줄과 명령어 설명이 없습니다. 덤프를 고르고 분석 버튼을 다시 누르면 나옵니다.
- 보관 덤프 19개를 v0.2.69와 비교하면 크래시 덤프 4개에 명령어 설명과 "어떻게 튕겼나" 줄이 추가됐고, 영어 프리징 리포트 5개에서 "[프리징] … 다시 캡처" 권고가 "재수집 / 비교"로 옮겨졌으며, 2026-10-05 무한 로딩의 오류 창 본문에 있던 모드 제작자의 빌드 경로가 가려졌습니다. 판정, 원인 모드, 신뢰도, 결론 문장은 바뀌지 않았습니다.
- 1.5.97의 셀 로드 교착 같은 프리징 3종은 조사했지만 이번에는 넣지 않았습니다. 여러 스레드의 스택과 잠금 상태를 함께 맞춰야 해서 지금 판정 방식으로는 정확히 가려낼 수 없습니다.
