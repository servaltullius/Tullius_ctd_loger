# v0.2.68-rc5 — 전체 코드 리뷰 반영: 크래시 기록 누락·중복, 설정 인코딩, 경로 가리기, 분석 정확도

전체 코드 리뷰(70건 확인)에서 나온 문제를 고친 테스트용 프리릴리즈입니다. 플러그인, Helper, 분석기, 뷰어가 모두 바뀌었습니다.

## 한눈에 보기
- **rc4 회귀 수정:** `CrashLogger.ini`의 `Crashlog Directory`를 ANSI(CP949)로 저장한 한글 경로로 설정하면, Helper가 시작할 때마다 종료돼 크래시·프리징·수동 캡처가 전혀 동작하지 않았습니다.
- **크래시를 놓치거나 두 번 기록하던 경로를 막았습니다.**
  - 크래시를 잡은 뒤 같은 CTD를 "프리징"으로 한 번 더 덤프하고 뷰어를 두 번 띄우던 문제
  - Helper가 크래시를 처리하다 죽으면 그 세션의 이후 CTD가 전부 기록되지 않던 문제
  - Crash Logger가 없으면 처리되지 않은 C++ 예외·중단점·noexcept 위반으로 꺼진 게임이 기록되지 않던 문제
- **설정 파일과 저장 폴더:** `SkyrimDiagHelper.ini`를 UTF-8 BOM·UTF-16으로 저장해도 설정이 무시되지 않고, 한글 `OutputDir`도 바르게 읽습니다. 출력 폴더에 쓸 수 없으면 대체 폴더에 저장합니다.
- **개인정보:** 경로 가리기가 켜진 리포트·Summary·WCT 사본·사전점검 파일에 사용자 이름이 든 절대 경로(MO2 폴더, 심볼 경로 등)가 남던 문제를 고쳤습니다.
- **분석 정확도:** ENB/ReShade의 `d3d11.dll`·`dxgi.dll`을 Windows 시스템 DLL로 보던 문제, Crash Logger 자신을 용의자로 올리던 문제, 근거가 약한 후보를 과장하던 문구를 고쳤습니다.

## 수정
**플러그인**
- 처리되지 않은 C++ 예외와 중단점을 Crash Logger 없이도 기록합니다. 최상위 예외 필터와 abort 처리기를 추가했고, 둘 다 이전 처리기로 넘깁니다. 잡혀서 처리된 예외는 기록하지 않습니다. abort는 같은 스레드에서 0.5초 안에 던진 예외가 있을 때만 그 예외를 원인으로 기록합니다.
- Crash Logger가 C++ 예외를 보고하다 게임 코드에서 부수 예외를 내도, 원래 예외를 크래시로 기록합니다.
- 오래된 Visual C++ 런타임(msvcp140 14.40 미만)에서 플러그인과 Helper가 시작할 때 크래시할 수 있던 문제를 고쳤습니다(`_DISABLE_CONSTEXPR_MUTEX_CONSTRUCTOR`, vcpkg 의존성 포함).

**Helper: 크래시·프리징 처리**
- 크래시가 잡힌 동안에는 하트비트가 그 뒤로 다시 움직이기 전까지 프리징 판정을 하지 않습니다. 처리된 예외 뒤에 실제로 생긴 프리징은 계속 잡습니다.
- 프리징 확인 대기(1.5초) 중에 게임이 끝나거나 크래시가 나면 종료 처리와 크래시 캡처를 정상적으로 이어 갑니다. 전에는 Helper가 그대로 끝나 크래시 기록·뷰어가 빠질 수 있었습니다.
- Helper가 크래시를 처리하다 죽어 다시 실행되면, 새 Helper가 그 크래시를 한 번 다시 처리합니다. 같은 크래시에서 또 죽으면 다시 시도하지 않고 기록을 풀어, 이후 크래시는 정상적으로 기록됩니다(백신 등이 덤프 작성을 막아 게임이 계속 끊기는 일 방지).
- 하트비트 확인으로 "처리됨" 판정된 예외의 덤프를 바로 지우지 않고 `SkyrimDiag_Released_*.dmp`로 잠시 보관합니다. 곧바로 비정상 종료되면 그 덤프를 크래시 덤프로 되돌려 리포트·뷰어를 엽니다. 정상 종료하거나 게임이 1분 넘게 계속 돌면 지웁니다.
- 같은 위치에서 반복되는 처리된 치명 예외는 먼저 작은 덤프로 기록해 게임 멈춤과 디스크 사용을 줄이고, 실제 크래시로 남으면 설정한 크기로 다시 씁니다. C++ 예외·중단점과 메인 스레드 오류는 항상 전체 덤프를 씁니다.
- Alt-Tab 후 돌아왔을 때 오류 대화상자로 멈춘 프리징이 계속 억제되던 문제를 고쳤습니다.
- 정상 종료(종료 코드 0)가 오래 걸려 생긴 프리징 덤프는 남기되, 종료 후 프리징 뷰어는 열지 않습니다.
- `EnablePssSnapshotForFreeze=1`의 PSS 스냅샷이 권한 부족으로 항상 실패하던 문제를 고쳤습니다.
- 재캡처를 켠 경우 오래 걸리는 크래시 분석을 중간에 끝내 리포트가 남지 않던 문제를 고쳤습니다.
- 수동 캡처 단축키를 누르고 있으면 캡처가 반복되던 문제를 고쳤습니다.
- (선택 기능) 프리징 ETW 기록(`EnableEtwCaptureOnHang`)이 시작 직후 멈춰 거의 비어 있던 문제를 고치고, Helper 루프를 오래 막지 않게 했습니다. 최대 10초 기록합니다.

**Helper: 설정·환경**
- `SkyrimDiagHelper.ini`를 직접 읽어 UTF-8(BOM 있음/없음), UTF-16, ANSI를 판별합니다. 키 이름과 기본값은 그대로입니다.
- `OutputDir`를 만들거나 쓸 수 없으면 Helper 옆 `Tullius Ctd Logs`, 그다음 `%LOCALAPPDATA%\SkyrimDiag\Tullius Ctd Logs`에 저장하고, 이유를 Helper 로그 첫 줄에 남깁니다. 뷰어도 이 폴더들에서 덤프를 찾습니다.
- 시작 시 호환성 사전점검이나 Crash Logger 설정 읽기에서 오류가 나도 Helper가 종료되지 않습니다. 경로 확인 중 드라이브가 준비되지 않았거나 공유 폴더에 접근할 수 없을 때 종료되던 문제도 고쳤습니다.
- 마스터가 많은 플러그인도 헤더 전체를 읽어 누락된 마스터를 찾습니다.
- MO2 인스턴스를 MO2와 같은 순서(portable.txt → 전역 인스턴스 → portable)로 고릅니다.
- 확장자가 `.esl`인 플러그인은 헤더 플래그와 관계없이 라이트 슬롯으로 셉니다.
- `SkyrimDiag_Preflight.json`의 심볼 경로, 심볼 캐시, 게임 폴더, dbghelp/msdia 경로에서 사용자 폴더 이름을 가립니다.

**분석기**
- 경로 가리기가 켜져 있으면 Summary의 MO2 폴더, 심볼 검색 경로(환경 변수에서 온 것 포함), WCT 사본의 절대 경로를 가립니다. 이를 검사하는 런타임 테스트를 추가했습니다.
- 인시던트 manifest가 실제 캡처와 매칭되지 않아 인시던트 정보·캡처 프로필이 늘 비어 있던 문제를 고쳤습니다.
- 크래시 스택 스캔을 덤프 시점이 아니라 예외 시점의 스택에서 시작해, Crash Logger나 WER 자신의 프레임을 용의자로 올리지 않습니다.
- 게임 폴더의 ENB/ReShade/DXVK `d3d11.dll`·`dxgi.dll`을 모드로 봅니다. Crash Logger 로그의 콜스택에서도 프레임 주소로 Windows 원본과 구분합니다.
- 근거가 하나뿐인 후보를 "부분적인 다중 신호"라고 부르지 않고, 반복 기록과 근처 리소스만으로 후보를 만들지 않습니다. 프리징에서 SKSE 런타임·Crash Logger·usvfs를 원인 후보로 올리지 않습니다. 스택 스캔만 있는 후보를 "Tullius 콜스택"이라고 부르지 않습니다.
- C++ 예외 설명을 기본 설정(`CrashHookMode=1`)에 맞췄습니다. 어디에서도 처리되지 않은 예외만 기록된다는 점을 설명합니다.
- In-Page Error 안내에서 Steam 무결성 검사 권고를 빼고 백업 경고를 넣었습니다(다운그레이드한 설치 보호). 'Compact FormIDs' 안내에 세이브 파손 위험을 명시했습니다.
- 누락 마스터는 실제 플러그인 목록에서 나온 경우에만 높음으로 보고, 세이브·셀 로드가 끝난 기록이 있으면 낮음으로 봅니다.
- 로딩 화면 수동 캡처를 '로딩 멈춤'과 '프리징 아님'으로 동시에 판정하던 문제, 비크래시 스냅샷에 크래시용 로딩 안내가 붙던 문제, PSS fallback 표시가 사라지던 문제를 고쳤습니다.
- 메인 스레드 스택에 플러그인이 없어도, 게임 스레드가 멈춘 플러그인은 중간 신뢰도를 유지합니다.
- 크래시 이력의 한글 DLL 이름이 깨지던 문제, 최근 리소스·이벤트에 이전 기록이 섞이던 문제를 고쳤습니다.
- `CrashLogger.ini`의 `Crashlog Directory`를 Crash Logger와 같은 규칙으로 읽습니다(BOM, ANSI, `#`·`;`, 끝의 `\`).
- 덤프에 적힌 DLL·MO2·게임 폴더는 로컬 고정 디스크에 있을 때만 엽니다. 조작된 덤프가 네트워크 공유에 접근하거나 DLL을 로드하게 만들 수 없습니다. 손상된 입력이 분석기 프로세스를 끝내지 않습니다.
- `plugin_rules.json`에서 잘못된 조건을 가진 규칙은 무시합니다.

**뷰어**
- 검토 저장 중에 다른 덤프를 열어도 다음 저장이 엉뚱한 덤프에 기록되지 않습니다.
- 다른 덤프의 분석이 실패하거나 취소되면 이전 결과를 지웁니다. 같은 덤프 재분석이 실패해도 검토는 계속 저장할 수 있습니다.
- 뷰어 창을 여러 개 열어도 덤프 위치 목록이 서로 지워지지 않고, 설정 파일을 읽지 못하면 목록을 지우지 않고 오류를 표시합니다.
- 오프라인 네트워크 폴더가 등록돼 있어도 시작·분석 때 응답 없음이 되지 않습니다(검색을 백그라운드에서 실행).
- 검토 저장과 덤프 검색 결과가 분석 상태 메시지를 지우지 않습니다.
- `AutoOpenViewerBeginnerMode`는 효과가 없어 지원 중단(무시됨)으로 표시했습니다.

**개발·릴리즈**
- 릴리즈 공개 확인 단계가 zip 검증 실패를 무시하던 문제를 고쳤습니다. 출시 바이너리의 PDB를 워크플로 아티팩트로 보관합니다. 워크플로 권한을 최소화하고 액션을 커밋으로 고정했습니다. clang-tidy 버전을 확인합니다.
- 테스트 보강: 플러그인의 직접 크래시 기록, Helper 메인 루프·수동 캡처·자동 프리징 경로, 실제 출력 기준 스키마 검사, 대화상자 테스트가 멈추지 않도록 시간 제한.

- 크래시가 나면(일부러 낼 필요는 없습니다) 덤프와 리포트가 한 번만 생기고 프리징 덤프가 따로 생기지 않는지 봐 주세요.

## 주의사항
- 플러그인, Helper, 분석기, 뷰어, `SkyrimDiagHelper.ini`가 모두 바뀌었습니다. ZIP 전체를 설치하고, MO2에서 새 모드로 설치했다면 rc4 모드는 꺼 주세요.
- 처리된 예외로 판정된 덤프가 `SkyrimDiag_Released_*.dmp`로 잠시(최대 하루, 1개) 남을 수 있습니다. 크래시가 아니므로 뷰어 목록에는 나오지 않습니다.
- 새 최상위 예외 필터와 abort 처리기는 다른 크래시 로거(Crash Logger, Trainwreck)와 함께 쓸 때 실게임 확인이 아직 없습니다.
