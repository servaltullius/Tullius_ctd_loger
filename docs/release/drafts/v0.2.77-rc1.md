# v0.2.77-rc1 — 모드 DLL 안의 크래시를 Crash Logger가 있어도 "가능성 중간"으로: 리포트 전체가 같은 설명

v0.2.76 이후의 변경을 모은 테스트용 프리릴리즈입니다. 바뀐 것은 분석기뿐이고, 플러그인, Helper, 설정은 v0.2.76과 같습니다(SharedLayout protocol v4 그대로, 새 설정 없음). ZIP 전체를 설치해 주세요. MO2에서 새 모드로 설치했다면 이전 버전 모드는 꺼 주세요. v0.2.76이 분석해 둔 덤프는 뷰어에서 열 때 한 번 다시 분석합니다.

## 한눈에 보기
- **모드 DLL 안에서 튕긴 크래시가 Crash Logger를 쓸 때 오히려 약하게 나오던 문제를 고쳤습니다.** 모드 DLL 안에서 튕겼고 콜스택도 그 DLL을 가리키는 크래시는, Crash Logger 로그가 없으면 "가능성 중간", 있으면 "가능성 낮음"으로 나왔습니다. 권장 동반 모드인 Crash Logger를 쓰는 사람이 더 약한 답을 받은 셈입니다. 보관 덤프 4개(2026-11-15 실제 크래시 한 건, 11/13 실제 크래시 한 건, 크래시 테스터 두 건)를 Crash Logger 로그 유무로 나눠 분석해 확인했습니다.
  - 이제 둘 다 "가능성 중간"입니다. Crash Logger의 프레임은 예외가 난 위치를 한 번 더 말할 뿐이라 가능성을 높이지도 낮추지도 않습니다. 같은 위치를 두 번 세지 않으므로 "가능성 높음"으로 올리지는 않습니다.
  - 리포트 전체가 같은 설명을 합니다. 결론 문장, 빠른 답, 근거 목록, 권장 사항이 모두 "Crash Logger 프레임과 스택이 모두 이 DLL을 가리키지만, 둘 다 예외가 난 위치를 보는 것"이라고 적습니다. "이 단서가 계속 고립되어 있으면 재수집하라"는 권장은 가능성이 낮을 때(Crash Logger 프레임만 있거나 스택 근거가 약할 때)만 남습니다.
  - 빠른 답의 "다른 모드가 일으킨 문제가 여기서 드러나는 경우도 있습니다" 문장은 그대로입니다. 모드 DLL 안에서 튕겼다는 것만으로 그 모드를 원인으로 단정하지 않습니다.

## 수정
**분석기**
- 예외가 난 DLL의 후보를 정하는 후처리가 신뢰도 규칙을 따로 갖지 않습니다. 그 후보 자신의 신호에서 Crash Logger 프레임만 빼고 후보 합의를 다시 돌려 그 결과를 씁니다. Crash Logger 프레임밖에 없었으면 "낮음" 참고 단서입니다. 다른 후보(같은 Crash Logger 로그의 오브젝트 참조 등)는 넣지 않아, Crash Logger 없이 분석했을 때 없는 "신호가 갈림"이 생기지 않습니다.
- 스택만으로 "중간"이 되는 스택 가중치(5)를 한 곳에 두고 후보 합의와 독립 콜스택 판정이 함께 읽습니다. 값은 그대로입니다.
- 결론 문장의 "Crash Logger 프레임과 같은 덤프의 스택이 모두 이 DLL을 가리킨다" 분기가 조건 때문에 한 번도 나올 수 없었던 것을 고쳤습니다.
- 결론 문장과 권장 사항이 같은 Crash Logger 프레임 설명 함수를 씁니다(복제본 두 개를 하나로).
- 덤프에서 명령 바이트를 읽을 때 요청의 앞부분만 덤프에 있으면 나머지를 로컬 모듈 파일로 채웁니다. 덤프에 아예 없는 주소를 로컬 파일에서 읽던 규칙과 같습니다. 게임 코드(SkyrimSE.exe)는 지금처럼 덤프에서만 읽습니다.

**CI·테스트(내부)**
- 같은 모드 DLL 크래시를 Crash Logger 프레임이 있을 때와 없을 때로 만들어, 후보·빠른 답·결론·근거·권장이 같은지 확인하는 테스트. 약한 스택, 프레임만 있는 경우, 다른 플러그인의 오브젝트 참조가 있는 경우도 확인합니다.
- 덤프 부분 읽기를 로컬 파일로 채우는 테스트(`skydiag_stackwalk_e2e_tests`).
- 빈 함수 포인터 크래시 테스트가 덤프 폴더를 지울 때 예외를 던지지 않습니다(백신이 파일을 잡고 있어도 통과한 테스트가 실패하지 않음).

## 테스트 시 확인할 점
- 모드 DLL 안에서 튕긴 크래시(리포트의 예외 위치가 모드 DLL)가 나면, 빠른 답이 "가능성 중간"이고 결론·근거·권장 사항이 같은 설명인지 봐 주세요.
- 다른 크래시와 프리징의 결과는 v0.2.76과 같아야 합니다.

## 실게임에서 확인한 것
- 이 RC의 빌드로 게임을 돌려 보지는 않았습니다. 바뀐 것이 분석기뿐이라, 실제 게임에서 난 크래시 덤프를 이 RC의 분석기로 다시 분석해 확인했습니다(아래 "검증").
- 플러그인과 Helper는 v0.2.76과 같으므로 v0.2.76 노트의 실게임 확인이 그대로 해당합니다.

## 주의사항
- 예외 위치가 모드 DLL이어도, Crash Logger의 오브젝트 참조나 다른 독립 근거가 함께 맞아야 "가능성 높음"이 됩니다. 이 RC는 Crash Logger를 쓸 때와 안 쓸 때의 차이를 없앤 것이고, 그 기준은 바꾸지 않았습니다.
