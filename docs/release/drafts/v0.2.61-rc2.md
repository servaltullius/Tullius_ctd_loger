# v0.2.61-rc2 — Crash Logger 로그 해석 보강과 리포트 정리

Crash Logger 로그를 더 정확히 읽고 리포트의 문구와 모드 이름을 정리한 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- Crash Logger가 기록한 원래 예외를 보여 줍니다. 덤프에는 CrashLogger 자신의 2차 예외만 남은 경우에도, 로그의 원래 예외(예: assert의 `EXCEPTION_BREAKPOINT`)와 그 의미를 알려 줍니다.
- Crash Logger의 관련 오브젝트 중 플러그인이 없는 것(실행 중 생성된 액터 등)도 보여 줍니다. 예: `Character "블러드 드래곤" [0xFF0036F8]`.
- 플레이어가 서 있던 셀(장소)을 정의한 플러그인을 더 이상 후보로 올리지 않습니다.
- Crash Logger 상위 모듈을 알파벳순이 아니라 콜스택 순서로 보여 줍니다.
- 권장 조치에서 그 상황에 맞지 않는 문구(크래시의 히치 안내, 프리징의 "예외 모듈을 특정 못함", 수동 캡처의 프리징 상태 안내 등)를 뺐습니다.
- MO2 모드 이름에서 Nexus 압축 파일 이름의 꼬리를 떼어 냅니다. 예: `SmoothCam 41252 1.8.1 2026` → `SmoothCam`.

## 엔진 변경
- 분석기: Crash Logger 로그의 `Unhandled exception` 줄을 근거 항목, 리포트 `Crash Logger 예외:`, 요약 JSON `crash_logger.exception`에 넣고, CrashLogger 내부 2차 예외의 해석 안내에 원래 예외를 적습니다.
- 분석기: 이름이나 FormID만 있고 플러그인이 없는 관련 오브젝트를 근거 항목(신뢰도 낮음), 리포트, 요약 JSON `crash_logger.objects_without_plugin`에 넣습니다.
- 분석기: `TESObjectCELL`·`TESWorldSpace` 참조는 행동 우선 후보와 이력 후보에서 뺍니다(오브젝트 참조 근거에는 남음).
- 분석기: Crash Logger 상위 모듈의 동점은 콜스택에 처음 나온 순서로 정렬합니다.
- 분석기: 히치 안내는 크래시가 아닐 때만, "예외 모듈을 특정 못함"은 크래시일 때만, 프리징 상태 안내는 프리징일 때만 붙이고, modal 대화상자 프리징에서는 신뢰도 낮은 로드 순서 정리 안내를 뺍니다. `[트러블슈팅]` 안내는 크래시·프리징·캡처를 구분합니다.
- 분석기: MO2 폴더 이름 끝의 "Nexus 모드 ID, 버전, 업로드 날짜, 다운로드 해시"를 떼어 모드 이름으로 씁니다. 모드를 업데이트해도 이력의 후보 키가 갈라지지 않습니다.

## 테스트 시 확인할 점
- 이미 받아 둔 덤프를 WinUI나 CLI로 다시 열어 보세요. 분석기만 바뀌었으므로 바로 차이가 보입니다.
- 수동 캡처 리포트의 권장 조치에 `[프리징] 현재 프리징 근거가 애매합니다` 줄이 더 이상 없어야 합니다.
- 모드 이름이 `SmoothCam 41252 1.8.1 2026`처럼 나오던 곳이 `SmoothCam`으로 나오는지 봐 주세요.
- 아직 실게임에서 확인하지 못한 항목(rc1에서 이어짐): 덤프 오브젝트(실제 CTD 필요), 대기 기반 프리징 버킷(실제 프리징 필요), Windows 업데이트 뒤 새 덤프 분석(다음 업데이트 필요).

## 주의사항
- 분석기만 바뀌었습니다. ZIP 전체를 교체해 주세요.
- 이름이 정리되는 모드는 이력의 후보 키가 한 번 바뀌므로, 그 모드의 이전 이력과는 이어지지 않습니다.
- 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
