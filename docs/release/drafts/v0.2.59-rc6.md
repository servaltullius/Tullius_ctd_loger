# v0.2.59-rc6 — 게임 플레이 중 수동 캡처 단축키 수정

rc5 실게임 테스트에서 찾은 문제를 고친 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- 게임 플레이 중 `Ctrl+Shift+F12`를 눌러도 SkyrimDiag 수동 캡처가 만들어지지 않던 문제를 고쳤습니다. 같은 키를 쓰는 Crash Logger 1.25의 스레드 덤프는 만들어졌습니다.
- rc5의 Crash Logger 스레드 덤프 오탐 수정은 같은 테스트에서 확인했습니다. 스레드 덤프 동안 크래시 이벤트가 기록되지 않았습니다.
- 크래시 위치가 게임 본체(EXE)일 때 "버전 불일치나 후킹 충돌 가능성이 크다"고 단정하지 않고, 플러그인 데이터(ESP/ESM·메시) 문제도 함께 가능성으로 안내합니다.

## WinUI / 사용성
- 게임 본체 크래시의 권장 조치가 플러그인 데이터, Address Library/SKSE 버전 불일치, DLL 훅을 모두 가능성으로 듭니다. 다른 단서가 없을 때의 결론은 "이 덤프만으로는 가릴 수 없음"을 신뢰도 낮음으로 냅니다. rc5 실게임 CTD(함정이 모드 크리처에 맞은 순간, 콜스택 전체가 바닐라 엔진 코드)에서 이전 안내가 근거보다 단정적이었습니다.

## 엔진 변경
- Helper는 `RegisterHotKey`(`WM_HOTKEY`)에 더해, 별도 스레드가 20ms마다 Ctrl·Shift·F12가 지금 눌려 있는지 확인해 키 조합이 새로 눌릴 때마다 수동 캡처를 요청합니다.
- 이전의 대비 경로는 `GetAsyncKeyState`의 "마지막 확인 이후 눌린 적 있음" 비트를 읽었는데, 이 비트는 모든 프로세스가 함께 쓰므로 같은 키를 확인하는 Crash Logger가 먼저 가져갈 수 있었습니다. 지금 눌려 있는 상태는 다른 프로그램이 읽어도 사라지지 않습니다.
- 캡처 중에 들어온 입력은 버리고 캡처가 끝난 시점부터 중복을 막으므로, 두 경로가 같은 입력을 받아도 캡처는 한 번만 만들어집니다.

## 테스트 시 확인할 점
- **게임 플레이 중**(메뉴가 아닌 상태)에 `Ctrl+Shift+F12`를 한 번 눌러 주세요. 출력 폴더에 `*_Manual_*` 캡처가 하나 생기고, `SkyrimDiagHelper.log`에 `Manual capture triggered via key-state poll` 또는 `via WM_HOTKEY` 줄이 하나 있어야 합니다.
- 같은 로그에 `Crash event signaled` 줄이 없어야 합니다. Crash Logger를 쓰고 있다면 SKSE 로그 폴더의 `threaddump-*.log`도 함께 생깁니다.
- 수동 캡처 리포트(`*_SkyrimDiagReport.txt`)가 Windows 표시 언어(한국어 환경이면 한국어)로 나오는지, `누락 마스터`가 없는지 확인해 주세요.
- 모드의 assert로 난 CTD(Crash Logger 로그 맨 위가 `EXCEPTION_BREAKPOINT`)가 나면 리포트의 `ExceptionCode`가 `0x80000003`이고 `Module+Offset`이 `CrashLogger.dll`이 아닌지도 확인해 주세요(rc3 수정, 아직 실게임 미확인).

## 주의사항
- 이번 변경은 Helper와 분석기입니다. 플러그인은 rc5와 같지만 ZIP 전체를 교체해 주세요.
- 게임 플레이 중 `WM_HOTKEY`가 오지 않은 원인은 확인하지 못했습니다(게임의 입력 처리 방식으로 추정). 키 상태 확인 경로는 그 원인과 관계없이 동작하도록 만든 것이며, 실게임 동작은 rc6 테스트로 확인해야 합니다.
- 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
