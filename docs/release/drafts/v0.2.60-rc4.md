# v0.2.60-rc4 — Helper 안정성과 다음 조치 선택 개선

실사고 덤프 재분석과 코드 점검에서 찾은 문제를 고친 테스트용 프리릴리즈입니다. 기존 파일 일부만 덮지 말고 ZIP 전체를 설치해 주세요.

## 핵심 변경
- `é` 같은 문자가 든 플러그인 이름이 있으면 Helper가 종료돼 프리징 덤프를 잃던 문제를 고쳤습니다.
- 크래시 뒤 게임을 다시 켜도 직전 세션의 Helper 로그가 `SkyrimDiagHelper.previous.log`로 남습니다.
- 리포트의 "다음 조치"가 설명이나 일반 문구 대신 실제 후보를 가리킵니다. 보관 중인 실사고 CTD 5건 모두 그렇게 바뀌었습니다.
- 관리자가 아닌 사용자에게 매번 찍히던 `EnableDebugPrivilege failed` 경고를 없앴습니다.

## 엔진 변경
- Helper: `plugins.txt`, `Skyrim.ccc`, 플러그인 헤더의 마스터 이름을 ANSI 코드 페이지에서 UTF-8로 바꿔 다루고, 스캔 JSON은 잘못된 문자를 대체 문자로 기록합니다. 스캔이 실패해도 로그에 남기고 캡처를 계속합니다.
- Helper: 게임에 붙을 때 기존 로그를 지우지 않고 `SkyrimDiagHelper.previous.log`로 옮깁니다.
- Helper: `ERROR_NOT_ALL_ASSIGNED`(관리자가 아닌 사용자)일 때는 권한 경고를 남기지 않습니다. 이 경우에도 게임 스레드의 대기 정보는 그대로 읽습니다.
- Helper: 보관 정리가 파일 이름을 UTF-8로 비교하고, 실패해도 Helper를 멈추지 않습니다.
- 분석기/WinUI: `NextAction`을 태그 우선순위(modal 대화상자 → 행동 우선 후보 → Crash Logger 프레임 → 오브젝트 참조 → 충돌)로 고르고, 요약 JSON에 `next_action_index`를 추가했습니다.

## 테스트 시 확인할 점
- 게임을 켜고 수동 캡처(`Ctrl+Shift+F12`)를 한 번 해 주세요. Helper 로그에 `EnableDebugPrivilege` 경고가 더 이상 없어야 합니다.
- 게임을 한 번 껐다가 다시 켠 뒤, 출력 폴더에 `SkyrimDiagHelper.previous.log`가 생기고 그 안에 직전 세션 기록이 남아 있는지 확인해 주세요.
- 리포트의 `NextAction:`이 체크리스트 첫 줄이 아니어도 괜찮습니다. 후보가 있으면 그 후보를 가리키는 줄이 나와야 합니다.
- 아직 실게임에서 확인하지 못한 항목: 모드의 assert로 난 CTD에서 `ExceptionCode`가 `0x80000003`인지, 덤프 실패 시 실패 위치 진단, Address Library 오류 창 안내(보관 덤프 재분석으로만 확인), AMX CPU에서의 CTD 덤프(CI에서만 확인).

## 주의사항
- Helper, 분석기, WinUI가 바뀌었습니다. ZIP 전체를 교체해 주세요.
- 프리징 리포트의 결론은 아직 약합니다. 실사고 프리징 5건이 모두 근거가 약하거나 맞지 않았고, 다음 버전에서 다룰 예정입니다.
- 코드 점검은 "출력 폴더에 이상한 이름의 파일이 있으면 Helper가 매번 종료된다"고 했지만, 확인해 보니 일반적인 코드 페이지에서는 일어나지 않았습니다. 보관 정리 변경은 방어용입니다.
- 검수된 실사고 코퍼스가 없어 다른 로거 대비 적중률을 수치로 주장하지 않습니다.
